# 量產算圖（第三階段兵種）

- 依據：D-021（R5-02 兵種總表核准，東陸槍兵用前垂布）、D-017（3 倍素材，暫定）、ceo 2026-09-30 核准的計畫。
- 範圍：12 個兵種 × 全部動作 × 8 個方向。
  - 朝向 0、1、2、6、7 實際算圖。
  - 3、4、5 在遊戲裡用 1、0、7 左右翻轉，但各自算自己的影子，因為陽光從一邊來，翻轉的影子方向會錯。
- 動作與影格數照 R1 的量產估計（`common/spec.py`）：
  - 一般兵種：待機 8、走路 8、攻擊 10、倒下 10。
  - 農夫與農民另加 4 種工作各 8。
  - 法師：待機 12、走路 12、施法 30、受擊 6、破盾 8、倒下 12、死亡 4。
  - 模型還沒有的動作先用替代動作算，在報告和圖集的 `placeholder` 標出來，之後補上姿勢、給使用者看過再重算。
  - 目前的替代動作：
    - 騎兵、攻城器械的倒下。
    - 攻城器械的走路（輪子還不會轉）。
    - 農夫與農民的挖礦、耕田、蓋房子。
    - 兩種法師的受擊、破盾、倒下、死亡。

## 流程

1. `blender/render_prod.py --target <兵種>`：算 3 倍原始素材。
   - 每個方向開一個 Blender。
   - 圖層：本體、玩家色遮罩、影子（半解析度）、環境光遮蔽，法師另有特效層。
   - 輸出到 `build/prod/<兵種>/raw/`。
2. `common/postprocess.py --target <兵種> --scale 3|2 [--astc 4x4]`：修邊、打包成圖集、算記憶體。
   - 倍率和壓縮是參數。client 在 iPhone 實測、D-017 定案後，只要重跑這一步。
   - 圖集格式是草案，等 war-game-client 的規格到了再對齊（見檔頭說明）。
3. `common/checks.py --target <兵種>`：自動檢查，並出每個兵種的縮圖總表（列是動作，欄是 8 個方向，鏡像方向是翻轉後的樣子）。
   - 硬性檢查，不過就算失敗：缺圖、本體碰到畫框、空白影格、錨點或影格大小不一致。
   - 警告：影子或特效碰到畫框、玩家色太少。

算圖在 GitHub Actions 上跑（`design-render`，round 選 production，每個兵種一個 job）。
- 每個 job 上傳兩份：
  - 報告：`production-<兵種>-report`。
  - 原始素材加圖集：`production-<兵種>`。
- 兩份都保留 90 天，原始素材留著是為了之後重跑後處理。

```bash
gh workflow run design-render --ref <分支> -f round=production \
  -f targets='["farmer_e","spear_e","xbow_e","hcav_e","siege_e","mage_e","farmer_w","pike_w","bow_w","knight_w","siege_w","mage_w"]'
```

本機只在 available ≥ 2 GB 時跑 `--preview`（每個動作第一格、低取樣），一樣用記憶體上限區。

## 畫框自動量

- 算圖前先跑一次只擺姿勢、不算圖的量測（`render_units.py` 的 fit 模式）：
  - 每個動作的每一格、8 個方向都擺一次。
  - 量出兵種在畫面上往四個方向伸得最遠的距離，四邊各加 0.12 公尺，當成這個兵種的畫框。
  - 特效不算進去，飛出去的晶砲應該改由遊戲畫成彈道。
- 起因：第一次全部算圖（run 36694860969），12 個兵種有 10 個被切到。
  - 朝向 2（背對鏡頭）時，往前伸的武器和背旗在畫面上會往上跑。
  - 倒下時身體往側面倒。
  - 霹靂車的拋竿往後甩。
- 圖集會修邊，畫框大只多花算圖時間，不佔記憶體。

## 和 R5 算圖的差別

- 影子的畫框往下多留到 0.6 倍畫框高。R5 的農夫影子會碰到下緣，但 R5 合成時把影子裁到本體的畫框裡，所以看不出來。
- 影子圖層只讓太陽投影。R5 的冷色背光也會投一道往鏡頭方向的長影子，R5 同樣被裁掉，看不出來。
- 霹靂車、投石機的攻擊改成 10 格（`design/round5/blender/roster5.py` 改讀兵種的影格數，R5 的結果不變）。
