# 建築與資源點的圖集（提案，給 client 併進 `client/docs/sprite-atlas.md`）

- 依據：R6 brief（`docs/briefs/2026-10-ui-r6.md`）A，D-085。
- 外觀照 B1 核准的設計稿（D-040、D-041，`design/b1/README.md`）：
  - 施工中 A 分三階段、受損 A 著火、被摧毀 A 瓦礫堆；
  - 東陸箭樓用精修版；農田是東陸稻田、西陸麥田，各三個階段。
- 製作方式（ceo 2026-10-18 同意）：
  - 每棟各一張：完成、施工第 2 階段、施工第 3 階段、受損。受損的火先用靜態的，畫在圖裡。
  - 依占地大小和文化共用：施工第 1 階段（地基）、瓦礫。
- 這份是格式提案。client 同意後才上 CI 量產；量產圖集放在 art-v2。
- **art-v3 起改成方形斜看**（D-088，使用者 2026-10-19：「我覺得地圖還是正方形好」，選「甲 方形斜看」）：
  - 建築和資源點全部用新鏡頭重算（第 0 節），兵種照 art-v2。
  - 說明檔多一欄 `"view": "oblique"`（第 5、7 節）；art-v2 的說明檔沒有這欄，代表斜 45° 的菱形。
  - 前後順序改成依前緣的 y（第 6 節）。
- 沒寫到的地方都和兵種圖集第 2 版一樣：
  - 比例：3 倍 `px_per_m` 60，2 倍 40。
  - 修邊：alpha > 4。
  - 頁寬 2048，頁高補到 4 的倍數，影格間隔 2 px，不用 mipmap。
  - 圖層的格式：玩家色層用 `team_gain` 1.6；影子半解析度、黑色加透明度。

## 0. 鏡頭（art-v3 起，D-088；和 client 2026-10-19 談定）

- 正交鏡頭，仰角 30°，正對格線（art-v2 是轉 45°）。光跟著鏡頭轉，建築的影子在畫面上和兵種圖同一個方向。
- sim 的 +x 朝畫面右，+y 朝畫面下（離鏡頭越近）。
- 1 倍（zoom 1）：
  - 橫向 1 公尺 = 20 pt，縱深 1 公尺 = 10 pt，一格（2 公尺）是 40×20 pt；
  - 高 1 公尺 = 20 × cos30° ≈ 17.32 pt 往上。
- 地面點換到畫面：`px = (cellX − camX) × 40 × zoom + W / 2`，`py = (cellY − camY) × 20 × zoom + H / 2`。點擊換回格座標是它的反函數。
- 圖集的比例不變：3 倍 60 px／公尺，2 倍 40 px／公尺。
- 占地在畫面上是以錨點為中心、寬 40n、高 20n pt 的長方形（n 是格數）。
- 只有正面看得到，側面和地面垂直、看不到：玩家色都放在正面或旗子上（第 9 節的玩家色表）。
- client 照這一節寫進 `client/docs/sprite-atlas.md` 第 1 節（O-1）。

## 2. 檔案

art-vN 的壓縮檔裡，和 `units/`、`effects/` 並列：

```
buildings/

  buildings_E_color_<k>.png
  buildings_E_team_<k>.png
  buildings_E_shadow_<k>.png
  buildings_W.json  … 西陸同上
  memory.json
nodes/
  nodes.json
  nodes_color_<k>.png
  nodes_shadow_<k>.png

```

- 一個文化一組頁，不是一棟一組：
  - 一棟只有幾張圖。一棟一組的話，每頁都很空，記憶體以整頁算。
  - 東陸對西陸載兩組；同文化對打只載一組。
- 資源點沒有玩家色層，所以只有顏色層和影子。
- 每組頁有自己的 `memory.json`，欄位和兵種的一樣。

## 3. 影格命名與狀態

影格名稱是 `<kind>_<c>_<state>`，`<c>` 是 `E` 或 `W`。建築不轉向、不鏡像，所以沒有方向。

| 狀態 `<state>` | 內容（B1-02 核准的樣子） | 誰有 |
|---|---|---|
| `done` | 完成 | 每棟（農田見下面） |
| `build1` | 施工第 1 階段：整塊占地打上木樁、拉繩，旁邊堆建材 | **共用**：`found_<n>x<n>_<c>`，依占地 2×2、3×3、4×4 和文化各一張 |
| `build2` | 施工第 2 階段：木架加鷹架 | 每棟 |
| `build3` | 施工第 3 階段：牆蓋好，屋頂只有椽子 | 每棟 |
| `damaged` | 受損：屋頂破洞、火、黑煙、牆被燻黑。火和煙是靜態的，畫在圖裡 | 每棟 |
| `rubble` | 被摧毀：低矮的瓦礫、燒黑的樑、餘煙（0.6 公尺以下） | **共用**：`rubble_<n>x<n>_<c>`，依占地和文化各一張 |

- 共用的地基和瓦礫，用 B1-02 核准的那三棟算：民居（2×2）、兵營（3×3）、主城（4×4）。發布前我會給 ceo 核准稿和量產圖的並排對照，大建築、小建築各至少一棟。
- **農田**：
  - 沒有 `done`，改成三個作物階段：`farm_<c>_sown`（剛播種）、`farm_<c>_growing`（長高）、`farm_<c>_ripe`（成熟）。
  - 施工第 1 階段是農田自己的 `farm_<c>_build1`：空田加木樁。共用的地基有兵營的台基，放在田上不對。
  - 施工第 2、3 階段用 `farm_<c>_sown`。
  - 沒有受損和瓦礫：田不會著火、也不會留瓦礫，被摧毀就直接消失。
  - 作物階段只是畫面，模擬裡沒有（農田不會採完）。建議 client：一名農民在田裡工作時，每 20 秒（sim 時間）換下一個階段，成熟之後回到剛播種；沒人工作就停在當時的階段。
- **大城的箭樓**（`TownTower`）：
  - 只有 `done`、`damaged`、`rubble`。玩家不能蓋，所以沒有施工階段。
  - `rubble` 用 B1-03 核准的「大城箭樓已拆」那張，不用共用瓦礫。
  - 玩家色層照持有者上色，中立時用 `NEUTRAL_TINT`。
- **哨所**（`Outpost`，art-v5.1 起）：
  - 六個狀態都是自己的圖：`outpost_<c>_build1`、`_build2`、`_build3`、`_done`、`_damaged`、`_rubble`。不用共用的地基和瓦礫。
  - 暫用版，用現在建築的畫風（使用者 2026-10-22 核准 R8-13、R8-14）；寫實版在 R8 第二批。
  - 記憶體（CI run 39730695449 打包，和 art-v5 的 39442321932 比）：
    - 3 倍未壓縮：東陸 46.7 → 50.1 MB、西陸 46.0 → 49.1 MB。
    - 2 倍 ASTC：東陸 5.48 → 5.65 MB、西陸 5.41 → 5.65 MB。
    - 其他影格（建築、資源點、城牆、地形）一張都沒變。

一個文化總共 53 張（art-v5.1 起加哨所 6 張，共 59 張）：10 棟 × 4 張、農田 4 張、大城箭樓 3 張、共用地基 3 張、共用瓦礫 3 張。

## 4. 圖層

| 圖層 | 和兵種不同的地方 |
|---|---|
| 顏色 `color` | 受損的火和煙也在這一層。沒有特效層 |
| 玩家色 `team` | 一樣修到玩家色的範圍，另有一張 `team` 表。沒有玩家色的影格（例如瓦礫）不列在 `team` 裡 |
| 影子 `shadow` | 一樣，畫在地面層。只有一個方向，所以每張影格一個影子 |

煙在顏色層裡，所以影子層沒有煙的影子。

## 5. 說明檔 `buildings_<c>.json`

```json
{
  "format": "war-game buildings 1",
  "culture": "E",
  "scale": 3,
  "px_per_m": 60,
  "cell_m": 2,
  "view": "oblique",
  "team_gain": 1.6,
  "pages": {
    "color":  ["buildings_E_color_0.png", "buildings_E_color_1.png"],
    "team":   ["buildings_E_team_0.png"],
    "shadow": ["buildings_E_shadow_0.png"]
  },
  "buildings": {
    "House": {
      "type": 1, "footprint": [2, 2],
      "states": { "build1": "found_2x2_E", "build2": "house_E_build2", "build3": "house_E_build3",
                  "done": "house_E_done", "damaged": "house_E_damaged", "rubble": "rubble_2x2_E" }
    },
    "Farm": {
      "type": 5, "footprint": [3, 3], "ground": true,
      "states": { "build1": "farm_E_build1", "build2": "farm_E_sown", "build3": "farm_E_sown" },
      "crops": ["farm_E_sown", "farm_E_growing", "farm_E_ripe"]
    },
    "TownTower": {
      "type": 9, "footprint": [2, 2],
      "states": { "done": "town_tower_E_done", "damaged": "town_tower_E_damaged", "rubble": "town_tower_E_rubble" }
    }
  },
  "frames":  { "house_E_done": { "page": 0, "x": 0, "y": 0, "w": 260, "h": 230, "ax": 130.0, "ay": 172.5 } },
  "team":    { "house_E_done": { "page": 0, "x": 0, "y": 0, "w": 60, "h": 80, "ax": 40.0, "ay": 120.5 } },
  "shadows": { "house_E_done": { "page": 0, "x": 0, "y": 0, "w": 140, "h": 70, "ax": 60.0, "ay": 35.3, "half_res": true } }
}
```

- 上面的數字只是舉例。
- `view`：算圖的鏡頭。`"oblique"` 是方形斜看（第 0 節）；沒有這欄（art-v2）是斜 45° 的菱形。client 的鏡頭和這欄對不上時，建築和資源點改畫圖形，不畫歪掉的圖。
- `buildings` 的 key 是 `BuildingType` 的名字，`type` 是它的數字。client 照 `states` 找影格名稱，不用自己拼。
- 同一張影格可以出現在好幾個狀態（例如共用地基、農田的 `build2`、`build3`）。
- 沒有的狀態就不列：農田沒有 `done`、`damaged`、`rubble`；大城箭樓沒有施工階段。
- `ground: true`：畫在地面層（第 6 節）。
- `footprint` 是格數 `[x, y]`。這次的建築都是正方形。
- `sizes`（art-v4 起，只有 `TownTower`）：同一種建築的其他大小。隨機地圖相鄰出生時大城箭樓是 3×3（sim `GameMap.towerSize`，D-074），用 `sizes["3"].states` 的影格；其他照 `states`。

## 6. 錨點、前後順序、地面層

- **錨點**：占地的中心點，在地面上。也就是 sim 的 `cellX + size / 2`、`cellY + size / 2`（格座標）。
  - `ax`、`ay` 的規則和兵種一樣：錨點在「這一層修邊後的方框」裡的位置。
  - client 照第 1 節的公式把錨點換成畫面座標。
  - client 可以從 `footprint` 算出占地的四個角。
- **前後順序**（art-v3 起，方形斜看；和 client 2026-10-19 談定）：
  - 依「前緣 y」由小到大畫：建築用 `cellY + n`，資源點用 `cellY + 1`，單位用自己的 y。
  - 前緣 y 一樣時，x 小的先畫，再依 ID。
  - A 的占地整個在 B 的 y 較小一側時，A 一定先畫，前緣排序已經涵蓋。
  - 點選用同一個排序：從最後畫的往前找，第一個圖案方框（或占地）包含手指的就是點到的。
  - art-v2（菱形）的規則是「x + y 小的先畫」，加上占地整個在另一棟 x 或 y 較小一側時先畫；方形斜看不用。
- **地面層**：農田、採完的資源點、瓦礫，比所有單位和建築先畫。三種都很低（0.6 公尺以下），不會擋人。
- **點選**：建築的圖比占地高，點到圖的範圍也算點到那棟（第 10 節「高的圖案怎麼點選」）。

## 7. 資源點 `nodes.json`

| sim `NodeKind` | 影格 | 狀態 |
|---|---|---|
| `Tree` 0 | `tree_E_v0`–`v2`、`tree_W_v0`–`v2` | 採完：`tree_<c>_stump`（樹樁，畫在地面層，可以走） |
| `GoldMine` 1 | `gold_v0`、`gold_v1` | `full` → `mined` → `depleted`，例如 `gold_v0_mined` |
| `Berries` 2 | `berry_v0`、`berry_v1` | `full` → `depleted` |
| `CrystalVein` 3 | `crystal_v0`、`crystal_v1` | `full` → `depleted` |

```json
{
  "format": "war-game nodes 1",
  "scale": 3, "px_per_m": 60, "cell_m": 2, "view": "oblique",
  "pages": { "color": ["nodes_color_0.png"], "shadow": ["nodes_shadow_0.png"] },
  "nodes": {
    "Tree":        { "kind": 0, "footprint": [1, 1],
                     "variants": { "E": ["tree_E_v0", "tree_E_v1", "tree_E_v2"], "W": ["tree_W_v0", "tree_W_v1", "tree_W_v2"] },
                     "depleted": { "E": "tree_E_stump", "W": "tree_W_stump" } },
    "GoldMine":    { "kind": 1, "footprint": [1, 1], "variants": ["gold_v0", "gold_v1"],
                     "stages": ["full", "mined", "depleted"] },
    "Berries":     { "kind": 2, "footprint": [1, 1], "variants": ["berry_v0", "berry_v1"], "stages": ["full", "depleted"] },
    "CrystalVein": { "kind": 3, "footprint": [1, 1], "variants": ["crystal_v0", "crystal_v1"], "stages": ["full", "depleted"] }
  },
  "frames":  { "gold_v0_full": { "page": 0, "x": 0, "y": 0, "w": 120, "h": 90, "ax": 60.0, "ay": 62.0 } },
  "shadows": { "gold_v0_full": { "page": 0, "x": 0, "y": 0, "w": 70, "h": 35, "ax": 30.0, "ay": 18.0, "half_res": true } }
}
```

- 錨點是那一格的中心，在地面上。
- 選哪一個 `variant`：建議用格座標算，例如 `(cellX × 7 + cellY × 13) mod 變體數`。同一格每次都一樣，看起來也不會整排相同。
- 樹用哪一陸（ceo 2026-10-18）：兩陸混著用，但要一片一片的，不要一格一格換，樹林才會一叢一叢的，不是棋盤格。
  - 建議：地圖切成 6×6 格的區塊，一塊用同一陸：`((⌊cellX / 6⌋ × 7 + ⌊cellY / 6⌋ × 13) mod 2)`，0 是東陸、1 是西陸。
  - 區塊裡每一格再照上一條選 `variant`。
- 金礦的 `mined`：建議剩下的量 ≤ 第一次看到時的一半就換。`amount` 是 0 時用 `depleted`。
- 金礦、野果、晶脈東西陸共用一套。樹分東陸、西陸，見第 8 節的問題。
- 森林是一格一棵樹排出來的；B1-04 總表裡的「森林」只是示範，不另外出圖。

## 8. 狀態怎麼選

client 2026-10-18 同意照這一節做。ceo 同意瓦礫、樹、大城箭樓的做法，各加了一個條件，已寫進下面和第 7 節。

- **施工**：快照的 `progress`（千分比）：
  - < 334 → `build1`；
  - < 667 → `build2`；
  - < 1000 → `build3`；
  - 1000 → `done`。
- **受損**：完成後，`hp` ≤ 最大血量的一半 → `damaged`。修好回到一半以上就換回 `done`。
- **被摧毀**：sim 會馬上把建築移走，那幾格可以走。
  - client 在原地畫 `rubble`，畫在地面層，不擋路。
  - 留 30 秒（sim 時間），最後 2 秒淡出。
  - 同一塊地上一有新建築開工，就馬上清掉那裡的瓦礫，不要疊在施工的地基下面（ceo 2026-10-18）。
- **記住的建築**（迷霧裡、`Remembered`）：用最後看到的那個狀態的圖。

## 11. 城牆 `castle/castle_<c>.json`（art-v4 起，D-089）

使用者 2026-10-19 說「希望像一個城堡」，2026-10-20 看過 R6-06 城堡設計稿後選「可以，照這樣做」。小鎮是木柵，大城是石牆加城樓、角樓，只能從四個城門進出，門一直開著。

格子和 war-game-core 對過，正本是 `design/b1/castle-layout.json`（`common/castle.py`）。有三種配置：

| 配置 | 用在哪 | 牆 | 牆以內 |
|---|---|---|---|
| `small` | 小鎮 | 距中心格第 5 格，木柵 | 9×9＝81 格 |
| `large` | 固定地圖的大城（箭樓 2×2） | 箭樓外第 7 格，石牆 | 12×12＝144 格 |
| `large3` | 隨機地圖相鄰出生的大城（箭樓 3×3） | 距中心格第 7 格，石牆 | 13×13＝169 格 |

規則（模擬由 core 做，這裡只記畫面要配合的）：
- 牆只擋走路，不擋射擊和視野。
- 牆不會壞。
- 城門永遠可以走（art-v4；D-096 起城門會關、打得破，見下面的 D-096 段）。
- 城鎮範圍改成牆以內。

```json
{
  "format": "war-game castle 1", "culture": "E", "scale": 3, "px_per_m": 60, "cell_m": 2, "view": "oblique",
  "team_gain": 1.6,
  "pages": { "color": ["castle_E_color_0.png"], "team": ["castle_E_team_0.png"], "shadow": ["castle_E_shadow_0.png"] },
  "pieces": {
    "pal_gate_x": { "footprint": [3, 1], "frames": { "intact": "castle_pal_gate_x_E_intact", "ruin": "castle_pal_gate_x_E_ruin" } }
  },
  "tiles": { "square": "castle_tile_square_E", "street": "castle_tile_street_E", "garden": "castle_tile_garden_E" },
  "layouts": {
    "small": {
      "walls": [ { "piece": "pal_gate_x", "anchor": [0.5, -4.5], "front": -4, "cells": [[-1, -5], [0, -5], [1, -5]] } ],
      "floor": [ { "cell": [0, 0], "tile": "square" } ]
    }
  },
  "frames": { }, "team": { }, "shadows": { }
}
```

### 圖塊和格子
- **座標**：`cells`、`anchor`、`front`、`floor[].cell` 都是相對城鎮中心那一格的格數。`(dx, dy)` 那一格是 sim 的 `[townX + dx, townX + dx + 1)`。
  - 把 `townX`、`townY` 加上去，就是 sim 的格座標。
  - 大城的箭樓：`large` 在 dx、dy 為 −1、0 的四格（map.ts 的 tower = centre − 1）；`large3` 在 |dx|、|dy| ≤ 1。
- **錨點**：`anchor` 是那個圖塊占地的正中間，在地面上。和建築一樣，影格的 `ax`、`ay` 對到這一點，用第 0 節的投影換到畫面。
- **一座城門一張圖**：門和兩邊的墩子（石牆）是同一張。一座角樓的 2×2 格是同一張。一般的牆一格一張。
  - 共 32 張：小鎮 4 座門、4 個角、24 段牆；大城 4 座門、4 座角樓、24 段牆。
- **圖塊種類**（`pieces`）：

| 圖塊 | 占地 | 用在 |
|---|---|---|
| `pal_x`、`pal_y` | 1×1 | 小鎮木柵：北、南兩面（`_x`）和東、西兩面（`_y`）的一格（art-v5.2 起改成四面分開，見 D-096 段） |
| `pal_corner` | 1×1 | 小鎮四角的望樓 |
| `pal_gate_x`、`pal_gate_y` | 3×1、1×3 | 小鎮的城門（北南、東西） |
| `sw_x`、`sw_y` | 1×1 | 大城石牆的一格（art-v5.2 起改成四面分開，見 D-096 段） |
| `sw_ctower` | 2×2 | 大城四角的角樓 |
| `sw_gate_x`、`sw_gate_y` | 4×1、1×4 | 固定地圖大城的城門：2 格門洞加兩邊墩子 |
| `sw_gate_x3`、`sw_gate_y3` | 5×1、1×5 | 相鄰出生大城的城門：3 格門洞加兩邊墩子 |

- **地板**（`tiles`、`floor`）：牆以內每一格一塊地磚，種類是廣場 `square`、街 `street` 或菜園 `garden`。箭樓的格子也鋪廣場，拆掉以後才看得到。每座城門外再鋪兩格街。地磚畫在地面層，比單位和建築都先畫。

### 狀態和顏色
- **擁有者**：中立、我方治理、敵方治理用 `intact`，玩家色層乘上擁有者的顏色：中立 #d8d2c0（米色）、我方藍、敵方紅。
- **廢墟**：用 `ruin`：燒黑、旗子燒成破布、門照樣開著。`ruin` 的圖沒有玩家色（不在 `team` 表裡）。
- **玩家色**只在城門、望樓、角樓上，一般牆段沒有，是刻意的：擁有者的顏色集中在門和角，遠看才清楚。量測見第 9 節。

### 前後順序與擋住
- 牆的圖塊和建築、單位一起照第 6 節排（前緣 y，`front` 已經算好）。
- **前面的牆會擋住牆後的兵**（靠鏡頭那一面，也就是南面）。
  - 石牆 4.2–4.6 公尺，兵站在牆後面整個看不到；木柵 2.6–2.9 公尺，會擋到兵的腰以下。
  - 建議做法：「輪廓」。畫完所有圖塊以後，把被牆擋住的兵再畫一次，只畫輪廓，用他的玩家色、透明度 45%。
    - 判斷擋住：兵的圖案方框和一張「在他後面畫」的牆圖塊重疊。
    - 敵我的兵都畫；迷霧裡看不到的不畫。
  - 選到的兵另外加亮：選取圈也畫在牆的上面。
  - 輪廓太慢的話，退一步的做法：自己的兵在牆後時，那一段前牆（只有南面那一排）畫成 50% 透明。這樣比較簡單，但看起來牆會一閃一閃，所以排第二。
- 城門的門洞：門洞沒有東西擋，兵走過去照常畫。

### D-096：城門的四種樣子、牆上的兵、城樓射箭（art-v5.2 起；使用者 2026-10-22 核准 R8-15 到 R8-20）
規則（core #266）：
- 城門關起來，只讓擁有者的兵過；所有兵都打得破。
- 遠程兵和法師可以上自己城鎮的牆；民兵一半上牆投石。
- 治理的城鎮，城樓會射箭。
- 模擬裡能站人的牆格是 `castle.wall`：一般牆段、角落（小鎮的望樓、大城的角樓）、大城城門兩側的柱子格。

**一般牆段改成四面分開**
- 圖塊是 `pal_n`、`pal_s`、`pal_w`、`pal_e`、`sw_n`、`sw_s`、`sw_w`、`sw_e`。art-v4 的 `pal_x`、`pal_y`、`sw_x`、`sw_y` 不再用。
- 走道在城裡那一側，所以北、南不能共用。`layouts` 已經照格子指好。
- 木柵：尖樁照舊，城裡那一側一道射擊台（木板架在柱子上）。尖樁高出台面 1.3 公尺。
- 石牆：
  - 牆頂是走道。外側一道有垛口的胸牆：每格中間一個垛口，下緣離走道 1 公尺；垛子東陸 1.55 公尺、西陸 2 公尺。
  - 城裡那一側一道矮牆：東陸女牆 0.9 公尺、西陸 0.6 公尺。
  - 依據見 R8-15、R8-16 的參考圖。

**牆上的兵站在哪裡**（和 war-game-client 2026-10-22 談定）
- 一般牆段：
  - `walk_m`：走道離地的高度。
  - `stand_in_m`：兵站的位置，從格子正中往城裡量，單位公尺；負的是往城外。
  - 兵的位置：格子正中往城裡挪 `stand_in_m`，再往上抬 `walk_m`。高度用第 0 節的投影換成畫面上的位移。
- 角落和城門（`pal_corner`、`sw_ctower`、`sw_gate_*`）：
  - `stand_m`：`{"dx,dy": [x, y, z]}`，每一格各有一個站點。
    - `dx,dy`：從圖塊西北角那一格數起。
    - `x, y, z`：x 往東、y 往南、z 往上，從錨點量，單位公尺。
  - `walk_m`：站點的高度。
  - 望樓站在平台上；角樓站在頂上，前面兩格在正面、後面兩格在兩側，不站在亭子或錐頂後面；城門的柱子格站在城樓的平台或塔頂。
- 畫的順序，同一個圖塊裡依序疊：圖塊 → 站在這個圖塊上的兵 → 圖塊的前片。
- 前片：
  - 城鎮有人持有時（`intact`，城門還有 `closed`、`damaged`、`broken`）用 `intact_front`。
  - 廢墟用 `ruin_front`。
  - 前片只放真的擋在某個兵前面、在畫面上和他重疊的部件。和圖塊同一個錨點，只有顏色層，沒有影子、沒有玩家色。
  - 前片是空的圖塊，`frames` 裡就沒有這兩個名字，不用畫。
- 兵的影子：站在牆上的兵不畫影子（牆頂不是地面）。

**城門**（`pal_gate_x`、`pal_gate_y`、`sw_gate_*`）多三個影格
- `closed`：關著。
- `damaged`：受損，門被打破一塊，有火和煙。
- `broken`：破了，門倒在地上；模擬裡門已經不在。
- `intact` 是開著的門（art-v4 原樣）；`ruin` 照舊。
- 建議：
  - 血量一半以下用 `damaged`。
  - 自己的兵在門口一兩格內時用 `intact`（開著），其他時候用 `closed`。
  - 廢墟的城鎮照舊用 `ruin`。
- 東西門從這個鏡頭看是側面，門扇看不出來。受損和破了的時候，火、碎木和倒下的門扇掉在牆外，看得到。

**城樓射箭**
- 城門的 `pieces` 多 `shoot_at_m`：箭出發的點，兩個。座標同上（x 往東、y 往南、z 往上，從錨點量，公尺）。
- 射箭時用離目標近的那一個點，在那裡播效果 `tower_shot`（`effects.json`，5 格，每秒 20 格，錨點在正中間）。
- 箭照現在主城、箭樓的畫法飛。

## 12. 地形 `terrain/terrain.json`（art-v5 起，R6-51）

使用者 2026-10-20 看 R6-51 地形設計稿，說「全部照整張地圖加」；密林選甲「可以砍」，所以密林就是一般的樹（用 `nodes.json` 的樹，這裡沒有密林）。地形的值和形狀是 war-game-core 的（PR #245，`sim/PROTOCOL.md` 3.6）：

| 值 | 地形 | 畫什麼 |
|---|---|---|
| 0 | 空地 | 不畫 |
| 1 | 岩石（石堆、岩脊） | 每格一堆石頭 |
| 2 | 城牆 | 第 11 節 |
| 3 | 水（河、湖） | 水的圖塊 |
| 4 | 淺灘 | 水的圖塊，再蓋一張淺灘 |
| 5 | 橋，南北向（人南北走） | 水的圖塊，再蓋橋面，兩側欄杆 |
| 6 | 橋，東西向 | 同上 |
| 7 | 懸崖 | 每格一根岩柱，相連的格子之間一段岩壁 |

- 一律只看這一格和旁邊幾格的值就決定畫哪一張，協定不用多帶資料。
- 參考程式是 `design/b1/common/terrain_rules.py` 的 `pieces()`：client 照它寫，結果要一樣。設計稿也用它畫。

```json
{
  "format": "war-game terrain 1", "scale": 3, "px_per_m": 60, "cell_m": 2, "view": "oblique",
  "pages": { "color": ["terrain_color_0.png"], "shadow": ["terrain_shadow_0.png"] },
  "rules": { "values": { }, "wet": [3, 4, 5, 6], "ground_order": ["water", "ford", "deck"],
             "variant": "(x * 31 + y * 17 + ((x ^ y) & 7)) % n", "rock": { }, "water": { }, "ford": { }, "bridge": { }, "cliff": { } },
  "frames": { }, "shadows": { }
}
```

### 每一種怎麼擺
- **座標**：`(x, y)` 是格子，那一格是 sim 的 `[x, x + 1)`、`[y, y + 1)`。「中間」是 `(x + 0.5, y + 0.5)`。錨點和建築一樣，是地面上的一點（`ax`、`ay` 對到這一點，用第 0 節的投影換到畫面）。
- **哪一張**：同一種有好幾張時，用 `variant`：`(x * 31 + y * 17 + ((x ^ y) & 7)) % n`，只用小整數，每台裝置算出來都一樣。
- **岩石（1）**：中間放 `terrain_rock_v<0–5>` 其中一張，前緣 `y + 1`。相鄰的格子自己排成石堆和岩脊。
- **水（3、4、5、6）**：水的圖塊放在**格子的角**上，不是格子中間。
  - 地圖上每個角 `(X, Y)`（`X`、`Y` 從 0 到地圖寬高）看它四周四格是不是「濕的」（值 3、4、5、6；淺灘和橋也算，岸才畫得對）。
  - 四格合成一個 4 位元的數：西北 `(X−1, Y−1)` 是 1、東北 `(X, Y−1)` 是 2、西南 `(X−1, Y)` 是 4、東南 `(X, Y)` 是 8。北是 sim 的 −y。地圖外的格子當成最近那一格。
  - 不是 0 就畫 `terrain_water_m<數>`（1–15），錨點是那個角 `(X, Y)`。
  - 每一張剛好一格大：3 倍 120×60、2 倍 80×40 像素，錨點在正中間。相鄰的圖塊邊對邊接起來，沒有縫。
  - 岸是泥土色，大約 0.55 公尺寬，畫在乾的那一格上。
- **淺灘（4）**：水的圖塊之上，中間再放 `terrain_ford_v<0–1>`（淺水和墊腳石）。
- **橋（5、6）**：水的圖塊之上，中間放橋面：5 用 `terrain_bridge_deck_ns`，6 用 `terrain_bridge_deck_ew`。
  - 橋面的影子已經畫在橋面那張圖裡，不用另外畫。
  - 欄杆是站著的圖塊，放在橋的兩條長邊上：
    - 5（南北向）：西邊 `(x, y + 0.5)`，條件是 `(x − 1, y)` 不是 5；東邊 `(x + 1, y + 0.5)`，條件是 `(x + 1, y)` 不是 5。圖用 `terrain_bridge_rail_y`，前緣 `y + 1`。
    - 6（東西向）：北邊 `(x + 0.5, y)`，前緣 `y + 0.01`，條件是 `(x, y − 1)` 不是 6；南邊 `(x + 0.5, y + 1)`，前緣 `y + 1`，條件是 `(x, y + 1)` 不是 6。圖用 `terrain_bridge_rail_x`。
  - 橋面高 0.44 公尺（`rules.bridge.deck_top_m`）。兵走在橋上時，畫面往上抬 0.44 公尺（第 0 節：1 公尺高＝17.32 pt）看起來才是站在橋面上；不抬的話，腳會陷在橋面裡。抬不抬由 client 決定，模擬不受影響。
- **懸崖（7）**：
  - 相連的懸崖格之間放一段岩壁。錨點在兩格中間的那一點：
    - 東邊 `(x + 1, y)` 是 7：`terrain_cliff_arm_E_v<k>`，錨點 `(x + 1, y + 0.5)`，前緣 `y + 0.99`。
    - 南邊 `(x, y + 1)` 是 7：`terrain_cliff_arm_S_v<k>`，錨點 `(x + 0.5, y + 1)`，前緣 `y + 1.99`。
    - 東南 `(x + 1, y + 1)` 是 7，而且 `(x + 1, y)`、`(x, y + 1)` 都不是 7：`terrain_cliff_arm_SE_v<k>`，錨點 `(x + 1, y + 1)`，前緣 `y + 1.99`。
    - 西南 `(x − 1, y + 1)` 是 7，而且 `(x − 1, y)`、`(x, y + 1)` 都不是 7：`terrain_cliff_arm_SW_v<k>`，錨點 `(x, y + 1)`，前緣 `y + 1.99`。
    - 每個方向有 3 種，`k` 是起點那一格 `(x, y)` 的 `variant(x, y, 3)`，一長段直的岩壁才不會每格都一樣。
  - 斜的岩壁只在沒有直角轉彎的地方畫。階梯狀的懸崖線靠東、南兩段接起來，不會多出一塊三角形。
  - 岩壁的兩端比格子中間多伸出 0.15 公尺，截面一樣。直線上的兩段在中間重疊，接成一片，中間不用岩柱。
  - 岩柱 `terrain_cliff_post_v<0–1>` 只放在轉彎、線的兩端和分岔的格子中間，前緣 `y + 1`。判斷方式：這一格「連到」的方向，也就是四邊是懸崖的那幾格，加上斜角是懸崖、而且中間兩格都不是懸崖的那幾格。連到的方向剛好是相反的兩個（東西、南北、或兩條斜線），就不放岩柱。
  - 岩壁的前緣比同一排岩柱小一點，岩柱一定畫在岩壁後面，蓋住接頭。
  - 懸崖是一道連續的岩壁：截面沿著線掃過去，高約 2.8 公尺，半腰有一道岩層，腳下有碎石。這是使用者選了懸崖以後重畫的，第一版看起來像一排石柱。

### 圖層和前後順序
- **地面層**（`ground_order`）：水的圖塊 → 淺灘 → 橋面，接著才畫第 6 節的地面層建築（農田）和城牆的地磚。岸會伸進旁邊的乾格子約 0.55 公尺，蓋在乾格子上的農田要畫在岸的上面。這些都比影子層、單位和站著的建築先畫。地面層的地形圖塊沒有影子，不在 `shadows` 表裡。
- **站著的**：岩石、岩柱、岩壁、欄杆。和建築、單位、樹一起照第 6 節的前緣排，影子畫在影子層。
- 地形不擋射擊和視野（core 的規則），所以不用像城牆那樣畫輪廓。
- 地形沒有玩家色（沒有 `team` 頁）。
