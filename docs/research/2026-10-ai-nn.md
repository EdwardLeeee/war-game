# 困難電腦的小型類神經網路（D-086 B）

war-game-ai，2026-10-19 起。依據：D-086、brief `docs/briefs/2026-10-ai-stronger.md` 的 B 段、ceo 核准的計畫（2026-10-19），以及使用者的建議「人工給它一些意見讓它再去學」（ceo 2026-10-19 轉達）。

這份筆記寫做法、數字，和每個數字出自哪個 run。數字到了再補上。

## 1. 網路管什麼

網路打開時（`HardPlan.net` 有權重），只管困難的四個決定，其他照困難原本的規則。每組決定的第一個選項都是「照困難」（ceo 2026-10-19 核准）：選它就照困難原本的規則做。所以權重全是 0、只有「照困難」有偏差的網路（`asHardNet`），打起來和困難一模一樣。網路學的是什麼時候不照困難。

| 決定 | 選項（第一個都是照困難） | 不照困難時，換掉困難原本的哪一條規則 |
|---|---|---|
| 軍隊（在家時） | 照困難、守家、出兵打敵方主城 | 出兵門檻（pushArmy、比強弱、反擊）；守家時也不去拿城鎮 |
| 練兵比例 | 照困難、槍兵多（70%）、遠程多（30%） | 照看到的敵軍調比例（counterMix） |
| 下一個蓋的 | 照困難、村民先（目標多 4 名）、兵營射場先 | D-083 (c) 的 productionFirst |
| 第一次打下的城鎮 | 照困難、搶、治理（付得起才治理） | D-086 A2 的「第 12 分起，最近的小鎮付得起就治理」 |

- 兵怎麼走、怎麼打、躲晶砲、撤退、拆據點時比強弱（D-081），都照困難原本的規則。
- 網路每次思考都算一次，每 10 tick，間隔和現在的電腦一樣。
- 時間上限快到時（AI 對 AI 的最後幾分鐘）和總攻時，照困難原本的規則。

### 不准選的（遮罩）

ceo 2026-10-19：明顯不合理的選擇，直接不准選。遮罩只管「不照困難」的選項；照困難時，困難自己的規則裡已經有這些限制。門檻都從困難現在的規則裡取，做成參數：

- 兵少於 `netMarch`（14，困難的 counterArmy），或還不知道敵方主城在哪：不准出兵打主城。
- 村民少於 `netFarmers`（12，困難第 12 名村民才蓋射場）：不准「兵營射場先」。

## 2. 輸入：只用困難自己知道的

網路有 48 個輸入，都是 0–255 的整數，由 `sim/src/ai/net.ts` 的 `features` 算：

- 自己：第幾分、四種資源、人口、上限、天花板、村民和各兵種的數量、九種建築的數量、兵的總值、在家和在外的兵、主城血量。
- 敵人：困難記得的敵兵（槍兵、遠程、法師、騎兵）和總值、現在主城旁看到的敵兵、知不知道敵方主城在哪、上次看到時的血量、知道的據點數。
- 城鎮：自己治理的、正在搶或等選擇的、敵方的、中立的、廢墟，以及最近一座中立城鎮的距離。
- 狀態：困難現在的模式（在家、去城鎮、打主城、防守、拆據點），還有最近兩分鐘自己死了幾名兵、看到敵兵倒了幾名。

這些都來自困難自己的 PlayerView 和它的記憶，和困難原本用的一樣，所以不會開掛。`ai.test.ts` 有一個測試檢查這件事：同一個畫面，迷霧裡多放 30 名敵兵，網路的輸入和下的指令都一模一樣；放在看得到的地方，輸入就會變。

## 3. 怎麼算：手機上要一模一樣

- 形狀：48 → 32 → 16 → 12（四組輸出，各 3 個）。
- 大小：權重 2240 個、偏差 60 個，存成 JSON 大約 8 KB；上限是 500 KB。
- 算法：
  - 權重是 −127 到 127 的整數，加總用 32 位整數。
  - 每一層做完 ReLU 後右移，再限制在 0–255。
  - 每組取分數最高的；同分時取編號小的。
- 不用浮點數，不用 exp、softmax 或任何 Math 函式。`ai.test.ts` 檢查 `net.ts` 裡沒有 Math 和小數，另外用一組固定的權重和輸入核對輸出分數。
- `net.ts` 會打包進模擬 Worker。訓練的程式在 `sim/src/ai/learn/`，Worker 不會 import。`ai.test.ts` 會從 `worker.ts` 開始追所有 import 來確認。

## 4. 怎麼訓練

### 4.1 起點：和困難一模一樣的網路

- 原本計畫先模仿困難（行為複製）再演化。量過以後改成從 `asHardNet` 開始（ceo 2026-10-19 核准），原因見第 7 節的紀錄。
- `ai.test.ts` 有測試：`asHardNet` 一邊或兩邊打開，和網路關著的困難，同一局打 12 分鐘的雜湊相同（固定、隨機地圖）。CI 上也用電腦對電腦的組比 finalHash。
- 記錄工具（`learn/train.ts record`）留著：記下困難在每個決策點的輸入和它實際做了什麼，之後拿來檢查網路「不照困難」的時候。

### 4.2 再用演化策略微調（`learn/es.ts`）

- 從 `asHardNet` 開始。
- 每一代的做法：
  - 把權重加上和減去同一個隨機擾動，做成成對的候選，四捨五入成整數。
  - 每個候選打同一批局：同樣的種子、出生點和對手。
  - 照分數排名，權重往每一對裡比較好的那一邊移。
- 每一局都用遊戲裡真的會跑的整數網路在打。
- 分數：
  - 贏得 1 分，輸和平手都是 0 分。平手算輸，這樣才不會學成只守不攻。
  - 中間加分（ceo 2026-10-19）：用 D-086 A 量到的東西，小小地加。
    - 第 20 分有治理城鎮。
    - 第 10–20 分木頭卡住的分鐘數少。
    - 第 20 分兵比對手多。
    - 村民被殺後有補回。
    - 局末差距。
  - 加分的權重：第 0 代是 0.2（五項全滿也只加 0.2 分，贏一局是 1 分），到第 60 代減到 0。
- 由易到難（ceo 2026-10-19）：
  - 原本：先對普通，勝率過 60% 改對困難，過 45% 改成混合（困難一半、普通四分之一、新那組四分之一）。
  - 起點已經和困難一樣強，對普通一開始就贏九成，所以「先對普通」那一段沒有意義。預設從混合開始（`startStage: 2`）；要從普通或困難開始，在設定裡改。
- 每一代都回報：
  - 局數、贏、平手、輸；
  - 「打到對方主城的局數」（10 名以上的兵到對方主城 12 格內）。這是用來看它有沒有為了拿加分而囤兵不出門；
  - 每組決定，「照困難」以外的選項各被選了幾次，以及「不照困難」佔全部思考的比例（ceo 2026-10-19）。風險是網路永遠照困難、不敢改，這一欄看得到它有沒有在試。

### 4.3 人工看（ceo 2026-10-19）

- 每跑一段（大約每 20 代），抽 3–5 局目前最好那份網路的時間軸，寫它犯了什麼錯，再調整中間加分和不准選的門檻，然後繼續練。
- 每次調整都記在這裡：第幾代、看到什麼、改了什麼。
- 使用者的對局紀錄只在本機用，用來找網路和困難的毛病，不拿來模仿，也不上傳成 GitHub 的 artifact。

### 4.4 GitHub 上怎麼跑（`.github/workflows/ai-train.yml`）

- 只用手動啟動，權限只有讀。啟動的方法有兩種：
  - 從 Actions 頁面啟動（workflow_dispatch）。這要等這個檔合併到 main 才能用。
  - 推一個 ai/train-* 分支，分支裡的 `sim/src/ai/learn/run.json` 寫設定，欄位和 workflow_dispatch 的參數一樣（ceo 2026-10-19 同意）。只有 war-game-ai 手動推才會跑。
- 有自己的 concurrency group，同時只跑一次訓練；每次最多 8 個 job。
- 每個 job 跑到 5.5 小時就存檔，上傳成 artifact，保留 14 天，不 commit；下一次從那個 run 的存檔接續。
- 最後一個 job 把這次 run 的 job 時間加起來，算出 runner 小時。
- 第一次先試跑（dryrun），量 runner 有幾核、一小時打幾局，再算預算夠練幾代。

## 5. 怎麼比強弱

照 brief：

- 網路版對現在的困難，至少 100 局，兩個出生點對調；平手要列出來，特別看只守不攻的平手。
- 也比：對普通、主動四組、新那組（後期翻盤）。
- 思考時間用現在的量法。
- 最後回報的數字，用 scratch 分支打開網路，跑 CI 的電腦對電腦和腳本玩家。
- `learn/train.ts eval` 是訓練中看進度用的。

- 演化策略第一次跑完。
- 開始訓練後滿 2 週，或用滿 500 個 runner 小時，先到的那個為準。

### 7.3 演化策略 v1：724.7 小時沒有比困難強，但網路幾乎看不到局面（2026-10-29、30）

- v1：分支 ai/train-es1，8 個島，規則是整批之前的 main（KEEP、SIEGE、RICH 都關），對手照第 4.2 節的混合。最後的存檔是 run 40797044106，第 570 代左右。
- 比強弱（run 40830579194）：8 個島拿平均權重對困難各打 200 局，都在對照的起伏內。對照（困難本身，同一批種子）是 44-12-44（固定）、39-22-39（隨機）。ceo 決定停掉這條鏈。
- 2026-10-30 查 v2 時發現同一個 bug，v1 也有：
  - 中間兩層都右移 8 位（除以 256），權重又是個位數的小整數，第二層的輸出幾乎都是 0。
  - 拿真實對局的 123 個決策點，餵 v1 第 570 代的島 0、2、5：第二層最大只到 3–5（滿分 255），非 0 的只有 24–40%。這 123 個決策點裡，選擇的組合島 0 有 7 種、島 2 有 3 種、島 5 有 4 種；各組決定的分數只差 26–107，很少會改變選擇。
- 所以「v1 沒有比困難強」不能當成「從困難開始用演化策略微調」這個做法沒用的證據（ceo 2026-10-30）：v1 的網路只有一點點看得到局面。

### 7.4 演化策略 v2（ceo 2026-10-29 核准，分支 ai/train-v2，不合併）

- 規則：整批（D-112 起 main 的預設）；訓練的開關多了 MARKET。
- 起點：0 權重，也就是 kbag 困難。
- 決定：
  - 軍隊、城鎮照舊；
  - 新增第 5 組「防守」：照困難／現在存錢在主城或治理的城旁蓋箭樓／先不蓋；
  - 練兵、先蓋什麼：輸出那兩組的權重固定，永遠照困難。
- 每代：4 對候選，每個候選打同一批 32 局。
  - 對手：困難 13、普通 3、push 6（每 3 局有 1 局帶騎兵）、push-crush 7（玩家採集 +30%）、push-turtle 3。
  - 上限 60 分，沒分出勝負算輸。
- 比強弱：
  - 每個 run 跑完，6 個島的平均權重各對困難打 200 局（60 分）、對 push-crush 打 40 局（90 分），種子從 2000001 起。
  - 對照是困難本身，同一批種子：run 40886447856，對困難 99-2-99（贏－輸的標準差 14.1）；push-crush 21-2-17，第 45 分平均 6.3 座箭樓、3.5 座治理的城。
  - 有 PR 的檢查在跑或在等時，那次不比。
- 停止規則（ceo 2026-10-29、30）：
  - 預算 300 runner 小時；
  - 第一次有島比對照多 2 個標準差以上，先用新種子重比（對困難 400 局、push-crush 40 局），重比也超過才算數；
  - 300 小時用完時，最好的島比對照多 1 個標準差以上、而且一次比一次好，才再加 300 小時，只加一次。
- 第一次開跑（f1c7555，run 40895405707 起，約 95 runner 小時）作廢：
  - 第二層一直是 0，每個島整局都做同一組選擇，只由最後一層的偏置決定。
  - 所以權重不同的島，打出一模一樣的局：
    - 島 0、5 是「一直不蓋塔」，兩次都 89-3-108；
    - 島 1、4 是「一直治理」，89-2-109；
    - 島 2 一直照困難，99-2-99，剛好等於對照。
  - 比強弱的 run：40936790862、40973295432、40998173610。
- 修正（3511ef2，ceo 2026-10-30 核准，預算重新給 300 小時）：
  - 中間兩層的位移從 8 改成 4（`NET_SHIFT`），位移存在權重檔裡。
  - 40 個隨機候選（訓練時的雜訊 ±4），在 400 個真實決策點上：位移 8 只有 5 個會隨局面改選擇，位移 4 是 40 個；第一層飽和（到 255）只有 1%。平均權重（約 ±1）：位移 8 是 0 個，位移 4 是 40 個。
  - 加了三道檢查：
    - 每代報告列出有幾個候選在局中改過選擇；
    - 比強弱列出平均網路一共用了幾種選擇組合；
    - 單元測試：照訓練的雜訊大小隨機給權重，10 個網路至少 9 個要隨局面改選擇。位移 8 時只有 2 個。
  - 從 0 重新開始。
- 修正版的結果（D-116）：
  - 練了約 66 runner 小時，比強弱兩次（runs 41044811137、41078453635），6 個島都沒比困難強，島 2 對困難差 −4.05 個標準差。
  - 原因：「照困難」的偏差只有 1，訓練的雜訊 ±4／±64 就把它蓋過去。候選有 53–71% 的決定不照困難，大半是亂下。
  - 鏈子在 run 41078447033 因為下載存檔的暫時錯誤斷掉，ceo 決定不再接。

### 7.5 演化策略 v3（ceo 2026-11-01 核准，分支 ai/train-v3，不合併）

- 和 v2 不同的地方：
  - 「照困難」的偏差從 1 改成 2500（`asHardMargin`）。拿真實對局的 650 個決策點、40 個候選量過：
    - 2500：不照困難的比例 12–13%，40 個裡有 34 個會隨局面改選擇；
    - 1500：20–27%；
    - 3000：5–11%，只有 27 個會隨局面改選擇。
