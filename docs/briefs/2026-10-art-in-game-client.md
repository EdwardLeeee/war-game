## 範圍（`client/`、`.github/workflows/pages.yml`、`.github/workflows/client.yml`）

1. **拿圖**：
   - Pages 和 CI 建置時照 tag 下載 Release、核對 sha256。
   - Release 出來之前，本機可以先用 artifacts 開發，但不要 commit 圖。
   - 怎麼下載、放在哪裡、tag 寫在哪個檔，由你提，寫進 sprite-atlas.md。
2. **iPhone 量測頁**（先做這個，量完才定倍率）：
   - 載入整套兵種圖集，跑現有的量測場景（很多兵同時打）：
     - 3 倍未壓縮。
     - 2 倍未壓縮。
     - 有 ASTC 的話，加一頁 ASTC 樣本。看顏色和邊緣，ui 要等這個結果才量產壓縮版。
   - 讀這些數字：
     - fps 中位數、最慢 5%、每 tick 幾 ms。
     - Safari 有沒有因為記憶體不足重新載入分頁。
     - `MAX_TEXTURE_SIZE`、`MAX_TEXTURE_IMAGE_UNITS`、有沒有 ASTC。
   - 使用者用 iPhone 14 Pro Max 量。步驟寫成 3–5 步，給 ceo 轉給使用者。
   - 結果決定 D-017 的倍率。
3. **換兵種**：
   - 原型的兵：村民、槍兵、遠程、法師、騎兵。民兵用同文化的槍兵，套中立色。攻城器械原型沒有。
   - 動作照規格：
     - 一般動作：待機、走路、攻擊、倒下。
     - 村民的 4 種工作。
     - 法師的晶彈、施法、受擊、破盾，防護罩那一層。
     - 落地揚塵。
   - sim 的朝向對到圖片的 8 個方向，照規格第 3 節。
   - 玩家色先用現在的 `OWN_TINT`、`ENEMY_TINT`，R6 定案後再換。
   - 選取圈、血條、躲藏、閃紅這些標示照舊，疊在圖上。
   - **我方和電腦穿哪一陸的衣服**，使用者還沒決定。做好以後出截圖選項，ceo 拿去問使用者：
     - A：我方東陸、電腦西陸。
     - B：我方西陸、電腦東陸。
     - C：兩邊同一陸，只靠玩家色分。
4. **換建築和資源點**（ui 的 Release 有建築以後）：
   - 照 B1-02：施工中分三階段、受損著火、被摧毀變瓦礫堆。
   - 資源點：樹、金礦、野果、晶脈。
   - 還沒有圖的照現在畫：哨所、地形的岩石、城鎮符號（D-084）。
- **不改模擬**：
  - `sim/` 一行都不動，這樣上線後使用者手機上存著的局還能繼續。
  - 占地、擋路、城鎮配置照現在的模擬。圖和占地對不起來的地方，回報 ceo，不要自己改圖或改規則。

## 驗收

- 全部圖都載入時，在使用者的 iPhone 上：fps 中位數 ≥55、最慢 5% ≥30、每 tick ≤5 ms（第二階段的驗收標準）。
- 截圖 814×380，合併前 ceo 給使用者看：
  - 每種兵的待機、走路、攻擊、倒下。
  - 村民的工作。
  - 法師開防護罩、破盾。
  - 兩軍交戰。
  - 我方、敵方、中立（民兵）。
  - 換建築那一個 PR 另外再附：每種建築的完成、施工中、受損、被摧毀，和資源點。
- e2e：兩個瀏覽器都跑，畫面 814×380。
- 回報 CI 時，依 head SHA 列出全部 run。
- 最後以使用者的 iPhone 實機為準。

## 流程

- 先把計畫回給 ceo（簡短），核准後開始：
  - 分幾個 PR：例如量測頁、兵種、建築。
  - 拿圖的做法。
  - 等 ui 的 Release 時先做什麼。
- 從 origin/main 開新分支。
- 會改變試玩版本的 PR，第一行寫「會改變試玩版本」。合併時機由 ceo 決定。
- 公開 repo：不放金鑰、個資，不 commit 圖集。
