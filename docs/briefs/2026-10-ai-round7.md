主旨：war-game-ai 讓電腦會用第七輪的規則：城鎮只能搶一次、箭樓、遠程兵和法師躲進建築、騎兵。普通做最少的改動，困難重新量。依據是使用者 2026-10-07 的回饋（D-061）和 war-game-core 的第七輪協定（PR P）。

## 目標

- 電腦不會因為新規則卡住（例如一直搶已經搶過的城）。
- 打普通也看得到新東西：電腦會出騎兵、被打時會躲進主城。
- 困難照樣越強越好、不能開掛（D-055），而且用得上新規則。

## 依據

- 使用者原話與選擇：`docs/decisions/log.md` 的 D-061（含補充）。
- 規則和協定：`docs/briefs/2026-10-core-round7.md`；core 的 PR P（`sim/PROTOCOL.md` 第七輪那幾節）。
  - 敵方建築只看得到「有人躲著」（`BuildingFlag.Occupied`），看不到幾名。
  - 城鎮的 `TownFlag.Plundered`、`incomePermille` 電腦也看得到。
  - Rules 帶主城射箭、箭樓、騎兵、馬廄的數值，不要在 `ai.ts` 寫死。
- 你 2026-10-07 提的三件事和 ceo 的回覆（D-061 補充）。
- 困難的做法和量測工具：`sim/README.md` 的困難那節，`../war-game-worktrees/ai-tools/`。

## 範圍

### 要改（`sim/src/ai/`、`sim/test/ai.test.ts`）

1. **所有難度**：看到 `Plundered` 的城鎮，攻下後只治理，不再送 `plunder`。
2. **困難要修的**：周圍看得到、人卻不見了的敵兵，不要算成陣亡；看到走進建築的，記成躲著。
3. **普通**（其他行為不動）：
   - 對方有法師或遠程兵時，出一些騎兵（要蓋馬廄）。比例你定，簡單的規則就好。
   - 主城被打的時候，把遠程兵和法師躲進主城；打退了再出來。
   - 要不要蓋箭樓，你量完提議。
4. **簡單**：只做第 1 項。
5. **困難**：箭樓、躲進建築、騎兵、治理還是搶，都可以當成參數，照以前的做法在 CI 上兩個位置互打來挑。

### 不做

- 規則、協定、腳本玩家、CI workflow：war-game-core。需要協定改動就回報 ceo。
- 畫面：war-game-client。

## 驗收條件

- [ ] `ai.test.ts`：上面每一項各有測試，拿掉改動時要失敗。
- [ ] 100 局門檻照舊：普通對普通出生點 35–65%、平手 ≤ 25%、重播 0；普通對簡單 ≥ 80%；簡單第一次打野城不早於第 18 分。
- [ ] 困難對普通 100 局，分出勝負的局困難至少贏 65%；困難對困難出生點 35–65%、平手 ≤ 25%。
- [ ] 腳本玩家主動那幾組對新的普通，和 core 的量測並列：主動、一直搶城鎮、自動訓練、自動加搶城鎮、搶城鎮後治理。
- [ ] 電腦對不動的玩家的時間軸（種子 1–5）：普通、困難各自第幾分出第一名騎兵、第一次打主城帶幾名、有沒有躲進主城。
- [ ] perf：思考時間列在 PR 描述。
- [ ] `sim/README.md` 的電腦那幾節同步更新。
- [ ] 回報 CI 時依 head SHA 列出全部 run。

## 限制

- 等 core 的 PR P 合併後再開始；T、D、K 還沒合時，在暫存分支（`ai/scratch-*`）疊上去量。
- 只看自己的 PlayerView，不給加成（`test/boundaries.test.ts` 照樣管）。確定性規則照 `AGENTS.md`。
- 公開 repo：不放金鑰、個資或真實姓名。
- 本機只跑相關的單元測試和小型量測，完整對局最多 5 局；重工作用 `systemd-run --user --scope -q -p MemoryMax=1500M -p MemorySwapMax=0` 包起來，available 低於 2000 MB 就等。
- 合併時機由 ceo 決定：和 core、client 的第七輪一起上線。
- 使用者指示（2026-10-03）：你自己 terminal 每個回合的結尾文字一行就好；給 ceo 的訊息只在三種時候傳：計畫要核准、PR 好了、需要決定的事。
