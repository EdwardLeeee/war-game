主旨：war-game-ai 讓困難不再輸給「偷家」：派哨兵看路，大軍在外面時算清楚，來不及就回家救援。依據是使用者 2026-10-07 打贏困難的那一局和他的裁示（D-072）。

## 目標

- 玩家帶大軍繞過困難的軍隊直接打它主城時，困難能及早看到，並且做出對的選擇：回家救，或確定自己先拆掉對方主城就繼續打。
- 不能開掛（D-055）：只靠自己單位的視野和記住的情報，和玩家一樣。

## 依據

- 使用者原話與 ceo 查到的：`docs/decisions/log.md` 的 D-072。
  - 使用者：「我直接帶三十幾隻兵攻擊電腦主堡，他的兵比我慢到我的主堡，他的主堡比我早被打爆了」、「當然要補強，而且電腦都沒有插視野吧，它根本不知道我快打到它家旁邊」。
- 程式（`sim/src/ai/ai.ts`，main 4b0d356，和線上 d867633 的 sim 相同）：
  - `createHardAi` 的 `armyOrders`：`committed`（軍隊中心離對方主城比離自己主城近）時，自家主城 16 格內有 4 名以上敵兵也不回防，只送 `recall`。
  - 困難沒有偵察或哨兵；大軍出門後，家附近只剩建築和村民的視野。
- 腳本玩家「主動」（24 名就出發）對困難 40 局全輸（CI run 37567105895）。ceo 看了種子 1、2：出發時困難 36–37 名在家，玩家的兵一分鐘內被打光。所以現有的腳本組量不到這個破綻。

## 範圍

### 要改（`sim/src/ai/ai.ts`、`sim/test/ai.test.ts`；只改困難）

1. **先看使用者那一局**（設計之前做）：
   - 用 `node services/game-logs/fetch.ts` 抓紀錄（`services/game-logs/README.md`「給 war-game-ai」；金鑰只從使用者筆電的設定檔讀，不印、不寫進 repo 或訊息）。
   - 找 2026-10-07 結果是 `win`、對手困難的那一局，用紀錄 `commit` 那一版的 `sim/` 重播，雜湊要對得上。
   - 印時間軸：
     - 雙方大軍各在第幾分出發、兩支大軍最近時相距幾格。
     - 困難第一次看到玩家大軍是第幾分、在哪裡；當時困難的 mode 和 `committed`。
     - 兩邊主城血量什麼時候開始掉、什麼時候倒。
   - 用幾行回報 ceo。玩家的 `deviceCode` 等可以認出手機的資料不要寫進 repo 或 PR。
2. **哨兵**：困難派兵站在通往自家的路上，早一點看到敵方大軍。
   - 位置、人數、兵種、什麼時候派、被打死要不要補，你量完提議。
   - 哨兵不算進出發打主城的兵數。
3. **回家救援**：大軍在外面時，看到（或記得）敵方大軍往自家走，就比較兩邊的主城誰先倒。
   - 估算要用：雙方兵力、路程、主城血量、主城的箭和躲著的兵。估法你定。
   - 自己的主城先倒就回頭救；確定自己先拆掉對方主城就繼續打。
   - 原本「還在自己這半邊就回防」照舊。
4. 其他做法（例如出發前先確認對方大軍在哪）你也可以提，一樣做成參數、量過再留。

### 量測

- war-game-core 會加一組腳本玩家「主動（偷家）」重現這種打法（brief `docs/briefs/2026-10-core-race-group.md`）。
  - 在它合併之前，可以在 `ai/scratch-*` 分支自己寫一份暫時的版本來量。
  - 腳本玩家的正式程式是 core 的，不要放進你的 PR。
- 偷家組：改之前和改之後各 40 局，對困難。目標是改之後偷家很少贏；也列出改之前贏幾局。
- 照舊的門檻：
  - 困難對普通 100 局，分出勝負的局困難至少贏 65%。
  - 困難對困難：出生點 35–65%、平手 ≤ 25%。
  - 普通、簡單逐局和 main 相同（最後的雜湊、局長、勝方）。
- 腳本玩家主動那幾組對困難，和 main 並列。
- 思考時間：中位數、p95、p99、最大值，列在 PR 描述。
- 第八輪（PR #165）合併以後，在新的 main 上重跑上面的量測，再請 ceo 合併。

## 限制

- 只看自己的 PlayerView，不給加成（`test/boundaries.test.ts` 照樣管）。確定性規則照 `AGENTS.md`。
- 公開 repo：不放金鑰、個資或真實姓名。對局紀錄只留在 `~/war-game-logs`，不提交。
- 本機只跑相關的單元測試和小型量測，完整對局最多 5 局。大量對局用 CI 的 `ai/scratch-*` 分支。
  - 本機要跑時，available 低於 2000 MB 就等，並用 `systemd-run --user --scope -q -p MemoryMax=1500M -p MemorySwapMax=0` 包起來。
  - 2026-10-07 18:58 這台電腦才因為記憶體用光當機過。
- 要 rebase 疊著的分支時，不強制推送，改推新分支、開新 PR（使用者 2026-10-07）。
- PR 會改變試玩版本，描述第一行寫「會改變試玩版本」。合併時機由 ceo 決定。
- 使用者指示（2026-10-03）：你自己 terminal 每個回合的結尾文字一行就好；給 ceo 的訊息只在這幾種時候傳：計畫要核准、第 1 項的時間軸、PR 好了、需要決定的事。

2. 第 1 項做完先回報時間軸。
3. PR 好了回報連結、CI 結果和量測表。
