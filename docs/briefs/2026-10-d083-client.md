## 依據

- `docs/decisions/log.md` D-083：使用者原話、選擇欄位、ceo 查到的。
- 使用者看過的選項圖（ceo 畫的示意，不是設計稿）：D083-1-A「離開編隊」，使用者選的。
- 現在的做法（main 0d75ca6）：
  - `game.ts` 的 `pruneArmy`：只有駐守哨所的兵離開編隊；城鎮留守記在 `army.ts` 的 garrisons。躲進建築的兵還在編隊裡，按鈕的「現有」也算他們。
  - `hud.ts` 的 `GROUP_WANT_MAX = 50`。
  - `main.ts` 的 `keepLog`：只在對局結束、或同一頁開新局時存紀錄。使用者的 80 分鐘那局被 Safari 清掉，紀錄也沒了。

## 範圍（`client/`）

### PR A（先做）

1. **躲進建築的兵離開編隊**：
   - 和駐守哨所同一套：兵一躲進箭樓或主城，就離開原本的編隊。目標人數不變。
   - 自動補兵開著就補；挑空閒的兵時，不能挑躲著的兵。
   - 躲著的兵出來以後不在任何編隊。
   - 「退N」、閃紅提醒、全軍、全軍撤退照現在的規則，檢查躲著的兵改成不在編隊以後，結果有沒有變。
2. **每兵種上限**：改成跟著人口上限。core 的新規則合併前，就用現在的上限 120。
3. **頁面切到背景就存紀錄**：
   - 切到背景（`visibilitychange` 變成 hidden、`pagehide`）時，先存一份「沒打完」的紀錄並上傳，條件照現在（打滿 1 分鐘）。
   - 之後打完、或回來接著打，就更新同一筆，不要多出好幾筆。Worker 收不收同一個 id 的更新，你查；要改 Worker 就一起改（`services/game-logs/`）。
   - 不要因為存紀錄讓對局頓一下。

### PR B（等 core 的快轉介面）

4. **繼續上一局**：
   - 對局中定期存（切到背景時一定要存）：指令紀錄，加上畫面這邊的狀態（編隊和目標、留守、駐守、姿態、自動補兵、鏡頭、速度、難度、地圖）。
   - 頁面重新載入後，如果有沒打完的對局，開局畫面多一個「繼續上一局」，寫上第幾分。
   - 按下去：
     - 用 core 的介面快轉，顯示進度。
     - 快轉完，還原畫面的狀態，接著打。
   - 不能繼續時（網站已經更新、紀錄對不上），說清楚原因；紀錄照樣上傳。
   - 對局打完，或開了新局，就清掉存的那一局。

### PR C（等 core 的 perf 場景合併，不用等快轉）

5. **量測**：選單可以選 120、200、360 三種 perf 場景。使用者要用 iPhone 量，人口規則才能上線，所以這個 PR 要比 PR B 先。

## 驗收

- 單元測試：
  - 躲進去就離開編隊；目標不變；補兵不挑躲著的兵；出來以後不在編隊。
  - 每兵種上限跟著人口上限。
  - 切到背景會存紀錄；同一局只有一筆。
- 繼續上一局：
  - e2e 或真模擬：打幾分鐘、存起來、重新載入、繼續；接著打的雜湊和沒中斷的一樣，編隊還在。
  - 網站版本不同時，顯示不能繼續。
- e2e：兩個瀏覽器、814×380 都要測。
- 截圖放 `client/docs/screens/2026-10-d083-*.png`：開局畫面的「繼續上一局」、快轉的進度、躲進去以後的編隊按鈕。ceo 合併前會先給使用者看。
- 回報 CI 時，依 head SHA 列出全部 run。
