# Brief：iOS app（war-game-mobile）

- 依據：D-163（使用者 2026-11-24）、D-162（正式版先只做 1 對 1）、D-013（引擎 TypeScript + PixiJS 8 + Capacitor 8）。
- 負責：`war-game-mobile`（新角色，2026-11-24 起）。負責路徑：`mobile/`、`.github/workflows/mobile*.yml`。
- 收到後先把計畫回給 ceo（不用 plan mode），ceo 核准才動手。每個階段做完回報 ceo，ceo 驗收後才往下。

## 使用者定的

- 只做 iOS（不做 Android）。使用者有 Apple 開發者帳號。免費，不賺錢：沒有內購、沒有廣告。
- 遊戲（含美術圖）帶在 app 裡，不做連到網站的殼（使用者選「同意：遊戲帶在 app 裡（推薦）」）。
  - 依據：Capacitor 官方文件寫 `server.url` 不是給正式版用的；只包網站的殼容易被 App Store 審核 4.2（minimum functionality，"repackaged website"）退件。
  - 代價（使用者知道）：網頁版修好的東西，app 要重新建置、上傳才會更新。
- 先上 TestFlight 給使用者自己裝。要不要公開上架 App Store，等使用者玩過再決定，到時 ceo 問。
- bundle ID：`com.edwardleeee.wargame`（使用者選的；上傳後永遠不能改）。
- repo 公開，但不加開源授權，保留所有權利（使用者選「只公開，不加授權（現況）」）。不要新增 LICENSE 檔。
- 聲音暫時不做（D-162）。

## 事實（ceo 查過的）

- iOS 上 Capacitor 用 WKWebView，和 Safari 同一套 WebKit／JavaScriptCore。所以 app 不會比網頁快（ceo 已告訴使用者）。驗收只要求「不比 Safari 慢」。200 名兵卡頓由 client、core 另外修。
- 網頁的建置在 `client/`（Vite，`base: "./"`，相對路徑）。美術在 GitHub Release，`client/art.lock.json` 釘 tag，`client/scripts/fetch-art.ts` 下載並核對 sha256。iPhone 用 x3 ASTC。
- `client/public/sw.js` 只快取 `art/<tag>/`。WKWebView 的自訂 scheme（`capacitor://localhost`）不支援 service worker，app 裡註冊失敗不能變成錯誤或卡住；美術本來就在 app 裡。
- 對局紀錄上傳（D-056）：`services/game-logs/` 的 Cloudflare Worker，`wrangler.toml` 的 `ALLOWED_ORIGINS` 只有 `https://edwardleeee.github.io`。app 的來源是 `capacitor://localhost`，要加進去才上傳得了。Worker 屬於 client；重新部署要使用者本人用 wrangler 登入的帳號跑一行指令（經 ceo 轉）。
- 「繼續上一局」和設定存在 IndexedDB／localStorage。app 和 Safari 的資料分開，app 第一次打開沒有網頁版的存檔，這是預期的。
- 引擎 spike 已經在 CI 的 macOS runner 建過 Capacitor iOS 模擬器版（`.github/workflows/spike-web.yml` 的 `ios` job、`spikes/tools/ios-run.sh`），可以參考；那是丟棄式的程式，不要重用它的 bundle ID（含本機帳號名）。
- 本機是 Linux，沒有 Xcode。建置、簽章、上傳都在 GitHub Actions 的 macOS runner。repo 公開，標準 runner 不收費。
- 跑 CI 時照 D-123：電腦的訓練會讓位給 PR 檢查和網站部署。訓練開著時，macOS 的 job 也算在 20 個同時的 job 裡。

## 要做的（照 app-store-launch 的順序；Android、公開上架的階段先不做）

1. **app 專案**（`mobile/`）：
   - Capacitor 各套件鎖精確版本，和 `client/` 的版本對得上（寫檢查）。
   - `webDir` 是 client 的建置結果，加上 x3 ASTC 美術。建置不改 client 的工具鏈；需要 client 改東西（例如「在 app 裡」的判斷、不註冊 service worker），寫清楚回 ceo，ceo 派給 client。
   - 只支援 iPhone、只橫向；全螢幕、隱藏狀態列；安全區照網頁現在的做法。
   - `ITSAppUsesNonExemptEncryption = false`；`PrivacyInfo.xcprivacy` 宣告用到的 required-reason API；桌面名稱（暫用「war-game」，正式名稱還沒定，到時 ceo 問使用者）。
   - 圖示和啟動畫面：先用 `client/public/icons/` 現有的暫時圖示（1024×1024、不透明、不自己加圓角）。正式圖示之後由 ui 出稿給使用者看。
   - 完成條件：CI 的 iPhone 模擬器上，全新安裝能開局、玩到第 2 分鐘、存檔後關掉 app 再開能「繼續上一局」，飛航模式（離線）也一樣。
2. **CI**：
   - PR workflow（只在 `mobile/**` 或它自己改動時跑）：建模擬器版、跑冒煙測試、再建一次不簽章的 Release 裝置版。
   - 發布 workflow（手動觸發）：只從已經上線的網頁 commit 建（version.json 的 commit），顯示版本用網頁的 commit 或版號，建置號用 run number。
   - 完成條件：發布 workflow 對一個已上線的 commit 跑完，TestFlight 出現建置。
3. **帳號與簽章**：
   - Apple 那邊的操作寫成給使用者看的逐步指南（開哪個網址、按哪個按鈕、下載哪個檔）：App ID、Apple Distribution 憑證（用 openssl 產生 CSR，不需要 Mac）、App Store 描述檔、App Store Connect API key（`.p8` 只能下載一次）、Team ID、在 App Store Connect 建 app 記錄（名稱要問使用者，被占用就停下來）。
   - 指南交給 ceo，ceo 轉給使用者。金鑰照 `secrets-custody`：放進 GitHub Actions secrets 由使用者本人用 `! gh secret set … < 檔案` 做，任何 session 都不印出、不保存金鑰內容，不放進 repo。
   - TestFlight 內部測試：使用者本人就是帳號持有人，直接加進內部群組。
   - 完成條件：使用者在自己的 iPhone 14 Pro Max 上從 TestFlight 裝好，能開局、繼續上一局、離線玩。
4. **對局紀錄**：app 裡照樣上傳（ai 用使用者的對局找電腦的弱點）。由 client 把 `capacitor://localhost` 加進 Worker 的允許來源，使用者重新部署。紀錄裡要分得出是 app 還是網頁（例如 `ui` 旁加一個欄位），格式改動經 client。

## 不做的

- Android、公開上架 App Store 的商店頁面、截圖、表單、送審（使用者決定要公開上架後另派）。
- 推播、內購、廣告、帳號登入、聲音。

## 公開 repo 規則

- 不提交金鑰、憑證、描述檔、`.p8`、`.p12`、密碼；不出現使用者的真名、email、本機帳號名或本機絕對路徑。
- 新的第三方套件記進 `THIRD_PARTY_NOTICES.md`（Capacitor 是 MIT）。
