主旨：war-game-client 做「對局紀錄自動收集」：每局打完，遊戲自動把指令紀錄存在手機上並上傳到使用者的 Cloudflare，給 war-game-ai 重播和訓練困難電腦。使用者不用按任何東西。依據是使用者 2026-10-04 的選擇（D-056）。

## 目標

- 使用者在 iPhone 上照常玩，每一局的紀錄自動傳到一個收紀錄的地方。
- war-game-ai 拿得到這些紀錄：重播出一模一樣的局、找電腦輸在哪、統計使用者的打法。
- 部署只要使用者做一次登入授權。

## 依據

- 使用者的選擇（選擇欄位，2026-10-04，`docs/decisions/log.md` 的 D-056）：
  - 對局紀錄「要拿來訓練，但玩家不用按分享」。
  - 傳到「用我的 Cloudflare」。
- Cloudflare 官方價格頁（ceo 2026-10-04 查過）：
  - Workers 免費方案每天 100,000 次請求、每次 10 毫秒 CPU。
  - Workers KV 免費方案每天寫入 1,000 次、儲存 1 GB；超過當天的寫入會失敗。
  - R2 的免費額度要不要先登記付款方式，頁面沒寫，所以先用 KV。
- 現有的程式：
  - 模擬的 Worker 已經會匯出指令紀錄（`export_log` → `log` 訊息，第一行是 `LogHeader`，`sim/src/protocol.ts`）。
  - 同一份紀錄用同一版模擬重播，會得到一模一樣的局（`sim/src/headless.ts`）。

## 範圍

### 要做

1. **手機自動存**（`client/`）
   - 每局結束（勝、負、投降、重來前）把紀錄存在手機上（IndexedDB 或你選的儲存），最多留最近 50 局。
   - 每筆附上：遊戲版本的 commit、難度、勝負、遊戲時間、紀錄本身。
   - 不放任何可以認出使用者的東西：沒有帳號、沒有裝置名稱。
   - 為了去重，每筆附一個隨機產生的局編號。
   - 存不了（私密瀏覽、空間滿了）就跳過，不能影響遊戲。
2. **收紀錄的小程式**（`services/game-logs/`，新的路徑，歸你）
   - Cloudflare Worker 加一個 KV。
   - `POST`：收一筆紀錄。檢查格式和大小（上限你定，要能放下一局 40 分鐘的紀錄），不合格的丟掉。
   - 讀取：要帶一把讀取金鑰，才能列出和下載紀錄，給 war-game-ai 用。
   - 注意 KV 每天 1,000 次寫入的上限。一局一次寫入就好；超過時回傳錯誤，手機下次再傳。
   - 試玩網址是公開的，別人打的局也可能傳上來，要能分辨或之後濾掉。例如紀錄裡附版本，ai 那邊只用使用者用的版本；做法你提。
   - 用 `wrangler` 部署；`wrangler.toml` 放在 repo，不放任何金鑰。
3. **手機自動上傳**（`client/`）
   - 每局存好後馬上上傳，成功就在手機上標記已傳。
   - 失敗或沒網路就下次開遊戲、或下一局結束時重傳。
   - 上傳不能卡住畫面，失敗不顯示錯誤給使用者。
   - 收紀錄的網址寫在 client 的設定裡；還沒部署前是空的，就只存不傳。
4. **給 war-game-ai 的取用方式**
   - 一個小工具，例如 `services/game-logs/fetch.ts`：帶讀取金鑰把紀錄抓到本機的資料夾，資料夾不進 repo。
   - 寫進 `services/game-logs/README.md`。
5. **給使用者的部署步驟**
   - 寫成一步一步的說明，放在 PR 描述和 `services/game-logs/README.md`。
   - 在這台筆電上，從登入 Cloudflare、建 KV、設讀取金鑰、到部署，每步寫要打什麼指令、會看到什麼。
   - 使用者可以在 Claude Code 裡打 `! <指令>` 執行。
   - 讀取金鑰由使用者產生、只存在他的筆電（例如 `~/.config/war-game/`）和 Cloudflare，不進 repo、不傳給任何 session 的訊息。

### 不做

- 上架用的隱私說明和「關掉上傳」的開關：上架前再做。GDD 會記一筆。
- 拿紀錄訓練電腦：war-game-ai。
- 自動部署的 workflow：這一輪先由使用者手動部署一次。

## 驗收條件

- [ ] 單元測試：
  - 存、留最近 50 局、去重。
  - 上傳成功就標記、失敗重傳。
  - 沒有網址時只存。
  - Worker 的格式檢查、大小上限、讀取要金鑰。
- [ ] e2e：打完一局（用測試場景），紀錄被存下來；上傳打到一個假的網址並帶對的內容。
- [ ] 用一份上傳的紀錄重播（`sim/src/headless.ts`），最後雜湊和那局一樣。
- [ ] 沒有金鑰、帳號或個資進 repo；`wrangler.toml` 只有名稱和 KV 綁定的名稱。
- [ ] PR 描述第一行寫「會改變試玩版本」；附使用者的部署步驟。CI 依 head SHA 列出全部 run。

## 限制

- 公開 repo：不放金鑰、個資或真實姓名。
- 部署到使用者的 Cloudflare，由使用者本人執行（對外的寫入）。session 不替使用者登入，也不碰他的金鑰。
- 本機只跑相關測試，重工作用 `systemd-run --user --scope -q -p MemoryMax=1500M -p MemorySwapMax=0` 包起來。
- 合併時機由 ceo 決定。
- 使用者指示（2026-10-03）：
  - 你自己 terminal 每個回合的結尾文字一行就好。
  - 給 ceo 的訊息只在三種時候傳：計畫要核准、PR 好了、需要決定的事。

## 回報方式

1. 先回一段簡短的計畫（儲存方式、Worker 的介面、怎麼分辨別人的紀錄），接著直接開始。
2. 可以排在第六輪的 PR 之後做。
