主旨：war-game-ai 讓電腦在隨機地圖上自己偵察：開局只知道自己家附近，要派兵找城鎮、資源和敵方主城，然後照找到的打。做完以後拿掉「電腦暫時知道整張地圖」那一段，隨機地圖才能開放給使用者玩。依據是 D-074，以及 core 的隨機地圖 PR #172。

## 目標

- 隨機地圖上，普通和困難都不偷看，只靠自己看到、記得的東西玩。
- 困難在隨機地圖上照樣強；普通照樣能讓使用者練習。
- D-072（困難不輸給偷家）在隨機地圖上也成立：哨兵和回家救援不寫死座標。

## 依據

- D-074：
  - 使用者選「什麼都要探（像世紀帝國）」，電腦照同一條規則。
  - 地圖 129×129，出生在對角或相鄰的角落，城鎮 7 座。
  - 固定地圖保留，照現在的玩法。
- core 的 PR #172（main e78e742）：
  - `view.ts` 的 `mapInfo(map, p)`：偵察後電腦該拿的開局資料。隨機地圖只有自己的主城，`towns` 是空的，`terrain` 全是空地。
  - 城鎮從 `view.towns` 來，探到才有。位置看 `TownField.cellX`、`cellY`、`size`（`TOWN_STRIDE` 14）。
  - 資源點從 `view.nodes` 來；岩石從 `view.placement` 的 Blocked 來，隨機地圖只標探過的格子。
  - `spawns` 要用 `player` 找，不能用陣列位置當玩家編號。
  - 偶數大小的建築（主城 4×4、箭樓 2×2）的中心格，要用 `frame.ts` 的 `footprintCentre`、`spawnCentre` 在標準座標裡算。直接用 `spawns` 的 cellX、cellY，在左右翻或斜翻的地圖上會差一格。
  - 要拿掉的暫時那段：`runner.ts` 建 `know` 的地方（註解寫著 TEMPORARY）。
  - `worker.ts` 擋住「有人類玩家的隨機地圖」，拿掉暫時那段的同時一起開放。
  - core 的腳本玩家已經有最簡單的偵察：沿邊緣繞去另外三個角落和中央，40 局裡 37–39 局找到電腦主城。可以參考。
- 隨機地圖上電腦暫時知道整張地圖時，電腦對電腦平手 44%（只當參考）。原因是對角出生時兩座主城相距約 134 格，固定地圖是 88 格，電腦是照固定地圖調的。
- D-072 的進度：分支 ai/defend-home，哨兵和回家救援已經寫好，預設關。

## 範圍（`sim/src/ai/`、`sim/test/ai.test.ts`；`runner.ts`、`worker.ts` 是 core 的路徑，ceo 已經請 core 同意由你在同一個 PR 裡改那兩段，core 會審那兩段）

1. **偵察**（普通、困難都要）：
   - 開局派兵或村民去找城鎮、敵方主城和資源。派誰、什麼時候派、走哪裡，你定。
   - 城鎮、敵方主城只從看到、記得的資料來。
   - 簡單、普通盡量簡單；困難可以更聰明。
2. **照找到的打**：
   - 挑城鎮、打主城、守家，都改成用記得的位置。
   - 地圖變大以後的時間點，例如出發的兵數、什麼時候打主城，在隨機地圖上重新量。
3. **D-072**：哨兵和回家救援改成不寫死座標，從看到、記得的地形和路線算。
   - 在固定地圖和隨機地圖上都量。偷家組是固定地圖的。
4. **拿掉暫時那段**：
   - `runner.ts` 改用 `mapInfo(map, p)`。
   - `worker.ts` 開放有人類玩家的隨機地圖。
5. 固定地圖：電腦拿到的資料和現在一樣，所以普通、簡單在固定地圖上要逐局和 main 相同。困難如果因為 D-072 改了，要列出差別。

### 量測

- **固定地圖**：
  - 100 局門檻照舊：普通對普通出生點 35–65%、平手 ≤ 25%、重播 0；普通對簡單 ≥ 80%；簡單第一次打野城不早於第 18 分；困難對普通分出勝負的局困難至少贏 65%、平手 ≤ 25%；困難對困難出生點 35–65%、平手 ≤ 25%。
  - 腳本玩家主動組，對普通、對困難各 40 局，和 main 並列；偷家組改前改後。
- **隨機地圖**（電腦只靠偵察）：
  - 同樣四種對局各 100 局，對角、相鄰分開列。
  - 門檻和固定地圖一樣。平手如果因為地圖大而過不了，帶數字回報 ceo，不要硬調。
  - 腳本玩家主動組和偵察組，對普通、對困難。
  - 電腦第一次找到敵方主城、第一次拿下城鎮是第幾分。
- 思考時間：中位數、p95、p99、最大值。偵察和尋路不能讓手機變慢。

### 不做

- 地圖產生器、協定、腳本玩家、CI workflow：war-game-core。需要新欄位就回報 ceo。
- 開局畫面的地圖選項：war-game-client。等這個 PR 合併後才上線。

## 限制

- 確定性規則照 `AGENTS.md`。
- 公開 repo：不放金鑰、個資或真實姓名。
- 本機只跑相關的單元測試和小型量測，完整對局最多 5 局。大量對局用 CI 的 `ai/scratch-*` 分支。
  - 本機要跑時，available 低於 2000 MB 就等，並用 `systemd-run --user --scope -q -p MemoryMax=1500M -p MemorySwapMax=0` 包起來。
- 要 rebase 疊著的分支時，不強制推送，改推新分支、開新 PR（使用者 2026-10-07）。
- PR 會改變試玩版本，描述第一行寫「會改變試玩版本」。合併時機由 ceo 決定。
- 可以分成兩個 PR：先偵察和拿掉暫時那段，再 D-072。先後你提。
- 使用者指示（2026-10-03）：你自己 terminal 每個回合的結尾文字一行就好；給 ceo 的訊息只在三種時候傳：計畫要核准、PR 好了、需要決定的事。

## 回報方式

1. 先回計畫：偵察的做法、PR 怎麼分、預期的風險（例如地圖大、平手變多）。核准後開始。
2. PR 好了回報連結、CI 結果和量測表。
