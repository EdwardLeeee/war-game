## 範圍

### 要改（`client/`）

1. **#83 現在轉 ready**。使用者已經給了第三輪的回饋，我審完就合併。
2. **開局提示**（一個 PR，不用等 core）
   - 每一局開始時提示一次：魔晶來自城鎮；離主城最近的城鎮在哪裡；打倒民兵之後可以搶或治理。
   - 小地圖上離自己主城最近的那座城鎮閃幾下，或用你覺得更清楚的方式標出來。
   - 最近的城鎮用 `map.towns` 和自己的出生點算，不要寫死編號。core 的 PR A 合併後，它會自動變成家附近那一座。
   - 文字和呈現方式由你決定。原型的介面是臨時版，不用等設計稿。
3. **地圖多了城鎮之後測試不要壞**（和第 2 項同一個 PR）
   - 檢查用真模擬跑的 e2e（main-flow 等）和單元測試，有沒有假設「只有兩座城鎮」或寫死城鎮的編號、位置。有的話改成不依賴這些。
   - core 的 PR A 上 Client 的 run 如果失敗，我會把失敗的測試轉給你。
4. **散開的說明**（core 的 PR B 合併後，我會通知）
   - `FORMATION_TEXT` 的散開改成新規則的意思：遠程兵和法師行軍、交戰時也保持間隔；近戰兵打起來還是會擠到目標旁邊。確切的規則以 core 的 PR B 為準。
   - 法師開砲現形、待命的兵反擊：畫面不用改，快照本來就會多出看得到的法師（D-037）。姿態按鈕上「積極」的說明要不要加一句，等 core 的 PR B 定案後我再告訴你。

### 不做

- 規則和地圖：war-game-core 負責。
- 選兵、框選的改善：使用者這次用 iPhone 玩，沒有提操作的問題。等他提了再排。
- 正式介面：R6。

## 驗收條件

- [ ] 開局提示每局出現一次；重來、繼續這局的行為寫在 PR 描述裡。
- [ ] 單元測試：最近的城鎮怎麼算（多座城鎮、距離一樣時挑編號小的）。
- [ ] e2e：開局看得到提示；測試不依賴城鎮的數量和編號。
- [ ] 沒有動到 `sim/`。CI 依 head SHA 列出全部 run，包括失敗和取消的。
- [ ] PR 描述第一行寫「會改變試玩版本」，並附給使用者的實機步驟。

## 限制

- 公開 repo：不放金鑰、個資或真實姓名。
- 本機只跑相關的測試，重工作用 `systemd-run --user --scope -q -p MemoryMax=1500M -p MemorySwapMax=0` 包起來，available 低於 2000 MB 就等。完整的 e2e 交給 CI。
- 每個 PR 都會改變試玩版本，合併時機由 ceo 決定。
