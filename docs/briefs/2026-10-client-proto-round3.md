主旨：war-game-client 做原型第三輪的操作改動：姿態按鈕寫出說明、攻下城鎮可以留守、編隊自動補兵、散開隊形的按鈕。依據是使用者第二次試玩的回饋（D-026、D-027）。

> 2026-10-01 更新（D-027）：使用者說「而且先不用開發別的難度的ai」，原本的第 4 項「難度三種」取消，換成「隊形按鈕」。

## 目標

- 使用者看得懂積極和堅守差在哪裡。
- 攻下城鎮後，用按鈕決定留幾名兵，而且不會被「全軍」帶走。
- 編隊有人陣亡後，新訓練的兵會自己補進去。
- 使用者可以把部隊切成散開隊形，不會被一發晶砲炸到一整團。

## 範圍

### 要改（`client/`）

1. **姿態按鈕寫出說明**
   - 按鈕要讓人一眼看出現在是哪一種、按了會變成哪一種，並寫出這一種的意思：
     - 積極：6 格內有敵人就追上去打，追到離原位 8 格就回來。
     - 堅守：站在原地不動，只打走進射程的敵人。
   - 也要讓人知道：姿態只影響沒有指令、站著待命的部隊。
   - 文字怎麼排由你決定，意思要和 GDD 第 9 節一致。
2. **攻下城鎮可以留守**（GDD 第 5 節）
   - 「搶或治理」的對話框和城鎮的選取資訊，都有「留守 [−] N [+] 名」。
   - 選治理時，N 預設是最少駐軍數；選搶時預設 0。
   - 挑哪幾名：城鎮範圍內自己的兵，離城鎮中心最近的先挑；距離一樣挑編號小的；法師排在最後。
   - 被挑中的兵：
     - 送 `stance` 指令改成堅守。
     - 記成這座城鎮的留守。
     - 不算在「全軍」裡。
     - 從原本的編隊移出。
   - 城鎮的選取資訊顯示留守幾名，可以用 −／+ 增減。
     - 加一名：挑城鎮範圍內還沒留守的兵。沒有的話，提示「城鎮裡沒有其他的兵可以留守」。
     - 減一名：那名兵不再留守，姿態改回積極。
   - 玩家親手給留守的兵下前進、攻擊或撤退指令，他就不再留守。
   - 留守的兵陣亡，就從名單移除。這一輪不自動補留守。
   - 這些都用現有的指令做，不需要 core 改規則。
3. **編隊自動補兵**（GDD 第 10 節）
   - 存編隊時，記住每種兵各有幾名。按鈕顯示「現有／原本」，例如 `1·12/14`。
   - 收到 `unit_trained`，而且是自己的槍兵、遠程或法師時：
     - 找開著自動補兵、而且缺這種兵的編隊。缺最多的優先，一樣多就挑編號小的。
     - 把新兵加進那個編隊。
     - 新兵先在集結點等。同一個編隊的新兵湊滿 3 名，或第一名已經等了 20 秒（遊戲時間），就一起下前進指令，走到編隊現在的中心。
     - 還沒走到之前，如果編隊移動了，每隔一段時間重下一次前進指令。走到 6 格內就不再管。
     - 玩家親手給新兵下指令，就不再替他下指令。他仍然留在編隊裡。
   - 沒有編隊缺這種兵時，新兵照舊留在集結點。
   - 每個編隊可以開關自動補兵，預設開。開關放在哪裡由你決定。
   - 重新存編隊，或編隊的兵被移去留守時，「原本」的人數怎麼算，請在計畫裡提出。
     - ceo 的想法：重新存就重新記；移去留守不改「原本」的人數，所以會補回來。
4. **隊形按鈕**（GDD 第 9 節，D-027）
   - 要等 core 的介面 PR 合併：新的指令（暫定 `formation`，帶 `u` 和 `loose`）和單位旗標（暫定 `UnitFlag.Loose`），名稱以 core 的 PR 為準。
   - 指令區多一顆「隊形：密集／散開」，做法和姿態鈕一樣。只對士兵有效；混選時顯示「混合」，按一下全部改成散開。
   - 按下去部隊會在原地重新排好（core 的規則，D-028），所以按鈕不用另外下移動指令。
   - 選取資訊寫出意思：
     - 密集：站位間隔 1 格，火力集中。
     - 散開：站位間隔 2 格，站好時一發晶砲只炸得到 1 名；隊伍比較寬，過窄路比較慢。近戰兵打起來還是會擠在一起。
   - 編隊自動補兵時，新兵跟著編隊的隊形：編隊裡超過一半是散開，就替新兵送一次散開的指令。
5. **自動施放預設開**
   - core 會讓新訓練的法師預設開著自動施放。畫面不用改邏輯，但 e2e 和文字如果假設「預設關」，要跟著改。
6. **測試與對照表**
   - 單元測試：留守怎麼挑人、全軍排除留守、編隊補兵挑哪個編隊、湊 3 名或 20 秒才出發。
   - e2e 的主要流程加這幾步：改姿態、治理並留守、編隊缺人後新兵補進來、切成散開隊形後前進（走到後彼此相隔約 2 格）。
   - PR 描述裡的手勢對照表，補上 GDD 第 10 節的新列。

### 不做

- 規則（兵種平衡、自動施放的預設、隊形的間隔）：war-game-core 負責。
- 新的難度：不做（D-027）。開局畫面維持簡單、普通兩種。
- 正式介面：R6 由 war-game-ui 出設計稿。這一輪都是原型介面，不用等設計稿。
- 騎兵、城牆、分城。

## 驗收條件

- [ ] 上面第 1–5 項都做到，並有對應的測試。
- [ ] 按「全軍」不會選到留守的兵；治理並留守後，城鎮不會因為按了全軍再前進而叛離（e2e 或單元測試）。
- [ ] 編隊存 10 名槍兵、陣亡 3 名後，接下來訓練出的 3 名槍兵會進到這個編隊，按鈕回到 10/10。
- [ ] 沒有動到 `sim/`。
- [ ] CI：check、WebKit、Chromium 全綠。回報時依 head SHA 列出全部 run，包括失敗和取消的。
- [ ] PR 描述附給使用者的實機步驟：在哪裡、做什麼、會看到什麼。

## 限制

- 公開 repo：不放金鑰、個資或真實姓名。
- 本機只跑相關的測試，重工作用 `systemd-run --user --scope -q -p MemoryMax=1500M -p MemorySwapMax=0` 包起來，available 低於 2000 MB 就等。完整的 e2e 交給 CI。
- 每個 PR 都會改變試玩版本。PR 描述第一行寫「會改變試玩版本」，合併時機由 ceo 決定。

## 回報方式

1. 先回一段簡短的計畫給 ceo，接著直接開始做。需要使用者決定的事才先問。
2. 第 1–3 項不用等 core，可以先做、先開 PR。第 4、5 項等 core 的介面 PR 和規則 PR 合併後再接。
   - client 的計畫已核准（2026-10-01）：PR A 是姿態和留守，PR B 是編隊自動補兵，PR C 是隊形按鈕和自動施放的測試調整。
3. 每個 PR 回報連結和 CI 結果。
