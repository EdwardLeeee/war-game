主旨：war-game-ai 做「困難」難度：電腦靠更好的決策變強，不給資源加成；普通維持現在的樣子。依據是使用者 2026-10-03 的選擇（D-052）。

## 目標

- 開局畫面可以選「困難」。使用者打得贏普通之後，有一個更難、但照樣打得贏的對手。
- 困難的電腦看起來更聰明（例如集中打法師、躲晶砲、看時機進攻），不是因為資源比較多。
- 普通的每一局和現在一模一樣。

## 依據

- 使用者原話（2026-10-03，線上版本 7826402）：「我已經有打贏過電腦了，所以你可以讓電腦進化了」。用選擇欄位選了「加一個『困難』」和「開 war-game-ai」（`docs/decisions/log.md` 的 D-052）。
- GDD 第 13 節：「困難靠更好的決策，不靠作弊。如果之後要加有資源加成的難度，會寫在這裡並標明。」
- 現在的電腦：`sim/src/ai/ai.ts`。
  - 難度表 `LEVELS`：`easy`、`normal`。檔頭的註解寫了電腦每次思考做哪些事。
  - 加簡單難度時的做法：兩種難度抽一樣的亂數，所以 normal 的每一局和加之前一樣。請照這個做法加 hard。
- 已知的弱點和線索（可以從這裡開始，不限於這些）：
  - 法術營常常蓋不出來：一次只蓋一棟、民居優先、木頭被遠程兵用掉（D-045，`sim/README.md` 的已知限制）。
  - 經濟分配的比例：war-game-core 量到「電腦比例跟著庫存調得慢一點，普通反而變強很多」（main 上把比例固定在開局值：腳本玩家主動 39→19、守家 26→8；D-050 的 PR #105 描述）。
  - 晶脈：普通派 2 名農民，條件是有法術營。
  - 打法師：晶砲是範圍傷害；現在的電腦不會集中打對方的法師，也不會散開躲晶砲（散開的規則在還沒合併的 #91）。
- 量測工具：`sim/src/scripted-games.ts`（腳本玩家對電腦，`sim/README.md` 有用法），以及 `sim/src/tournament.ts`（電腦對電腦）。
- 操作改善輪（D-050）剛上線：經濟分配會移現有農民、同一指令的兵整隊一起打。請在最新的 main 上做。

## 使用者 2026-10-04 的補充（D-055）

- 原話：「我覺得你在做ai的時候不用預設打法吧，你想辦法弄的超強讓我打就對了，但是你不能開掛aka有預知眼」
- 所以：
  - 目標是越強越好，不用照固定的建造順序或性格寫死。可以用電腦對電腦的大量對局去搜參數或打法（例如讓候選互打、留下贏的），也可以依偵察到的情況改變打法。
  - 不能開掛：只看自己的 `PlayerView`，迷霧外的東西看不到、猜不到；不給資源、人口或數值加成。`test/boundaries.test.ts` 照樣管。
  - 手機上要跑得動：電腦思考的時間要量，列在 PR 描述。

## 範圍

### 要改

1. `sim/src/ai/ai.ts`：加 hard。
   - 做法由你決定，可以加新的決策，也可以只是不同的參數；只要不給資源、不看迷霧外的東西。
   - normal 和 easy 的每一局都不能變。
2. `sim/src/protocol.ts` 的 `AI_DIFFICULTIES` 加 `"hard"`。
   - 協定屬於 core，這一行例外放在你的 PR 裡；core 知道。
   - 其他協定的改動照規則回報 ceo，由 core 加。
3. `sim/test/ai.test.ts`：hard 的行為各有測試，拿掉改動時要失敗。

### 不做

- 開局畫面的「困難」按鈕：war-game-client 在你的 PR 合併後做。
- 遊戲規則、地圖、腳本玩家量測工具、CI workflow：屬於 war-game-core。需要在 CI 加量測，回報 ceo。
- 正在進行的前期平衡（主城產魔晶、剋法師的規則，D-051）由 core 做。其中電腦的部分（例如看到 2 名以上法師就散開）會改到 `ai.ts`，到時 ceo 會協調由誰改。

## 驗收條件

- [ ] normal 對 normal、normal 對 easy 各 100 局，每一局的最後雜湊和改之前相同。
- [ ] hard 對 normal 100 局（出生點對調各一半）：
  - hard 在分出勝負的局裡至少贏 65%。
  - 平手不超過 25%。
  - 重播 0 失敗。
- [ ] hard 對 hard 100 局：出生點勝率 35–65%、平手不超過 25%。
- [ ] 腳本玩家五組（主動、守家、守家散開、守家經濟養大散開、不拿城鎮，各 40 局）對 hard 的結果，和對 normal 並列。
  - 只回報，不設下限：使用者 2026-10-04 說要「弄的超強讓我打就對了」（D-055），困難不用保證打得贏。
- [ ] hard 對不動的玩家的時間軸（`sim/src/ai-timeline.ts`，種子 1–5）：第一次打野城、第一次打主城、帶幾名法師。
- [ ] perf：hard 每 tick 的時間不能明顯比 normal 多。電腦每 10 tick 才思考一次，請列出思考的時間。
- [ ] `sim/README.md` 寫 hard 做了什麼。GDD 第 13 節由 ceo 依你的 PR 描述更新。
- [ ] 回報 CI 時依 head SHA 列出全部 run。

## 限制

- 公開 repo：不放金鑰、個資或真實姓名。
- 確定性規則照 `AGENTS.md`：整數或定點數、不用 `Math.random`、迭代順序固定。電腦只能看自己的 `PlayerView`。
- 本機只跑相關的單元測試和小型量測，完整對局最多 5 局。
  - `free -m` 的 available 低於 2000 MB 就等。
  - 用 `systemd-run --user --scope -q -p MemoryMax=1500M -p MemorySwapMax=0` 包起來跑。
  - 大量對局用 CI：腳本玩家只在 pull_request 和推到 `core/scratch-*` 的 run 跑。ceo 會請 core 加上 `ai/scratch-*`，加好之前可以先開草稿 PR 來跑。
- PR 會改變試玩版本：描述第一行寫「會改變試玩版本」。合併時機由 ceo 決定。
- 使用者指示（2026-10-03）：
  - 你自己 terminal 每個回合的結尾文字一行就好。
  - 給 ceo 的訊息只在三種時候傳：計畫要核准、PR 好了、需要決定的事。

## 回報方式

1. 先回一段簡短的計畫：你打算讓 hard 在哪幾件事上比 normal 聰明、怎麼保證 normal 不變、預期的風險。接著直接開始。
2. PR 好了回報連結、CI 結果和上面的表。
