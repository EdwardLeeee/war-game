## 每個 tick 的順序

0. AI 思考：每位 AI 每 10 tick 一次，兩位錯開 5 tick，讀的是上一個 tick 結束時的 PlayerView。
1. 套用這個 tick 的指令，依佇列順序。被拒的也記進紀錄。
2. 自動派工（每 20 tick）：閒置農民去修附近受損的建築、照經濟分配去採集，回城中則去躲。
3. 決策：找目標、姿態、依指令決定速度。有工作的農民由經濟決定：去哪、到了沒。校準中的法師站著不動；開著自動施放的法師找落點。
4. 移動：分離力、沿牆滑動。
5. 攻擊：剋制加成、主城與箭樓射箭、晶砲校準與發射；傷害先加總，再一次扣，防護罩先吸收；罩的回復。接著是農民的工作：採集、交貨、蓋、修、躲進建築。
6. 死亡：主城倒下就判勝負；建築倒下時，躲在裡面的農民出來；法師陣亡時擊殺方拿到魔晶。
7. 訓練：隊首進度加 1，滿了而且人口有空位就出生。
8. 城鎮：依 id 順序判斷攻下、搶、修繕、產出、叛離、廢墟。
9. tick 加 1；每 5 tick 更新一次戰爭迷霧。
10. 時間到（36,000 tick）判平手。每 100 tick 算一次雜湊。

每一段都依 id 順序處理，移動和攻擊讀的是 tick 開始時的狀態。尋路場每 tick 最多重算 4 張，由 id 小的單位先拿到；這會影響誰先走新路線，但順序固定，所以結果仍然一樣。

## 確定性

- 沿用引擎 spike 驗證過的做法：1 格 = 1024 定點、每秒 20 tick、xorshift32、依 ID 迭代、flow field、FNV-1a 雜湊、JSONL 重播。
- 雜湊涵蓋全部狀態：
  - 資源、地圖格、資源點、城鎮、單位表和建築表的每一欄。
  - 每位玩家的迷霧、探索與記憶。
  - 還沒到 tick 的指令不算狀態，因為重播時會一次全部排進佇列。

**對雙方公平的平手規則**（`src/frame.ts`）：
- 每位玩家都有一個「地圖對稱變換」，把它那一側的地圖對到玩家 0 那一側，也就是「標準座標系」。
  - 原型的 1 對 1 地圖沿 x↔y 鏡射，所以玩家 0 用恆等、玩家 1 用鏡射。
  - 之後的 4 方地圖只要換成旋轉。
- 會影響方向或位置的平手，一律先轉到標準座標系再比。這樣鏡像的局面會走出鏡像的結果：
  - flow field 的方向平手：標準座標系裡方向編號最小的。
  - 沿牆滑動：先試速度分量較大的那一軸；一樣大時，先試標準座標系的 x 軸。
  - 隊形的左右：鏡射會對調左右，所以左邊是標準座標系裡的左邊。
  - 兩名單位站在同一點：沿標準座標系的 x 軸分開。
  - 經濟選資源點：距離、離自己出生點的距離都一樣時，取標準座標系裡的順序。
  - AI 的所有位置選擇（蓋在哪、去哪個資源點、集結點）都在標準座標系裡做。
- 其他平手：
  - 目標格被擋住時，最近可走格的平手選離下指令玩家出生點較近的那格。
  - 16 方向的判斷在鏡射下完全對稱。
  - 尋路場每 tick 的重算額度是每位玩家（和中立）各 2 張，id 小的一方不會先用光。
  - 一樣近的目標：依時間和挑選者的 id，輪流選 id 小的或大的。id 是依建立順序給的，總是選小的，中立民兵和箭樓就會一直先打先建兵的玩家。
- 還留下的差異是雜訊，不是固定偏向某一邊：單位依 id 錯開找目標的時間、兩位 AI 錯開 5 tick 思考。
- 公平與否由 100 場 AI 對打的勝率門檻把關。

## 簡單 AI（`src/ai/ai.ts`）

- **看得到什麼**：只讀自己的 PlayerView，加上開局雙方都知道的資料（出生點、城鎮位置、規則表），以及自己的對稱變換。
  - 下的指令和玩家一樣，會寫進紀錄；重播時不需要 AI。
- **節奏**：每 10 tick 思考一次，雙方在同一個 tick 思考。
- **亂數**：由遊戲種子和「位置」推導。對打工具交換兩位 AI 的位置，就能讓同一對 AI 從兩個出生點各打一次。
- **性格**（GDD 第 13 節）：掠奪型、治理型、均衡型。一般對局依種子隨機選；只影響搶或治理的傾向，其他判斷相同。
- **做什麼**：
  - 經濟：經濟分配一直開著，依庫存微調比例；農民訓練到目標人數。建造一次只蓋一棟：民居優先，接著伐木場、糧倉、兵營、射場、法術營、農田、礦場；糧加木多的時候加蓋兵營和射場。
  - 軍隊：兵營、射場、法術營保持在訓練；法師打開自動施放；有法術營後派 2 名農民去晶脈（簡單難度不派，見下面的難度）。
  - 防守：敵軍接近主城時，整支軍隊回防；敵人比家裡的兵多時，全體回城。
  - 城鎮：軍隊夠大就去打城鎮。攻下的那個 tick 依局勢選搶或治理：付不付得起、有沒有多餘的兵留守、附近有沒有敵軍、還剩多少時間，再加一點亂數和性格。治理的城鎮會留駐軍。搶完、城鎮變成廢墟後，軍隊就離開，重新判斷下一步（以前會一直等在廢墟，見下面的平手說明）。
  - 防漏洞：搶過的城鎮，下次更傾向治理；自己剛搶過的城鎮，6 分鐘內不當作目標。
  - 進攻：兵夠多，或城鎮都拿下了，就進攻敵方主城。
    - **有時間上限的對局**（電腦對電腦），從上限往回算：
      - 剩 10 分鐘起，需要的兵數每分鐘少 3。
      - 剩 8 分鐘起不再出發打城鎮，在集結點集合，有 15 名就總攻；剩 6 分鐘起有 8 名就出發。
      - 最後 4 分鐘駐軍也一起去，全力進攻、不撤退，也不再回去把搶做完。
      - 總攻期間新訓練的兵也加入攻擊。
      - 30 分鐘的對局，就是第 20、22、24、26 分鐘。
    - **沒有時間上限的對局**（有人類玩家，D-024）：以上都不用，不會在某個時間派一小隊兵出去。另外，人口到了規則上限（120 名中剩 2 名以內）、兵不能再多時，兵數到「打城鎮的門檻＋6」就出發。
    - **怎麼打**：出發的兵還沒走到敵方主城 12 格內時，成群前進（等最慢的、排隊形）；到了以後，主城附近有守兵就用前進指令邊走邊打，先打守兵，沒有守兵才下「攻擊主城」。
    - **撤退**：出發時的兵剩不到四成就撤（後來補上的兵不算）。攻主城撤退過以後，下一次要等兵數到正式的打主城門檻才出發，不再用「城鎮都拿下了，打城鎮門檻＋6」這條捷徑。
  - 不放棄快倒的主城：看得到的敵方主城血量 ≤40% 時，攻主城的軍隊不撤退（兵力剩不到四成或被較多敵軍圍住都一樣）。
  - 兵力評估（只用看得到的敵軍）：記住最近 2 分鐘同時看到的最多敵軍，自己至少多 30% 才出兵；行軍途中如果 12 格內的敵軍比自己多，就用撤退指令脫離、回集結點。最後 4 分鐘不撤退，全力進攻。
  - 所有位置選擇都在標準座標系裡做（`src/frame.ts`）。
- **難度**（`LEVELS`，GDD 第 13 節）：`"normal"` 是第一次試玩的電腦；`"easy"` 只限制自己，不給普通任何加成，數值見下面「原型第二輪補的數值」。兩種難度抽的亂數次數一樣，所以普通的對局和以前完全相同。
- **驗收**（CI 的 `ai-vs-ai`、`ai-summary`）：
  - 100 場 = 50 個種子 × 交換出生點，9 種性格組合輪流出現。
  - 每場都重播比對雜湊。
  - 兩個出生點的勝率要在 35–65%（平手不算進分母），平手要 ≤10%（D5）。
  - 另外 100 場普通對簡單（`ai-vs-easy`，同樣的種子、性格與出生點交換，每個出生點各當一半的簡單）：分出勝負的局裡普通至少贏 80%，平手 ≤25%，重播 0 失敗。
  - **平手暫時放寬到 ≤25%**（ceo 2026-09-30）：出生點勝率、重播、瀏覽器確定性都通過。第八輪查出平手的主因是 AI 的問題：平手局最後兵多的一方（中位數 64 名，對方 4–7 名）多半停在搶完的廢墟，一直到時間結束，因為廢墟不屬於任何人，AI 就一直等它變回中立。第九輪修正後平手仍是 21%，但已經沒有軍隊停在廢墟；21 局裡有 13 局是最後 4 分鐘攻到敵方主城（6–16 名兵）卻沒在時間內打下；這些主城裡多半躲著 8–15 名農民，躲著的農民會讓主城多射箭（有上限）。另外 8 局最後 4 分鐘沒有攻到主城。下一步怎麼回到 ≤10% 由 ceo 決定。

## 本機執行

```bash
cd sim
npm ci
npm run typecheck
npm test
node src/headless.ts --scenario skirmish --script demo --ticks 3000 --out /tmp/sk
node src/headless.ts --replay /tmp/sk/commands.jsonl --ticks 3000 --out /tmp/sk-replay   # 雜湊應該相同
node src/headless.ts --scenario standard --script eco --ticks 6000 --out /tmp/eco          # 雙方經濟腳本
node src/balance.ts                    # 兵種平衡量測（Markdown，約 5 秒）；--check 1,2,3,4 時目標沒成立就 exit 1
```

在這台開發機上，重工作一律用 `systemd-run --user --scope -q -p MemoryMax=1500M -p MemorySwapMax=0` 包起來。完整對局、100 場 AI 對打和瀏覽器測試交給 CI（`.github/workflows/sim.yml`）。
