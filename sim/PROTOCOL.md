# 模擬與畫面之間的介面（PROTOCOL_VERSION 1）

`sim/`（war-game-core）和 `client/`（war-game-client）之間的契約。型別、列舉、欄位順序都在
`sim/src/protocol.ts`，client 直接 import，所以兩邊對不上時編譯就會失敗。這份文件用白話說明每一項。

## 0. 規則

- **版本**：`PROTOCOL_VERSION`。只要 client 需要跟著改，就遞增版本。
- **改格式的流程**：core 通知 war-game-ceo，由 ceo 轉給 war-game-client。client 有需求也先回報 ceo。
- **所有權**：`sim/src/protocol.ts`、`sim/PROTOCOL.md`、`sim/src/worker.ts`、`sim/src/placement.ts` 都屬於 war-game-core。
- **分階段填值**：原型的所有欄位、事件和指令，這一版都已經定義好了。
  - 標「PR-n 起」的欄位，在那個 PR 之前是 0 或 -1，指令會被拒絕（原因碼 `NotAvailable`）。
  - 補上這些值不算改格式。
- **第七輪（D-061）的規則有開關**：`rules.features` 說哪些開著（3.3 節）。關著的指令會被拒絕（`NotAvailable`），畫面和電腦就不要顯示或使用；開關打開不算改格式。
- **怎麼用 sim**：
  - `sim/` 是獨立的套件，沒有建置步驟。
  - client 用相對路徑或 Vite alias 匯入 `sim/src/protocol.ts` 和 `sim/src/placement.ts`，再用
    `new Worker(new URL("<到 sim/src/worker.ts 的路徑>", import.meta.url), { type: "module" })` 開模擬。
  - Vite 需要的 `server.fs.allow` 由 client 在自己的設定裡處理。

## 1. 時間與座標

| 名稱 | 值 | 說明 |
|---|---|---|
| `TICKS_PER_SECOND` | 20 | 模擬每秒 20 步 |
| `CELL` | 1024 | 1 格 = 1024 定點單位。快照裡的位置 `x`、`y` 都是定點 |
| `CELL_SHIFT` | 10 | 格子 = 定點 >> 10 |
| `DIRECTIONS` | 16 | 朝向 k × 22.5°，0 = 東（+x），y 向下，所以順時針 |
| `HASH_EVERY` | 100 | 每 100 tick（含 tick 0）發一次狀態雜湊 |
| `FOG_EVERY` | 5 | 每 5 tick 重算並送出一次戰爭迷霧 |
| `MAX_TICKS` | 36,000 | 電腦對電腦、確定性檢查、headless 的時間上限（30 分鐘）：到了還沒分出勝負就是平手。每局的上限在開局時決定（`init` 和紀錄第一行的 `maxTicks`），0 = 沒有上限，是有人類玩家時的預設（第二輪起，D-024） |
| `STEP_BATCH` | 20 | 表頭附上最近 20 tick 的模擬時間總和 |

- **格子座標**：`cellX = x >> 10`。格子中心的定點值是 `cellX * 1024 + 512`。
- **格子編號**：`y * size + x`，也就是一列一列排。

玩家：
- 0 和 1 是對戰的兩方。
- `NEUTRAL = 2` 是城鎮的民兵與箭樓。
- `NO_OWNER = -1` 是「沒有人」。

## 2. 開局的靜態資料（`ready` 訊息）

- `map: MapInfo`
  - `mode`（D-074）：`"fixed"` 固定地圖、`"random"` 隨機地圖；模擬一定會送，型別上選填，沒有就當成固定地圖。下面先說固定地圖，隨機地圖見本節最後。
  - `size`：96。
  - `terrain`：`size * size` 個 `Terrain`（R6-51 起見 3.6）：
    - 0 空地（`Open`）、1 岩石（`Blocked`，石堆和岩脊）、2 城牆（`Wall`，D-089，見 3.5）。
    - 3 水（`Water`，河、湖）、4 淺灘（`Ford`）、5 南北向的橋（`BridgeNS`）、6 東西向的橋（`BridgeEW`）、7 懸崖（`Cliff`）。
    - 可以走：0、4、5、6（`walkableTerrain()`）；不能走：1、2、3、7。
    - 樹不算地形，是資源點；樹會擋路，砍完後變成可走。
  - `spawns`：兩個出生點。
  - `towns`：城鎮的 id、大小、中心格與 `radius`（D-089 起是城牆離中心幾格；城鎮的範圍是牆以內，見 3.5）。第六輪起 4 座（D-054）：0 中間的小鎮、1 大城、2 左上角的小鎮 (14,14)、3 右下角的小鎮 (81,81)；id 不變、新的排在後面，不要假設只有 2 座。
  - 這些都是地圖知識，雙方和 AI 一樣知道。
  - 資源點不在這裡，探索到以後才會出現在快照的 `nodes`。
- **對稱**：原型的 1 對 1 地圖沿 x↔y 鏡射（玩家 1 的出生點是玩家 0 的鏡像，城鎮和晶脈在對稱軸上）。
  - 模擬遇到跟方向或位置有關的平手時，一律先轉到玩家 0 那一側（標準座標系）再比，讓鏡像的局面走出鏡像的結果（`sim/README.md`「對雙方公平的平手規則」）。
  - 這不影響 client 要送或要畫的東西。
- **隨機地圖**（D-074，`init.map` 是 `"random"`）：每局用 `seed` 產生一張新地圖，129×129。
  - 開局只知道自己家：`terrain` 全部是可走（0），`spawns` 只有自己那一筆，`towns` 是空陣列。
    - `spawns` 請用每筆的 `player` 找，不要用陣列位置當玩家編號。
    - 敵方主城看到才知道（快照的 `buildings`）；城鎮探到才知道（快照的 `towns`，位置和大小在列裡，4.5 節）；地形探到才知道（快照的 `terrain`，4.7 節；`placement` 第 7 節）。
  - 旁觀（`human` 是 `null`）照樣拿到整張圖。
  - 大城的箭樓：相鄰出生時是 3×3，剛好擺在中線上；對角出生和固定地圖是 2×2。`ready.rules.buildings` 裡箭樓那一列照這局的地圖給，所以畫面照 `rules` 的 `size` 畫就對了。
  - 對稱：出生在對角（沿對角線鏡射）或相鄰的角落（沿中線鏡射），整張圖再隨機轉向或翻面。平手規則照樣先轉到各自的標準座標系再比。
  - 有人類玩家也可以開：電腦和人一樣只知道自己家，城鎮和敵方主城靠偵察找（D-074）。
- `rules: Rules`：兵種與建築的資料表，client 顯示花費、血量、占地、視野、射程時用這份，不要自己抄數值。
  - `units`：血量、防護罩、攻擊、射程（定點）、速度（每 tick 定點）、視野（格）、攻擊間隔（tick）、花費、訓練 tick、人口。
  - `buildings`：血量、占地邊長、能不能走過、花費、建造 tick、視野、人口上限、可以存放哪些資源、可以訓練哪些兵、全體回城時能躲幾名村民。
    - 第七輪加：`holds`（能躲幾名士兵，`garrison`）、`requires`（要先有哪些自己蓋好的建築才能蓋）。模擬一定會填；型別上選填，理由同下。
  - `multipliers`：剋制加成。`target` 是兵種或 `"shield"`；傷害 × num / den，全部整數運算。
  - `mageCap`（6）、`maxPopulation`（人口天花板不算城鎮的部分：120；D-083 的規則開著時 200）、`queueMax`（每棟建築的訓練佇列上限）。
  - 第七輪（D-061）加的，畫面和電腦都照這份，不要自己抄數值。模擬一定會送；型別上是選填，只是讓手寫的假資料（mock）照樣編得過，讀的時候給預設值（沒有就當成關著）：
    - `features`：哪些第七輪的規則開著。`plunderOnce` 城鎮只能搶一次、`towers` 可以蓋箭樓、`garrison` 遠程兵和法師可以躲進建築、`cavalry` 可以蓋馬廄、訓練騎兵。D-080 加 `outpost`：可以蓋哨所、派槍兵駐守（3.4 節）；只在開著時出現（值是 true），沒有這個欄位就是關著。
    - `arrows`：建築自己射的箭。`mainCity` 主城、`townTower` 大城的箭樓、`arrowTower` 玩家的箭樓；各有 `damage`、`range`（定點，從占地邊緣算）、`cooldown`（tick）、`extraMax`（主城每躲 1 名村民多 1 箭，最多幾箭；其他是 0）。
    - `garrisonTypes`：能用 `garrison` 躲進建築的兵種（遠程兵、法師）。
    - `garrisonCannon`：躲在建築裡的法師放晶砲時，傷害是平常的 `permille`／1000、冷卻是 `cooldownTimes` 倍。
    - `towerReach`：箭樓可以蓋在哪裡（第 7 節）。`town`（D-089 起）：持有的城鎮城牆外幾格。D-080 加 `outpost`：自己蓋好的哨所占地幾格內。
    - `outpost`（D-080）：哨所的 `slots`（最多駐守幾名槍兵）、`reach`（攻擊模式去打幾格內的敵人）、`chase`（追到幾格就回來），都是格數（3.4 節）。
    - `towns`：依 `TownSize` 排，城鎮的民兵、半徑、搶的時間與收穫、廢墟時間、治理費、修繕時間、每分鐘收入（`perMinute`，收入全額時）、人口上限、最少駐軍、叛離時間。D-089 加 `castle`（城堡的格子，見 3.5）。
    - `plunderRecovery`：搶過的城鎮再被治理時，收入從 `startPermille`（千分比）開始，治理 `ticks` 之後回到全額；`startPermille` 是 1000 表示沒有這條規則。
  - 第八輪（D-069）加的，一樣模擬一定會送、型別上選填：
    - `cannonRange`：晶砲射程（定點）。第八輪是 7 格（7168），以前是 8 格；沒有就當成 8 格。`cast` 超過它回 `OutOfRange`。
  - D-083 加的，一樣模擬一定會送、型別上選填：
    - `population`：人口天花板 = `base` ＋ 每座自己治理中的城鎮 `town[size]`（依 `TownSize`）。
      - 規則開關（`POPULATION_200`）關著：`base` 120、`town` [0, 0]，天花板就是 120，和以前一樣。
      - 開著：`base` 200、`town` [20, 40]。固定地圖全拿最多 300，隨機地圖 360。
        - 治理的城鎮給的人口上限（`towns` 的 `populationCap`）也跟著變成 20／40（關著時 5／10）。
        - 民居給的人口上限（`buildings` 裡民居的 `populationCap`）是 8（關著時 5）：主城 10＋24 間民居就到 200（使用者 2026-10-17）。
      - 現在的天花板直接看表頭的 `populationCeiling`（4.1），不用自己算。
      - 人口上限 `populationCap` = 主城、民居和治理的城鎮加起來，最多到天花板。城鎮被搶、叛離或變廢墟，天花板和上限都跟著降；已經有的單位不會消失，只是不能再訓練（`PopulationCap`）。
  - D-096（城門與城牆，3.7）加的，一樣模擬一定會送、型別上選填：
    - `features.gates`：城門會關；`features.walls`：可以上城牆。開著時才出現（值是 true），沒有就是關著。
    - `gate`：`rangedNum`／`rangedDen`（遠程兵和法師打城門只算 1/5，至少 1 點；近戰照算）、`rebuildTicks`（治理中的城鎮，城內沒有敵兵這麼久之後，打破的城門自己蓋回來：60 秒）。
    - `walls`：`range`（站在牆上射程多幾格，定點：1 格）、`takenNum`／`takenDen`（站在牆上挨遠程、法師晶彈和箭只算 3/4；晶砲照算）、`sling`（中立城鎮的民兵在牆上投石的射程，定點：4 格）。
    - `towns[size].gateHp`：每個城門的血量（小鎮 850、大城 2100）。`buildings[Gate].hp` 是大城的，畫血條請用 `gateHp`。
    - `arrows.gate`：治理中城鎮的城門射的箭；`perSoldiers` 是每幾名守軍多 1 箭（3），最多多 `extraMax` 箭（3）。
    - `gate`、`walls` 一定會送；`gateHp`、`arrows.gate` 只在城門開著時送。
  - D-097（兵種三角）：
    - `multipliers` 只剩三角：槍兵打騎兵 ×5/2、騎兵打法師和法師的護盾 ×3、遠程打槍兵 ×7/2。遠程打騎兵 ×9/5、遠程打護盾 ×3 拿掉了。騎兵打遠程沒有倍數，靠速度和血量。
    - 騎兵 60 糧 60 金、生命 150（`units`）。
    - `features.cavalryFlank`：騎兵自己挑目標時繞過前排去打後排（3.8）。開著時才出現（值是 true）。
  - D-099（攻城砲，3.9；開關 SIEGE 預設關，跟 art-v6 一起開）：
    - `features.siege`：可以蓋砲坊、訓練攻城砲。開著時才出現（值是 true）。
    - 關著時，`units` 不含攻城砲（`UnitType.Siege`，6），`buildings` 不含砲坊（`BuildingType.SiegeWorks`，14），`multipliers` 不含「騎兵打攻城砲 ×2」；陣列照舊從 0 排起，只是少了最後一項。

    - `siege`：`vsBuildings`（打建築的倍數 3；城門照 D-096 的 ×8）、`flightTicks`（砲彈飛幾個 tick：20）。一定會送。

## 3. 指令

一行一個 JSON 物件，也就是指令紀錄（JSONL）裡的一行。

- client 送 `{ type: "command", cmd }`，`cmd` 只含下面的欄位加上 `seq`（client 自己編的序號）。
- `t`（在哪個 tick 執行）和 `p`（哪位玩家）由 Worker 蓋上。
  - `t` 是「下一個還沒跑的 tick」。暫停時收到的指令，恢復後就在下一個 tick 執行。
- 指令在它的 tick 開頭套用，並驗證擁有者、花費、人口、上限。
  - 不合格就不執行，回傳事件 `rejected { seq, reason }`。
  - 被拒的指令也照樣寫進紀錄，重播時才會完全一致。

| `c` | 欄位 | 說明 | 從 |
|---|---|---|---|
| `move` | `u`、`x`、`y` | 前進到格子 (x, y)，路上遇到敵人會打（D-095 起，被 9 格內看得到的敵方單位打到也會回頭打，見下面「攻擊移動被打會還手」）。一起下指令的部隊等最慢的，抵達後近戰在前、遠程在後 | PR-2 |
| `retreat` | `u`、`x`、`y` | 撤退：不理會敵人，直接走。前期平衡起各走各的速度，不等最慢的；到了照樣排隊形 | PR-2（速度從前期平衡） |
| `attack` | `u`、`target` | 集中攻擊某個單位或建築（單位和建築共用 id） | PR-2 |
| `stop` | `u` | 停下，清掉指令 | PR-2 |
| `stance` | `u`、`stance` | `Aggressive`：會追擊附近的敵人，但不會追太遠；待命時，附近隊友在打的敵人也會去打（第三輪起，見下面「一起迎戰」）。`Hold`：原地不動，只打射程內的 | PR-2 |
| `formation` | `u`、`loose`、`face`（可省略） | 隊形：`true` 散開、`false` 密集。設定或清除這些單位的 `Loose` 旗標，並且馬上用新的間隔重排，見下面「散開隊形」。`face`（0–15，和單位的 `facing` 同一套方向）：重排後朝那個方向（D-095） | 第三輪（`face` 從 D-095） |

**路被建築完全堵住**（第二輪起，GDD 第 9 節）：`attack` 的目標、或 `move`／`retreat` 的目的地，從單位所在的地方完全走不到時（不是路變窄，而是連不起來）：
- `attack`，以及士兵的 `move`：改打擋路的敵方建築，打穿後回到原本的目標。
  - 擋路的建築：貼著單位走得到的範圍、而且比這個範圍裡任何一格都更靠近目標的敵方建築。
  - 有好幾棟時，打離目標最近的；距離一樣時，打 id 小的。
- 沒有這樣的建築時（被岩石、樹或自己的建築擋住），或是村民的 `move`、`retreat`：走到範圍裡離目標最近的格子停下，不會一直頂著牆。
  - `move`、`retreat` 到了就算完成。
  - 同一道 `move`、`attack` 一起收到的兵算一隊（操作改善輪，D-050）：隊裡有人開打，前進中或待命的隊友也一起上（12 格內，`sim/README.md`）；堅守的不加入，撤退的不打。協定不變，隊號不在畫面資料裡。
  - `attack` 會留著，路一打開就繼續打。
- 路只是變窄、還走得到時，照舊繞路。

**散開隊形**（第三輪起，D-027；使用者：「有沒有辦法讓兵分散開？不然法師一炮就帶走了」）：
- `formation` 指令設定或清除 `u` 裡自己單位的 `Loose` 旗標，任何兵種都可以。
  - `u` 裡沒有自己的單位：`NotOwner`；`loose` 不是布林值，或有 `face` 但不是 0–15 的整數：`InvalidTarget`。
- 新訓練的單位沒有這個旗標（密集）。
- 排隊形時：一起下指令的部隊裡，超過一半帶著 `Loose`，整隊就用 2 格的間隔；不然照舊 1 格。晶砲半徑 1.5 格。
- 保持間隔（第六輪，D-054；使用者：散開的兵追擊、向前進攻時還是會走在一起）：帶 `Loose` 的兵（任何兵種，村民除外）和同一隊、也帶 `Loose` 的兵互推到 2 格，不只是平常的 0.7 格；行軍、追擊、交戰、站著都一樣。同一隊是同一個 `move`、`attack` 指令一起收到的（操作改善輪的隊），撤退時是同一個隊形。和別人照舊 0.7 格。
- 按下去就用新的間隔重排。`u` 裡的兵分成下面幾種，分散在各地的兵不會被拉到同一個地方：
  - **還在路上的隊伍**（同一道 `move`、`retreat` 一起出發的兵）：目的地不變，在原本的目的地重排。這一隊裡已經走到、站著的兵也一起重排。
  - **站著的兵**（沒有指令）：彼此相距 3 格內的算同一隊，透過別人連起來的也算。每一隊在原地重排：
    - 隊伍的中心不動。
    - 朝向：近戰兵站在遠程兵和法師的哪一邊，那一邊就是前面，照各兵種現在站的位置算。整隊只有一種兵時，前面朝向敵方主城。
    - 每名兵照現在站的前後、左右分到位置，不會穿過整隊去另一頭；照兵的 id 分、走最遠的那名反而走得比較近時，就照 id 分。
    - 一隊只有 1 名：只設旗標，不移動。
  - **有 `face` 時**（D-095）：上面兩種都改朝 `face`：近戰兵在那一邊，然後遠程、法師。
    - 站著的兵：照舊在原地重排、中心不動，只是前面換成 `face`；相距 8 格內（不是 3 格）、透過別人連起來的算同一隊，追擊後散開的兵會集合成一個隊形。
    - 還在路上的隊伍：照舊在原本的目的地重排，到了朝 `face`。
    - 方向和快照的 `facing` 一樣是世界座標：0 是 x 增加的方向（東），4 是 y 增加的方向，8 西，12 北；鏡像的一方要自己換算。
  - **只設旗標、不移動**：村民、正在放晶砲的法師、正在攻擊指定目標（`attack`）的兵、剛訓練出來還在走向集結點的兵。
  - 重排就是一道前進指令：路上遇到敵人照樣會打。正在打的兵按下去，等於原地下一道前進指令。
- 只影響排隊形時站的位置。打起來之後，近戰兵照樣會擠到目標旁邊。

**開砲現形與反擊**（前期平衡起，D-057；第四輪的 D-037）：
- 法師校準晶砲期間，以及放完後 2 秒內，其他玩家看得到他所在的那一格（快照裡會有這名法師）。
- 待命、積極姿態、**沒有隊號**的玩家兵，自己 6 格內沒有敵人、也沒有隊友的戰鬥可以加入時：
  - 自己在最近 10 tick 內被打到，或 6 格內的隊友被打到，而且打人的單位看得到、離自己原位 8 格內，就去打它。
  - 有好幾個時，取離自己最近的；一樣近時取 id 小的。被主城或箭樓的箭打到不算。
- 有隊號的兵（同一個 `move`、`attack` 一起收到的，操作改善輪）照整隊的規則一起打，不吃反擊。
- 堅守姿態（包括城鎮的留守兵）、有指令的兵、村民、城鎮的民兵都不受影響。
- 「其他玩家」是除了法師自己以外的所有玩家；4 方混戰時要不要分敵我，第三階段再看。

**攻擊移動被打會還手**（D-095）：
- `move` 中、不是堅守的玩家兵，6 格內沒有敵人、也沒有隊友的戰鬥可以加入時：最近 10 tick 內被敵方單位打到，打它的單位在 9 格內、看得到，就去打它；同一隊的照整隊的規則跟上。
- 追到那個單位離自己轉身的地方超過 8 格就放棄，繼續原本的 `move`。追進 6 格內以後照一般路上遇到的敵人打。
- 主城、城鎮塔樓、箭樓的箭，躲在建築裡的兵打的，看不到的單位，都不算。放晶砲的法師會現形（上面），算看得到。
- `retreat` 照舊不打。協定不變。

**一起迎戰**（第三輪起，D-026）：
- 待命（沒有指令）、積極姿態的玩家兵，自己 6 格內沒有敵人時，會去打隊友正在打的敵人：
  - 「隊友正在打」：這個 tick 開始時，6 格內的隊友有一個敵方單位當目標，正在追或正在打。村民的目標不算。

  - 只取離自己原位（待命的位置）8 格內的敵人，和追擊上限一樣。所以隊友一個帶一個，也不會把整片兵拉離原位。
- 堅守姿態（包括城鎮的留守兵）、有指令的兵、村民、城鎮的民兵都不受影響。

### 3.1 經濟指令的細節（PR-3）

- **只有村民會做**：`gather`、`build`、`repair` 只派 `u` 裡的村民，其他兵種忽略。
  - `u` 裡沒有自己的單位：`NotOwner`。
  - 有自己的單位但沒有村民：`NotAvailable`。
- **躲在建築裡的村民**（全體回城）收到被接受的 `move`、`retreat`、`attack`、`stop`、`gather`、`build`、`repair`，會先出來再照做；被拒絕的指令和 `stance` 不會讓他們出來。
- **`gather`**：
  - 資源點要是自己看過的、還沒採完、旁邊有可走的格子，否則回 `InvalidTarget`。
  - 手上搬的資源種類不同時，會丟掉手上的。
  - 派出去的村民帶 `UnitFlag.HandPicked`（16，操作改善輪）：經濟分配不會把他移走。收到其他指令、或附近沒有同種資源可採而變閒置時解除。
- **`build`**：
  - `type` 不是 `BuildingType`：`InvalidTarget`。主城、城鎮箭樓（D-100 起是主堡 `Keep`）不能蓋：`NotAvailable`。
  - 位置不行：`BadPlacement`（第 7 節）。占地碰到城門的通道：`GateLane`（3.5、第 7 節）。占地碰到淺灘或橋：`Crossing`（3.6、第 7 節）。
  - 資源不夠：`CannotAfford`。
  - 放下時就扣錢，工地立刻擋路。站在上面的單位會被推到最近的空格。
  - 工地從 1 點血開始，蓋的時候血量和進度一起長。
  - 同一棟最多 4 名村民一起加速，速度線性相加，多的在旁邊等。
  - 蓋好後：農田由第一名村民直接耕作；伐木場、礦場的村民去採附近的木頭或金；其他建築的村民變成閒置。
  - **不帶村民**（`u` 是空陣列，第二輪起）：模擬依固定規則挑村民，所以重播結果一樣。
    - 人數依占地：2×2（民居、伐木場、礦場、糧倉）派 1 名，3×3（農田、兵營、射場、法術營）派 2 名。
    - 從自己的村民中，依離建築占地的距離由近到遠挑，距離相同依 id 小的先。
    - 不挑：玩家親手叫去待命的（見下面「待命」）、正在蓋別的建築或正在修理的、躲在建築裡的（全體回城）、正在採晶脈的（晶脈只能手動派工，挑走等於默默少了人手）。
    - 挑到的人數可以比上面少（至少 1 名）；一名都挑不到：`NoFarmer`，不放建築也不扣錢。
    - 蓋好後先回原本的工作：原本採的那處資源（資源點或自家農田）還在就回去，沒了才交給經濟分配。不會變成待命。
    - 其他檢查（`type`、位置、資源）和帶村民時一樣，先檢查這些，再挑村民。
- **`repair`**，依建築狀態：
  - `building` 不存在：`InvalidTarget`；不是自己的：`NotOwner`。
  - 沒蓋好：幫忙蓋。
  - 受損：修理，每名村民每秒 5 點，同一棟最多 4 人。
    - 主城受到攻擊後 200 tick（10 秒）內不能修理：修理的村民會在旁邊等，時間過了再繼續修。其他建築被打時照樣可以修。
    - 這段時間自己的主城在快照裡帶 `BuildingFlag.RepairLocked`（4）：主城有受損、而且最後一次被打是 200 tick 以內，旗標就是 1。
    - 鎖定中收到的 `repair` 一樣被接受，不會被拒絕：村民走過去等，鎖定一結束就自動開始修，不用再點一次。畫面可以用這個旗標提示「主城剛被攻擊，暫時不能修理」。
  - 沒受損的農田：耕作。一塊田只給 1 名村民，玩家點的優先：
    - 名單中第一名去耕這塊田。
    - 名單裡其他人，以及原本在耕這塊田的人：各自去離自己最近、沒人耕的自己的農田；沒有空田就變成閒置，交給經濟分配。
    - 名單裡派去田的人算手派（`HandPicked`），改經濟比例時不會被移走；原本在耕的人標記照舊。
    - 使用者 2026-10-07 回報：原本田有人耕時回 `NotAvailable`，「把指定去砍樹的村民叫去農田，它會沒辦法過去」。
  - 其他情況（沒受損、也不是農田）：`NotAvailable`。
- **`train`**：
  - `building` 不存在：`InvalidTarget`；不是自己的：`NotOwner`。
  - `n` 不是 1–7 的整數：`InvalidTarget`。
  - 建築沒蓋好，或不訓練這種兵：`NotAvailable`。
  - 佇列放不下：`QueueFull`。
  - **人口**：現有人口 ＋ 自己所有建築佇列中的單位 ＋ `n` 超過上限：`PopulationCap`。表頭的 `population` 只算已經出生的單位。
  - 法師：現有法師 ＋ 佇列中的法師 ＋ `n` 超過 6：`MageCap`。
  - 資源不夠 `n` 個：`CannotAfford`。整批接受或整批拒絕。
  - 上限變低（例如民居被拆）時，隊首會停在 100%，等有空位才出生。
- **`cancel_train`**：`index` 超出佇列：`InvalidTarget`。退回全額花費。
- **自動訓練**（第六輪，D-054）：
  - 兵營、射場、法術營有自動訓練開關，建築上的 `BuildingFlag.AutoTrain`（8）。
    - 開著時，每個 tick 訓練跑完以後，佇列空了就排一名這棟建築的兵（槍兵、遠程、法師），和 `train` 一樣在排入時扣錢。
    - 只用超過預留額的資源：每種資源「現有 − 預留額」都夠才排。
    - 人口：現有人口 ＋ 佇列中的單位 ＋ 1 超過上限就不排。這時建築帶 `BuildingFlag.AutoPopulationFull`（16），畫面可以提示是人口滿了才停；有空位、排進去以後就清掉。
    - 法師照樣受上限 6 限制，到上限就不排（不帶旗標）。
    - 同一位玩家的幾棟建築，照建築表的順序（先蓋的先）用錢。
    - 玩家自己的 `train` 照舊可以用，排在自動排的後面。
  - 預設：人類玩家的這三種建築一放下就開著（蓋好才開始排）；電腦的關著，電腦照舊自己下 `train`。由開局決定（6 節 `init`），重播照 `LogHeader.autoTrain`。
  - **`auto_train`**：
    - 不是自己的建築：`NotOwner`；建築不存在：`InvalidTarget`。
    - `on` 不是布林值：`InvalidTarget`。
    - 不是兵營、射場、法術營：`NotAvailable`。
    - 沒蓋好也可以設，蓋好以後照設定。暫停時兩個旗標都清掉；已經排的照樣訓練。
  - **`reserve`**：每位玩家一組，預設木 150、金 100（夠蓋一座法術營）、魔晶 15（留 3 發晶砲）、糧 0。
    - 四個值都要是 0–10000 的整數，否則 `InvalidTarget`。
    - 現在的預留額在表頭 `reserveFood` 到 `reserveCrystal`。
- **`rally`**：
  - 只有會訓練的建築可以設，其他：`NotAvailable`。
  - 新單位出生後走到集結點。
  - 村民的集結點如果在資源點或空著的自家農田上，出生後直接去採或耕。
- **`eco_ratio`**：三個值都是 0–100 的整數、加起來 100，`on` 是布林值，否則 `InvalidTarget`。比例開著時，除了閒置的村民，正在採糧、木、金的村民也會照比例重新分配：每秒檢查一次，某種資源的人數和比例差超過 1 名才移人（操作改善輪，`sim/README.md`）。
- **`recall`**：
  - `on: true`：所有村民記下手上的工作，躲進最近還有空位的主城（15 人）或民居（5 人）。沒位子的在主城旁等。
  - 回城中新訓練的村民也會去躲。
  - `on: false`：全部出來，回去做原本的工作。
- **待命**（GDD 第 4 節）：
  - 玩家用 `move`、`retreat`、`stop`、`attack` 親手指揮過的村民，閒下來後原地待命。自動修理和經濟分配都不會把他們派走。
  - 待命的村民照樣在 `idleFarmers` 清單裡，也有 `IdleFarmer` 旗標。
  - 玩家再給他工作（`gather`、`build`、`repair`）時解除待命。
  - 全體回城照樣會帶走待命的村民；回城結束後，他們回到待命狀態。
- **自動派工**，每 20 tick 一次，只處理閒置、而且不是待命的村民（回城中則全部都去躲）：
  - 回城中：去躲。
  - 否則：附近 6 格內有受損的自家建築就去修。
  - 再來，經濟分配開著時：派去離自己比例最遠的資源（平手依糧、木、金），晶脈不會自動派。
  - 糧食從最近的空農田或野果中選，木頭找樹，金找金礦。
- **村民不會自己找敵人打**，只有用 `attack` 指定目標才打。

### 3.2 法師、城鎮與投降（PR-4）

- **`cast`**：`u` 是一名法師的 id；`fx`、`fy` 是**定點座標**（1 格 = 1024，跟快照裡單位的 `x`、`y` 一樣）。
  - 被拒的原因，依檢查順序：
    - 不是自己的單位：`NotOwner`。
    - 不是法師：`NotAvailable`。
    - 座標不在地圖內：`InvalidTarget`。
    - 距離超過射程（`rules.cannonRange`，第八輪 7 格，以前 8 格）：`OutOfRange`。
    - 還在冷卻：`Cooldown`。
    - 魔晶不到 5：`NoCrystal`。
  - 法師原地校準 30 tick（1.5 秒），不能動，出現預警區（4.6 節）。
  - 發射那一刻扣 5 魔晶；魔晶已經不夠就不發射。
  - 打中落點 1.5 格內所有**不是施法者自己**的單位（敵方和中立民兵，躲在建築裡的不算）；不打建築。
  - 之後冷卻 160 tick（8 秒）。
  - 校準期間收到其他指令就取消，不扣魔晶。
- **`autocast`**：開關 `u` 裡的法師（旗標 `Autocast`）；沒有法師：`NotAvailable`。新訓練的法師一開始就開著（第三輪起，D-026），要用這個指令才會關掉。
  - 開著時，每 10 tick 檢查一次；法師在撤退、冷卻中或魔晶不到 5 時不檢查。
  - 在射程內看得到的敵方單位中，找一個位置：以它為落點時，半徑 1.5 格內的敵人最多，而且至少 3 名。平手取 id 小的。
  - 找到就開始校準，發射後回到原本的指令（例如前進）。
- **防護罩**（法師出生時 60）：
  - 先吸收傷害，罩破之後才傷到本體。同一個 tick 打在罩上的傷害全部由罩吸收，多出來的不傳到本體。
  - 打罩時用對「shield」的加成：遠程 ×3（前期平衡起，原本 ×1.5），晶砲 ×1。
  - 5 秒內沒有受到、也沒有造成傷害時，每秒回復 6。
- **法師陣亡**：
  - 擊殺方加 15 魔晶。被中立民兵或箭樓打死時沒有人拿到。
  - `mage_killed` 的 `killer` 是擊殺方玩家；同一個 tick 有多方命中時，算 id 最大的攻擊者。
- **`town_choice`**：
  - 被拒的原因：
    - 城鎮 id 或 `choice` 不對：`InvalidTarget`。
    - 不是你攻下的：`TownNotYours`。
    - 已經選過（不在待選擇狀態）：`TownChoiceMade`。
    - 治理的錢不夠：`CannotAfford`。
  - 治理的花費在選擇時就扣，叛離不退還。
- **城鎮的規則**（D4）：
  - 只算城鎮範圍內的軍隊（D-089 起是牆以內，見 3.5），村民和躲在建築裡的不算。雙方都有軍隊時是爭奪中（`Contested`），狀態凍結；廢墟照樣倒數。
  - **中立城鎮**：這座城鎮的民兵全部倒下（不管在不在範圍內），大城的箭樓也被拆掉，而且範圍內只有一方的軍隊，就被這一方攻下，變成待選擇。
    - 箭樓拆掉後不會再出現。
  - **被持有的城鎮**（待選擇、搶奪中、修繕中、治理中）：另一方有軍隊在範圍內、持有者沒有時，就被另一方攻下，重新待選擇；搶奪和修繕都取消。
  - **搶**：持有者有軍隊在範圍內時才倒數（小鎮 15 秒、大城 25 秒）。搶完拿到資源，變成廢墟 4 分鐘，之後回到中立、民兵補回一半。
  - **修繕**：駐軍達到最少人數時才倒數（小鎮 45 秒 1 人、大城 60 秒 3 人）。
  - **治理**：駐軍足夠時每分鐘產出；累加器每 20 tick 發放一次。人口上限 +5／+10（D-083 的規則開著時 +20／+40，天花板也 +20／+40，見 2 節的 `rules.population`）。
  - **叛離**：修繕中或治理中駐軍不足，`revoltTimer` 從 1,200 tick 倒數，歸零時變回中立、民兵補回一半；駐軍補足就停止倒數。
- **`surrender`**：投降的一方輸，`game_over` 的原因是 `Surrender`。之後的指令都回 `GameOver`。

### 3.3 第七輪：城鎮只能搶一次、箭樓與躲進建築、騎兵（D-061）

每一項都有開關，看 `rules.features`。開關關著時，模擬照第六輪的規則跑。

- **城鎮只能搶一次**（`plunderOnce`）：
  - 每座城鎮一局只能搶一次。搶完照舊變廢墟 4 分鐘，之後回到中立、民兵補回一半；再被攻下時只能治理。
  - `town_choice` 選搶一座搶過的城鎮：`AlreadyPlundered`，城鎮還是待選擇。
  - 快照的城鎮旗標 `Plundered`（4.5 節）說這座搶過了。
- **治理收入**：`rules.towns[size].perMinute` 是全額。
  - 搶過的城鎮再被治理時，收入從 `rules.plunderRecovery.startPermille` 開始，治理越久越高，`ticks` 之後回到全額。
  - 回升的進度記在城鎮本身，換人治理不會歸零。
  - 目前是幾成，看城鎮的 `incomePermille`（4.5 節）。
- **箭樓**（`towers`，`BuildingType.ArrowTower`）：
  - 用 `build` 蓋，占地、花費、血量照 `rules.buildings`。只能蓋在 `TowerLand` 的格子上（第 7 節）。
  - 自己會射箭，數值照 `rules.arrows.arrowTower`。
  - 大城的中立箭樓是另一種建築（`TownTower`；D-100 起是每座城都有的主堡 `Keep`，同一個值，見 3.10），不能蓋。
- **躲進建築**（`garrison`）：
  - `garrison`：`u` 裡自己的遠程兵和法師走到 `building`（自己蓋好的主城或箭樓）旁邊躲進去，其他兵種略過。
    - 每棟最多躲 `rules.buildings[type].holds` 名，走在路上的也算。超過的兵留在原地，指令不變。
    - 被拒：`u` 裡沒有自己的單位 `NotOwner`；不是自己蓋好、能躲士兵的建築 `InvalidTarget`；`u` 裡沒有能躲的兵 `NotAvailable`；一名都放不進去 `NoRoom`。
    - 走去的路上和躲在裡面時，單位的 `order` 是 `Garrison`、`orderTarget` 是建築 id；躲在裡面時 `action` 是 `Garrisoned`（不畫）。
  - 躲在裡面時：
    - 照自己的攻擊、攻擊間隔、剋制加成打看得到的敵方單位，射程從建築占地的邊緣算。不會移動、不會追。
    - 法師照樣用晶彈；晶砲的射程也從邊緣算，自動施放照舊，`cast` 也可以下。從裡面放的晶砲傷害 1/3、冷卻照舊（`rules.garrisonCannon`；ceo 2026-10-07：不打折時躲著的法師打不到又一直放，24、30 名進攻都全滅）。
    - 一樣近的目標：取在自己標準座標系裡 v 較小、再 u 較小那一格的，再取 id 小的，所以互為鏡像的局面打互為鏡像的目標。玩家的箭樓也一樣；主城和大城箭樓照舊。
    - 不會被任何攻擊打到（包括晶砲），也不算城鎮的駐軍。
    - 每射一次，事件 `shot` 給看得到建築或目標的玩家（第 5 節）。
  - 出來：
    - `leave`：`building` 裡自己的士兵出來，站在建築旁邊待命；有 `u` 就只放 `u` 裡的。沒有人可以出來：`NotAvailable`。
    - 對躲著的兵下 `move`、`retreat`、`attack`：先出來再照做。`stop`、`stance`、`autocast`、`cast` 留在裡面照用。
    - 建築被打掉時，裡面的人全部跑出來。
  - 村民照舊用 `recall` 躲進主城和民居，數量另算（`shelter`），不佔士兵的位置。
- **別人的建築裡有沒有人**：看得到的建築都帶 `Occupied` 旗標（裡面有人，村民或士兵都算）。人數（`garrisoned`、`soldiers`）和是誰只有自己的建築才有；這是規則，電腦的 PlayerView 也一樣。
- **騎兵與馬廄**（`cavalry`，`UnitType.Cavalry`、`BuildingType.Stable`）：
  - 馬廄用 `build` 蓋，`requires` 裡的建築要先有。用 `train` 訓練騎兵，`auto_train` 和兵營一樣（人類玩家的一開始開著）。
  - 數值和剋制照 `rules.units`、`rules.multipliers`。
- **`game_over` 的統計**：`unitsTrained`、`unitsLost` 照舊只列村民、槍兵、遠程、法師；騎兵另外放在 `cavalryTrained`、`cavalryLost`（PR K）；攻城砲在 `siegeTrained`、`siegeLost`（D-099，開著時才有）。

### 3.4 哨所（D-080）

開關是 `rules.features.outpost`（開著時才有這個欄位）。關著時 `build` 哨所和 `post`、`unpost`、`outpost_mode` 都回 `NotAvailable`。

- **蓋**：用 `build` 蓋 `BuildingType.Outpost`，占地、花費、血量、視野照 `rules.buildings`。
  - 放置規則和一般建築一樣（第 7 節）：走得到、探過、沒有被擋住的空地都可以。中立城鎮的範圍裡、自己治理的城鎮裡、敵方主城的箭射得到的地方都可以（使用者選「任何空地都能蓋」）。沒有數量上限。
  - 自己蓋好的哨所占地 `rules.towerReach.outpost` 格內可以蓋箭樓（第 7 節的 `TowerLand`）。
- **駐守**（`post`）：`u` 裡自己的槍兵走到 `building`（自己蓋好的哨所）周圍的位置站好，其他兵種略過。
  - 每座最多 `rules.outpost.slots` 名，走在路上的也算。超過的兵留在原地，指令不變。
  - 被拒：`u` 裡沒有自己的單位 `NotOwner`；不是自己蓋好的哨所 `InvalidTarget`；`u` 裡沒有槍兵 `NotAvailable`；一名都放不進去 `NoRoom`。
  - 走去的路上和駐守中，單位的 `order` 是 `Post`、`orderTarget` 是哨所 id。駐守的兵站在外面，看得到就照常顯示。
- **攻擊**（預設，沒有 `Hold` 旗標）：
  - 敵方的兵走進哨所占地 `rules.outpost.reach` 格內，駐守的兵就去打。
  - 範圍內沒有敵兵時，也去拆範圍內的敵方建築，例如敵人在旁邊蓋的哨所或箭樓。
  - 哨所或任何一名駐守的兵被打，駐守的兵就一起去打攻擊者，和堅守一樣。
  - 追出哨所 `rules.outpost.chase` 格就不追；範圍內沒有敵人就走回自己的位置。
  - 隔幾個 tick 才重新找一次目標，和其他兵一樣；被打時馬上反應。
- **堅守**（`outpost_mode` 的 `hold` true，哨所帶 `Hold` 旗標）：
  - 站在位置上不動，只打走到身邊的敵人。
  - 哨所或任何一名駐守的兵被打，駐守的兵就一起去打攻擊者，追到 `rules.outpost.chase` 格為止，再走回位置。
  - 這條只用在哨所。一般部隊的 `stance` 堅守照舊不反擊。
- **離開**：
  - `unpost`：這座哨所的駐守兵全部離開，站在原地待命。沒有人駐守：`NotAvailable`。
  - 對駐守的兵下 `move`、`retreat`、`attack`：他離開哨所，照新的指令做。`stop`、`stance`、`formation` 對駐守的兵沒有作用。
  - 哨所被打掉時，駐守的兵全部變回一般的兵，站在原地待命。
- **快照**：
  - 建築列的 `posted`：自己的哨所有幾名槍兵駐守（走在路上的也算）。別人的哨所是 0：他們的駐守兵站在外面，看得到的就在單位列裡（`order` 是 `Post`）。
  - 看得到的哨所都帶 `Hold` 旗標（堅守時）。這是規則，電腦的 PlayerView 也一樣。
- **畫面**：`order` 是 `Post` 的兵不要拉進軍團（D-080）。

**被拒的原因碼**（`Reject`）：

### 3.5 城堡（D-089）

使用者 2026-10-19：「希望像一個城堡」。城牆真的擋路，只能走城門；城門一直開著，誰都能走；小鎮用木柵，大城用石牆。

D-096 起城門會關、可以打破，持有的人可以上城牆，見 3.7（`features.gates`、`features.walls` 關著時照這一節）。

- **城牆是地形**：
  - 地格是 `Terrain.Wall`（2），不能走、不能蓋。
  - 不是建築，所以不會壞，城鎮變廢墟也還在。沒有人會去打牆：「路被擋住就打擋路的建築」（D-024）只找建築。
  - 不擋射擊、不擋視野：遠程兵、法師、箭樓都可以隔著牆打，和岩石一樣。
- **城門**：牆上的空地，一直開著。兵進出城只能走城門，尋路自己會繞過去。
  - **城門的通道不能蓋**（ceo 2026-10-20：使用者說城門一直開著，誰都能走，建築堵住城門就等於把門關上）：城門的格子、每一格城門外面那一格（`outside`）、裡面第一格（`behind`），每個門都留一條 3 格深的直通道。占地碰到任何一格都回 `GateLane`。
  - 通道以外的建築還是可能把路擋住（例如在門外一圈蓋滿）。這時要進城的兵照 D-024 先打擋路的那棟建築。
- **城鎮的範圍是牆以內**：攻下、持有、搶的倒數、修繕和治理的駐軍、叛離，都只算牆以內的軍隊。
  - 站在城門的格子上不算：城門在牆那一圈，不在 `inside` 裡。
- **格子**：`rules.towns[size].castle`（`TownCastle`），都是相對城鎮中心格（`TownField.cellX`、`cellY`）的偏移，用地圖本身的方向，雙方一樣：
  - `inside`：`{ x0, y0, x1, y1 }`，牆以內的格子（含邊界）。
  - `wall`：牆和角樓的格子；`corner`：其中角樓的格子。
  - `gate`：城門的格子；`outside`：每一格城門外面那一格空地；`behind`：每一格城門裡面第一格。`outside`、`behind` 的順序和 `gate` 一樣。
  - `militia`：民兵站的位置，照放的順序。
  - `garrison`：war-game-ui 畫的駐軍位置，只是示意；模擬不會替玩家排駐軍。
  - `towerLand`：箭樓可以蓋到 `inside` 外幾格（第一圈是城牆，所以 3 就是城牆外 2 格）。
- **三種城堡**：
  - 小鎮：牆在離中心第 5 格，牆以內 9×9（`inside` −4..4），城門 3 格寬、四面各一個。
  - 大城（固定地圖、隨機地圖的對角出生）：箭樓 2×2，牆以內 12×12，城門 2 格寬，四角 2×2 角樓。
  - 大城（隨機地圖的相鄰出生）：箭樓 3×3，牆以內 13×13（`inside` −6..6），城門 3 格寬，四角 2×2 角樓。
- **大城的偏移每張地圖可能不同**：大城的城堡以箭樓為中心。隨機地圖會把整張圖轉向或翻面，所以箭樓相對城鎮中心格的位置不一定。
  - `rules` 裡給的是這張地圖已經對好的偏移，每局都要從 `ready` 的 `rules` 讀，不要寫死。
  - 固定地圖的大城是 `inside` −6..5。
- **看到城鎮**：看到城堡的任何一格（牆以內、牆、城門）就算看到這座城鎮，快照的 `towns` 就有它的列（4.5）。城鎮的事件也照這樣送給看得到的人。
- **畫面怎麼知道牆和門**：
  - 固定地圖：`map.terrain` 一開始就有 `Wall`。
  - 隨機地圖：探到才知道，從快照的 `placement` 讀 `Wall`（16）、`Gate`（32）、`GateLane`（64），或在看到城鎮以後照 `castle` 畫。
- **`inTown(castle, townCellX, townCellY, cellX, cellY)`**（`protocol.ts`）：一格是不是在那座城鎮的牆以內，畫面和電腦都可以用。

### 3.6 天然障礙物（R6-51）

使用者 2026-10-20 選了「全部照整張地圖加」：河、橋和淺灘、有缺口的岩脊、懸崖、湖、石堆、密林。密林是普通的樹（甲，可以砍），種得比較密。

- **地形**（`Terrain`，第 2 節）：
  - 岩石（1，石堆、岩脊）、水（3，河、湖）、懸崖（7）：不能走、不能蓋。不擋射擊、不擋視野，和城牆一樣。
  - 淺灘（4）、橋（5、6）：可以走，和空地一樣快；不能蓋（`Reject.Crossing`），理由和城門的通道一樣，3 格寬的通道被堵住就等於斷了路。
  - 橋的方向就在值裡：5 是南北向（人往南北走過去），6 是東西向。不用看鄰格判斷（3×3 的橋看鄰格分不出方向）。
  - 地圖鏡射、轉向時，兩個值會互換。
  - 密林：照舊是樹（`nodes`），會擋路，砍完可以走。
- **形狀**（畫面要多畫哪些圖塊可以照這個）：
  - 水至少 2 格寬：每一格水都在一個 2×2 的水（或淺灘、橋）裡。
  - 懸崖 1 格寬的線，直的或斜的。
  - 淺灘、橋一律 3 格寬，從岸走到岸。兩端是空地。
- **固定地圖**：照 war-game-ui 的整張地圖（`core/fixed-terrain.ts`）。玩家 0 的橋在 (17–19, 58–60)，南北向；淺灘在 (39–41, 85–87)，東西向；鏡射的那一邊方向互換。
- **隨機地圖**：見 `sim/README.md`。每張的形狀規則和上面一樣。
- **畫面怎麼知道**：
  - 固定地圖：`ready.map.terrain` 一開始就是整張。
  - 隨機地圖：快照的 `terrain`（4.7），只放探過的格子。
- **`sim/src/map-grid.ts`**：印出模擬實際產生的地圖（一格一個字元，加上每格的 `Terrain` 值），給美術和模擬用同一份格子。

### 3.7 城門與城牆（D-096）

使用者 2026-10-21：城牆「雞肋」，對誰都一樣擋路。改成：城門會關、可以打破，自己的兵可以站上城牆，治理中的城鎮城樓會射箭。開關看 `rules.features.gates`、`features.walls`；關著時照 3.5。

- **城門是建築**（`BuildingType.Gate`，13）：
  - 每個開口一座，占地就是那個開口的格子（一排，不是正方形）。`cellX`、`cellY` 是開口左上角那一格；開口的格子照 `rules.towns[size].castle.gates`（每個開口一組，順序和 `gate` 一樣）。畫面畫占地時，寬和高請照 `castle.gates` 算，不要用 `buildings[Gate].size`（它是 1）。
  - 擁有者跟著城鎮：中立城鎮的是 `NEUTRAL`；被攻下以後（待選擇、搶的倒數、修繕、治理中）是持有的玩家。
  - 血量：`rules.towns[size].gateHp`。快照的建築列照一般建築送（看得到才有，看過的留在記憶裡）。
- **誰能走**：
  - 城門站著時，只有持有的玩家能走過去；中立城鎮的城門誰都不能走，民兵也不能。
  - 廢墟：誰都能走。打破的城門（建築沒了）：誰都能走。
  - 尋路照這個走：走不到的地方會繞，沒有路就打最近的那個城門（下面）。
- **打城門**：
  - `attack` 指定城門就去打。對 `move` 的目的地在城牆裡、又進不去時，兵會去打離自己最近的那個城門，打破再進去。
  - 城門不會被順路打：攻擊移動經過城外不會停下來打城門，城門也不會被當成一般目標。
  - 近戰照攻擊算；遠程兵和法師的普通攻擊只算 `rules.gate.rangedNum`／`rangedDen`（1/5），至少 1 點。
- **修和蓋回來**：
  - 自己的城門受損時，村民用 `repair` 修，和其他建築一樣。
  - 治理中的城鎮：城牆裡沒有敵兵 `rules.gate.rebuildTicks`（60 秒）以後，打破的城門自己蓋回來，滿血。
  - 修繕結束（變治理中）、廢墟變回中立時，所有打破的城門都蓋回來。
- **城樓射箭**：治理中的城鎮，每座站著的城門照 `rules.arrows.gate` 射：每 2 秒 1 箭、5 點、射程 9 格（從城門占地邊緣算），打持有者看得到、最近的敵方單位。
  - 持有者在城牆裡和牆上的士兵每 `perSoldiers`（3）名多 1 箭，最多多 `extraMax`（3）箭。打破的城門不射。
  - 每射一次照樣送 `shot` 事件（第 5 節），多射的箭數在 `n`。
- **上城牆**（`wall`）：
  - `u` 裡自己的遠程兵和法師走上 `town` 的城牆，每一格牆站一名，各自挑離自己最近的空牆格（一樣近時取自己標準座標系裡第一格）。其他兵種略過。
  - 只有自己持有的城鎮可以上：待選擇、搶的倒數、修繕、治理中。
  - 被拒：`u` 裡沒有自己的單位 `NotOwner`；`town` 不存在 `InvalidTarget`；不是自己持有的城鎮 `TownNotYours`；`u` 裡沒有能上牆的兵 `NotAvailable`；牆上沒有空位 `NoRoom`。功能關著：`NotAvailable`。
  - 走去的路上和站在牆上時，單位的 `order` 是 `Wall`、`orderTarget` 是城鎮編號。
  - 站上去以後：沒在打時 `action` 是 `OnWall`，射擊時是 `Attack`，法師放晶砲時是 `Calibrate`；不管哪一種，`flags` 都帶 `OnWall`（32）。位置就是那一格牆的中心。
  - 上牆和下牆都是一個 tick 就到：從牆內那一格跳到牆格，下來時跳回那一格。
  - 牆上的容量就是牆的格數（含角樓）：小鎮 28、大城 44（相鄰出生的大城照它的 `castle.wall` 算）。
- **站在牆上**：
  - 不會移動、不會追。射程多 `rules.walls.range`（1 格）。法師的晶砲照舊，自動施放和 `cast` 都可以。
  - 挨遠程兵、法師晶彈和箭只算 `rules.walls.takenNum`／`takenDen`（3/4）；晶砲照算。
  - 近戰只能從城牆裡面、站在牆邊打到；牆外的近戰打不到牆上的兵，也不會去追。
  - 算在城鎮裡：攻下、持有、搶的倒數、治理的駐軍都算。
  - 城鎮丟了（被攻下、變廢墟），自己下來。
- **下城牆**：`leave_wall`，或對它下 `move`、`retreat`、`attack`、`stop`：回到它上牆的那一格（牆裡面），再照新的指令做。`stance`、`autocast`、`cast` 留在牆上照用。
- **中立城鎮的民兵**：開局時一半站在牆上投石（小鎮 6 名裡 3 名、大城 12 名裡 6 名），射程 `rules.walls.sling`（4 格），攻擊照民兵。另一半在城裡。民兵的位置雙方對稱（照各自的標準座標系挑）。`action`、`flags` 和上面一樣。
- **出手的時間**：和所有單位一樣，攻擊間隔（`rules.units[type].cooldown`，民兵 30 tick）到的那個 tick 傷害就算進去，沒有飛行時間，也沒有每一下的事件。畫面照 `action` 是 `Attack` 起算、依攻擊間隔播出手動作，和其他兵一樣。

### 3.8 騎兵繞後排（D-097）

使用者 2026-10-22：「騎兵自動繞去打後排」。開關看 `rules.features.cavalryFlank`。協定不變，這裡寫行為，給畫面的說明和電腦參考。

- **什麼時候**：玩家的騎兵自己挑目標時：
  - 待命、積極姿態；
  - `move` 途中本來就會停下來打的時候（6 格內有敵人），不會為了遠處的法師離開移動路線；
  - 軍團一起打、加入隊友的戰鬥、被打還手。
- **不會**：直接下的 `attack`、堅守姿態、`retreat`、躲進建築、上城牆，照原本的做。
- **挑誰**：10 格內、看得到、走得到的敵方法師，取最近的；沒有法師就取遠程兵。離原位（待命時站的地方；`move` 途中是轉過去的那一點）超過 12 格的不挑。
  - 已知的敵方主城、大城箭樓、玩家箭樓、治理中城鎮的城門，射程再加 1 格內的目標不挑。
- **怎麼走**：騎兵和目標之間有敵方近戰兵擋著時，從那群兵伸得比較短的那一側繞過去，到那群兵最外側再往外 2 格、和最遠那名同高的點，再衝向目標。兩側一樣長時，照自己標準座標系決定，所以鏡射的兩局繞向鏡射的一側。這條路被地形擋住時不繞，照一般的路走。繞的途中不停下來打槍兵。
- **放棄**：繞了 8 秒還沒打到人，就改打最近的敵人，之後 5 秒內不再繞後排。目標死了或沒有了，`move` 照原本的路線繼續走。

### 3.9 攻城砲（D-099）

使用者 2026-10-22：「蓋一大堆防禦塔根本打不去」，選了加攻城砲（東陸霹靂車、西陸投石機）。開關看 `rules.features.siege`，關著時沒有這一節的東西。

- **砲坊**（`BuildingType.SiegeWorks`，14）：3×3，木 200，蓋 45 秒，生命 500；要先有自己蓋好的射場（`requires`）。訓練攻城砲，`auto_train` 和其他兵營一樣。功能關著時 `build` 回 `NotAvailable`。
- **攻城砲**（`UnitType.Siege`，6）：木 150、金 100，訓練 40 秒，生命 140，攻擊 35，射程 10 格、最短 3 格（`minRange`），每 5 秒一發，速度 0.6，視野 10 格，人口 1。數值照 `rules.units`。
- **砲彈**：
  - 丟出時就定好落點：打單位是那名單位當時的位置，打建築是占地的中心。`rules.siege.flightTicks`（1 秒）後落地才算傷害，會動的兵躲得掉。
  - 打單位的砲彈：落點 `splash`（1 格）內所有不是自己這方的單位都受傷，每名 35（照剋制倍率；牆上的兵 3/4）。不會打到自己人。
  - 打建築的砲彈：只打那一棟，35 × `rules.siege.vsBuildings`（3）；城門 35 × 8（D-096）。建築在落地前被拆掉就沒有效果。
  - 每丟一發送事件 `siege_shot`（第 5 節）：`u` 攻城砲、`x`、`y` 落點（定點）、`lands` 第一份看得到落地結果的快照的 tick（這個事件所在快照的 tick ＋ `flightTicks`）。
    - 給看得到攻城砲或落點的玩家（丟出那個 tick 的視野）。
    - 只看得到落點的玩家另外拿到 `from`：從落點往攻城砲的方向，16 方向（和 `facing` 一樣）。只有方向，沒有格子、沒有距離（ceo 2026-10-22：看得到石頭從哪裡飛來是合理的；電腦拿到的事件和欄位一樣）。畫面讓石頭從這個方向飛進來。
- **自己挑目標**（待命、攻擊移動、堅守都一樣），射程內、最短射程外、自己看得到的：
  1. 會射箭的敵方建築：主城、大城箭樓（D-100 開著時是每座城的主堡）、玩家箭樓、治理中城鎮的城門；
  2. 其他敵方建築（城門除外）；
  3. 單位：落點 1 格內不是自己這方的單位最多的那名，至少 2 名。
  - 一樣好時取近的，再照一般的規則。
- **最短射程**：自己挑的目標近到 3 格內就放掉。直接下 `attack` 的目標在 3 格內，就往反方向退到 3 格再丟。
- **剋制**：騎兵打攻城砲 ×2（`multipliers`）。攻城砲不在三角裡，和法師一樣；近身的兵都打得贏它。
- **統計**：`game_over` 多 `siegeTrained`、`siegeLost`（開著時才有）。

### 3.10 城鎮放大、主堡（D-100）

使用者 2026-10-23：「我覺得攻擊城市的操作手感不太好，常常點不到。我覺得把城鎮的範圍做更大一點，然後裡面也可以有一個主堡可以點，把這個主堡打下來跟殺完駐守的殘兵拿下了」。開關看 `rules.features.keep`，關著時沒有這一節的東西，城堡和大城箭樓照 3.5。

- **城鎮變大**：小鎮牆內 13×13，大城 17×17。牆、角樓、城門、門外和門內的格子看 `rules.towns[size].castle`。每座城都以中心格為中心，兩種地圖一樣。城門四面各一座，3 格寬，正對主堡。
- **主堡**（`BuildingType.Keep`，9）：3×3，在城鎮正中央，左上角是中心格 −1。玩家不能蓋（`NotAvailable`），也不能躲人（容納 0）。
  - 倒下時建築直接拿掉，那 3×3 格可以走。但不能蓋任何建築，因為主堡之後會在原地重建（`placement` 標 `Blocked`，`build` 回 `BadPlacement`）。重建時站在上面的兵會移到旁邊最近的空格。
  - 誰持有城鎮就替誰射箭：中立時替民兵射，治理中替治理的人射。箭看 `towns[size].keep.arrow`。
  - 生命照城鎮大小（`towns[size].keep.hp`）。擁有者的村民可以用 `repair` 修。
  - 攻城砲打它照一般建築 ×3。它會射箭，所以攻城砲自己挑目標時會先打它（3.9）。
- **拿城**：
  - 中立的城：民兵全死、主堡倒了、牆以內（含牆上）只有一方的兵。
    - 主堡倒了以後，牆上的民兵會下來，用攻擊移動走向城中央，一路打到底。城變大後，中央在他們投石的射程和視野之外，不這樣做的話城會一直拿不下來（war-game-ai 2026-10-24 找到）。
  - 別人持有的城：主堡倒了、守方牆以內沒有兵、我方有兵。
  - 主堡從倒下到下面三種情況之前都不在：等待選擇、搶、修繕中、廢墟。
    - 修繕完成（變成治理中）：替治理的人重建，滿血。
    - 回到中立（廢墟結束或叛離）：替民兵重建，滿血。叛離時主堡如果還站著，就直接交給民兵、補滿血。
    - 治理中主堡倒了、守方還有兵在裡面：沒有敵人在牆以內滿 `towns[size].keep.rebuildTicks`（60 秒）後重建；這段時間有敵人進來就重新算（和 3.7 的城門一樣）。
- **點城鎮的地面就是進攻**（畫面）：選著兵時點敵方或中立城鎮的地面，送 `move`（攻擊移動）到主堡的格子。兵進到牆內、6 格內沒有敵兵時，會自己打不是自己的建築，主堡在內；城門關著時先打擋路的城門。

### 3.11 多金多木與市場（D-101）

使用者 2026-10-22／23：「其實現在打很容易拖到後期都沒有樹跟金礦可以採」。選了「地圖上多放金和木」和「市場，換越多越貴」，沒有選商隊和樹農。兩個開關分開：RICH 管地圖，MARKET 管市場。

- **RICH**（地圖）：
  - 每格金 400 → 600，每棵樹 100 → 150。格子和數量不動，路線也不變。
  - 搶的金礦：在兩方一樣遠的軸線上。固定地圖 3 片：大城往晶礦那一側一片、兩座角落小鎮往角落那一側各一片。隨機地圖 1 片：大城的另一側，和晶礦反方向。
  - 隨機地圖第三座城旁的金礦每張都有（原本一半），放不下就不放，不重抽地圖。
- **市場**（`BuildingType.Market`，15）：3×3，木 150，蓋 40 秒，生命 600，要先有自己蓋好的穀倉，可以蓋多座。開關關著時 `build` 回 `NotAvailable`。
- **`trade`**：{ `resource`（`Resource.Food` 或 `Wood`）, `buy`, `lots`（1–`maxLots`）}。要有自己蓋好的市場，沒有就回 `NoMarket`（20）。
  - 一份一份算：
    - 買：付現價的金，價格 +`step`，最多到 `max`。
    - 賣：拿到 floor(現價 × `sellPermille` ÷ 1000) 金，價格 −`step`，最少到 `min`。
  - 全部成交或全部不成交：錢或貨不夠回 `CannotAfford`；`resource` 不是糧或木、`lots` 超過範圍，回 `InvalidTarget`。晶石不能買賣。
  - 成交時，事件 `traded`（第 5 節）只給自己。
- **價格**：每位玩家各自一套，糧、木各一個，起價 `start`。每 `recoverTicks`（30 秒）往起價走 1。表頭的 `priceFood`、`priceWood` 是自己的價格，關著時是 0。
- **統計**：`game_over` 多 `marketLots`，是買賣的份數（開著時才有）。

## 4. 快照（`snapshot` 訊息，每個 tick 一份）

內容是人類玩家的視角，也就是 PlayerView，跟 AI 讀的是同一套規則：
- 自己的東西全部都有。
- 敵方與中立的單位，只有站在看得到的格子上才會出現。
- 敵方建築：看得到的是現況，看不到的是記憶中最後一次看到的樣子。

所有 typed array 都用 transferable 傳，client 收到後直接擁有。各表都是 `Int32Array`，每列固定長度（stride），依 id 由小到大排列。

### 4.1 表頭 `header`（長度 `HEADER_LENGTH` = 28；D-101 以前 26，D-083 以前 25）

| 欄 | 名稱 | 說明 | 從 |
|---|---|---|---|
| 0 | `tick` | 這份快照是哪一個 tick 跑完的結果 | PR-2 |
| 1 | `paused` | 1 = 暫停中 | PR-2 |
| 2 | `speed` | 每秒 tick 數 × 100（正常是 2000） | PR-2 |
| 3 | `gameState` | `GameState`：進行中、贏、輸、平手 | PR-2 |
| 4–7 | `food`、`wood`、`gold`、`crystal` | 資源 | PR-3 |
| 8–9 | `population`、`populationCap` | 人口與上限 | PR-3 |
| 10–11 | `mages`、`mageCap` | 法師數與上限 | PR-4 |
| 12–15 | `ratioFood`、`ratioWood`、`ratioGold`、`ratioOn` | 經濟分配的比例與開關 | PR-3 |
| 16 | `recall` | 全體回城中 = 1 | PR-3 |

- 速度只決定每秒跑幾個 tick。

## 7. 能不能蓋：`sim/src/placement.ts`

- `checkPlacement(grid, building, cellX, cellY)` 回傳 0（可以蓋）、`Reject.GateLane`（占地碰到城門的通道，D-089）、`Reject.Crossing`（占地碰到淺灘或橋，R6-51）或 `Reject.BadPlacement`。依這個順序：碰到城門的通道就回 `GateLane`，再來是 `Crossing`。
- client 用快照裡的 `placement` 做即時的紅綠預覽；模擬用同一個函式、配上自己掌握全部資訊的格子圖來判定 `build` 指令。
- 最後一律以模擬的判定為準。例如迷霧裡看不到的敵方建築，預覽會顯示綠色，但模擬會拒絕。
- 判定規則：
  - 占地的每一格都要在地圖內、已探索、沒有被擋住。擋住的包括不可走的地形、樹、已知的建築（含農田）。
  - 農田的每一格還要在自己主城或糧倉的範圍內（`FarmLand`）：離已完成的主城或糧倉占地 6 格內（x、y 距離取較大的那個）。
  - 箭樓（第七輪）的每一格還要是 `TowerLand`：離自己已完成的主城占地 `rules.towerReach.mainCity` 格內（x、y 距離取較大的那個），或在自己修繕中、治理中的城鎮的牆以內、或城牆外 `rules.towerReach.town` 格內（D-089；x、y 距離取較大的那個，也就是 `castle.inside` 往外 `castle.towerLand` 格），或（D-080，`features.outpost` 開著時）離自己已完成的哨所占地 `rules.towerReach.outpost` 格內。`features.towers` 關著時沒有這種格子。
  - 站在那裡的單位不算阻擋，會被推開。
  - 城門的通道（D-089，3.5）：占地的格子不能有 `GateLane`。
  - 淺灘和橋（R6-51，3.6）：占地的格子不能有 `Crossing`。
- 快照裡的 `placement` 是這位玩家知道的狀況：資源點用最後看到的剩餘量，敵方建築用記憶。
  - 城牆（D-089）：牆和角樓的格子標 `Blocked` 和 `Wall`（16），城門的格子標 `Gate`（32）。城門的通道（城門、門外一格、門內一格）標 `GateLane`（64），不標 `Blocked`。D-096 起城門是建築：看得到或記得的城門，它的格子也照建築標 `Blocked`。
  - 水和懸崖（R6-51）標 `Blocked`；淺灘和橋標 `Crossing`（128），不標 `Blocked`。
  - 隨機地圖（D-074）：岩石、城牆、城門、通道、水、懸崖、淺灘、橋也只標探索過的格子；沒探索的格子只有 `Unexplored`。固定地圖照舊整張標出。
- 開局時，每位玩家出生點周圍 16 格已經算探索過，也知道那裡的資源點。

## 9. 重播與雜湊

- **指令紀錄**（`export_log`）：第一行是 `LogHeader`，之後每行一道已經套用的指令（含被拒的）。
  - `maxTicks`：這局的時間上限，重播照它判平手。舊紀錄沒有這個欄位，當成 `MAX_TICKS`。
  - `difficulty`：每位玩家的電腦難度，只是紀錄；重播時電腦關著，不影響結果。沒有時當成 `"normal"`。
  - `autoTrain`（第六輪）：每位玩家的兵營、射場、法術營是否一開始就自動訓練。會影響結果，重播照它開局。沒有時全部關著（電腦對電腦的紀錄不寫這個欄位）。
  - `map`（D-074）：`"random"` 時重播用同一個 `seed` 產生同一張隨機地圖。固定地圖的紀錄不寫這個欄位，沒有就當成固定地圖。
  - 同一份紀錄關掉 AI 重播，每 100 tick 的雜湊都會相同。
- **雜湊**：FNV-1a 32 位元，輸出 8 碼十六進位。範圍是模擬的全部狀態，依 id 順序：
  - 資源、單位、建築、生產佇列、資源點、城鎮與計時、法師的防護罩與冷卻、亂數狀態、每位玩家的記憶表。
  - 第七輪的狀態（城鎮搶過與回升、建築裡的士兵數、騎兵的訓練與損失數）只在它的規則開著時才算進雜湊，所以規則都關著時，雜湊和第六輪逐局相同。
- **確定性檢查的期望值**：`node sim/src/headless.ts --scenario standard --seed <n> --expected <檔案>` 會寫出 `ExpectedHashes` 格式的 JSON（PR-2 起）。
  - Pages 建置時用它產生 `expected-hashes.json`。
  - 手機上的 `determinism` 結果跟它比對。

### 9.1 接著打（`continue`，D-083）

給「繼續上一局」用：頁面被 Safari 清掉、重新載入以後，從存下來的紀錄接著打。
- **畫面要存的**：`export_log` 回的 `jsonl`、`hashes`、`tick` 三樣，原樣存。
  - 匯出當下還沒套用的指令（`t` 是下一個 tick 的）不在紀錄裡，所以按下去的那一瞬間就切到背景的話，那一道指令會掉。
- **`build`**：模擬這一版的識別，由畫面算好帶進 `init` 和 `continue`。模擬只把它當字串比對，不管它怎麼算。
  - war-game-client 的算法：vite 建置時用它的打包器 Rolldown，從 `sim/src/worker.ts` 打包一次，取實際打包進去的模組（moduleIds），路徑排序後連同內容算 sha256，取前 12 碼十六進位。
  - 這樣只有 worker 實際用到的模擬程式改了才會變。只改畫面，或只改 tournament 這類量測工具的上線，舊局照樣接得下去。
  - 畫面自己存的狀態（編隊、留守、鏡頭等）格式有沒有變，由畫面自己帶版本號判斷。
- **Worker 做的事**：
  1. 讀紀錄第一行。`protocol` 和這個 Worker 不同：`protocol`。`build` 和 `continue` 帶的不同：`build`。
  2. 用第一行的 `seed`、`scenario`、`ai`、`maxTicks`、`difficulty`、`autoTrain`、`map` 開局。
  3. 從第 0 tick 用最快的速度跑到 `toTick`，不建快照：
     - 電腦照常在模擬裡想、下指令；人類玩家的指令照紀錄，在它的 tick、電腦想之前放進去。
     - 每個 tick 套用的指令（電腦的也算），要和紀錄的那幾行一模一樣，順序也一樣。對不上：`commands`。
     - 每 100 tick 的雜湊要和 `hashes` 一樣。對不上：`hash`。
     - 每 1200 tick 送一次 `continue_progress`。
  4. 跑到 `toTick`：送 `ready`（和 `init` 一樣），接著一份完整的快照（新的編碼器：資源點全部、迷霧都有），停在暫停。畫面還原好自己的狀態後送 `resume`。
     - 之後的指令接在同一份紀錄後面，`export_log` 照常，`hashes` 也從第 0 tick 算起。
- **`ContinueFailure`**：
  - `protocol`、`build`：版本不同（網站更新過，模擬也改了）。
  - `log`：紀錄或 `hashes` 讀不懂、缺某個第 100 tick 的雜湊、有 `toTick` 以後的指令，或對局在 `toTick` 之前就結束。
  - `commands`：電腦這次下的指令和紀錄不同，或紀錄裡有一道指令沒有套用。
  - `hash`：雜湊對不上（例如紀錄被改過）。
- **要多久**：CI 上一局 80 分鐘（96,000 tick）大約 30–40 秒，見 `node src/continue-bench.ts`。
- 快轉時不能取消；畫面要中止，就直接結束這個 Worker。

## 10. 效能

- 表頭的 `stepMicros` 是這個 tick 的模擬時間，`stepBatchMicros` 是最近 20 tick 的總和。
- iOS Safari 的計時精度只有 1 ms，一個 tick 常常不到 1 ms，所以中位數會變成 0。量測頁請同時報平均值：`stepBatchMicros / 20`。
- 驗收標準：iPhone 上每 tick 模擬的中位數 ≤ 5 ms。
