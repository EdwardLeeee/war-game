# client：第二階段原型的畫面、觸控與測試頁

- 負責：war-game-client。brief：`docs/briefs/2026-10-client-prototype.md`。
- 測試頁：<https://edwardleeee.github.io/war-game/proto/>（合併到 main 後由 `.github/workflows/pages.yml` 部署）。
- 介面是臨時版（GDD 第 10 節的草稿），畫面角落標「原型介面（非正式設計）」。正式介面等 war-game-ui 的設計稿核准後才做。
- 遊戲規則和 AI 在 `sim/`（war-game-core）。client 只透過 `sim/PROTOCOL.md` 的 Worker 訊息送指令、收快照，不改 `sim/`。

## 指令

```bash
npm ci
npm run typecheck   # 型別檢查（連 sim/ 的型別一起）
npm test            # 單元測試（node --test）：手勢表每一列、鏡頭、量測互斥
npm run build       # 建置到 dist/
npm run e2e         # Playwright：WebKit 與 Chromium，iPhone 14 Pro Max 橫向、觸控
```

這台開發機記憶體很緊：本機只跑 `typecheck`、`test`，必要時跑一次 `build`，都用
`systemd-run --user --scope -q -p MemoryMax=1500M -p MemorySwapMax=0 <指令>` 包起來；
瀏覽器測試交給 CI（`.github/workflows/client.yml`）。

## 程式架構（`src/`）

| 資料夾 | 內容 |
|---|---|
| `sim.ts` | 唯一從 `sim/` 匯入的地方（`protocol.ts`、`placement.ts`） |
| `game/` | 一局遊戲：接模擬 Worker（`port.ts`）、收快照、把手勢變成選取和指令、暫停與速度、自動暫停（`game.ts`）；留守、編隊、自動補兵與軍團（拉沒編隊的兵）的名單（`army.ts`，純邏輯，D-026、D-050）；測試掛鉤（`test-hook.ts`） |
| `mock/` | 假世界：跟 `sim/src/worker.ts` 同一套訊息，版面固定，給手勢測試用（`?test=1&mock=1`） |
| `view/` | 畫面知道的一切：前後兩份快照（插值用）、資源點表、迷霧、放建築格子、選取 |
| `camera/` | 螢幕與世界座標、拖曳、縮放、慣性（純計算，Node 可測） |
| `input/` | 手勢狀態機（`gestures.ts`）、點擊的意思（`intent.ts`）、瀏覽器事件接線（`pointer.ts`）、介面按鈕的點／點兩下／長按（`pressable.ts`，同一個狀態機） |
| `render/` | PixiJS 圖層與程式畫的暫代圖形 |
| `ui/` | DOM 介面：右上的速度與暫停（`controls.ts`）；手勢用到的長按提示圈、框選框、技能輪盤、提示列、放建築的 ✓ ✗、被拒原因（`overlays.ts`） |
| `ui/hud/` | 介面外殼（臨時版）：`hud.ts`（編隊、全軍（寫會選到幾名）、閒置、全體回城、被攻擊箭頭、經濟分配、搶或治理、選單、勝負）、`panels.ts`（資源列（人口含訓練中、最後是遊戲時間）、選取資訊與軍團畫面、指令區（進攻／撤退／堅守））、`minimap.ts`、`names.ts`（顯示用名稱）、`economy-ratio.ts` |
| `lab/` | 量測與確定性檢查（互斥、無效標示、對照 CI 雜湊）、log 框 |
| `logs/` | 對局紀錄（D-056）：紀錄代號（`code.ts`）、存在 IndexedDB 的最近 50 局（`store.ts`）、上傳（`upload.ts`）、每局結束時組一筆紀錄並存、傳（`collect.ts`） |
| `tuning.ts` | 長按 350 ms、移動容許 10 px、點兩下 300 ms、慣性等參數 |
| `difficulty.ts` | 開局畫面的難度：第一次是簡單，之後記住這台手機上次選的；讀寫瀏覽器儲存空間失敗時當成沒存過（D-024） |

戰場接的是 core 的模擬 Worker（`game/port.ts` 的 `createSimPort`，Vite 把 `sim/src/worker.ts` 打包成獨立檔案）。
確定性檢查另開一個 Worker 跑同一局 AI 對 AI，逐一比對建置時用 `scripts/expected-hashes.sh`
（core 的 `sim/src/headless.ts --expected`）寫進 `dist/expected-hashes.json` 的雜湊。

## 網址參數

- `?test=1`：開 `window.__proto`（`commit`、`screen`、`ready`，以及 `game` 底下的選取、送出的指令、表頭、鏡頭、輪盤、放建築、格子轉螢幕座標、確定性檢查結果）。一般網址沒有。
- `?test=1&tps=N`：模擬每秒跑 N 個 tick（上限 400），CI 用來加快流程。遊戲裡的速度只有慢 20、正常 30、快 40（D-024）。
- `?test=1&mock=1`：用假世界代替模擬（`e2e/gestures.spec.ts`、`e2e/hud.spec.ts` 用；版面固定）。
- `?test=1&mock=1&r7=1`：假世界打開第七輪的規則（城鎮只能搶一次、箭樓、躲進建築、馬廄和騎兵；`e2e/round7.spec.ts` 用）。模擬的第七輪開關在 `sim/src/core/rules.ts`，網頁打不開。
- `?test=1&hint=1`：開局提示（D-044）。玩家的頁面每局都有；測試頁預設沒有，其他測試直接進戰場。
- `?test=1&logs=<網址>`：對局紀錄改傳到這個網址（`e2e/logs.spec.ts` 攔截用）。
- `?test=1&ai=0`：對手不由電腦操作，單位站著不動。`e2e/main-flow.spec.ts` 用，免得電腦先搶走小鎮或打掉主城；電腦的行為由 core 的 AI 對打測試。量測一律有電腦。

開局畫面選難度（簡單／普通／困難；困難是 D-055，war-game-ai 做的電腦）。玩家的對局沒有時間上限（`init` 的 `maxTicks: 0`），電腦照選的難度下（D-024）。

量測與確定性檢查在「選單 → 量測與確定性檢查」。「開始量測」會開一局 `perf` 場景（所有系統都開著），鏡頭對準交戰部隊，暖機 5 秒後量 30 秒。量測一律用普通、30 分鐘上限，確定性檢查照 CI 的那一局，都不受開局畫面的難度影響。結果和 log 會附上手機的貼圖上限（最大貼圖、一次繪製幾張、有沒有 ASTC），給精靈圖集用。

## 開局提示（D-044）

- 每一局開始時（「重來」也算，「繼續這局」和量測不算）跳出「魔晶從城鎮來」：法師要用魔晶、魔晶主要從城鎮來、搶和治理各得到什麼、離主城最近的小鎮在哪個方向和幾格遠。遊戲在提示開著時暫停。
- 指的是離自己出生點最近的小鎮：大城比較近也一樣，免得新手先去打民兵多、有箭樓的大城（ceo）。地圖上沒有小鎮時才指最近的大城。一樣近挑編號小的（`src/game/town-hint.ts` 的 `hintTown`），不寫死編號。core 在主城附近加小鎮後，自動變成那一座。
- 小地圖在提示開著時和關掉後 10 秒，用魔晶的青色圈閃那座城鎮；「看那座城鎮」會把鏡頭移過去。
- 「不再提示」記在這台裝置上，記法和難度一樣（`localStorage` 的 `war-game.proto.townHint`，`src/hint-pref.ts`），之後開局不再自動跳。瀏覽器不給存時（無痕、封鎖網站資料）照樣提示。「知道了」「看那座城鎮」不算，下一局還會提示。
- 「選單 → 魔晶怎麼拿」隨時打開同一個提示，一樣暫停。已經按過不再提示時，那一顆改寫「開局時要提示」，按了就恢復。
- 對局中途打開時，指的是最近、可以攻下的小鎮：中立的、對手的、還沒探索過的都算；自己的和廢墟不算（廢墟要等變回中立才有東西拿）。跳過了比較近的小鎮時，寫「離你的主城最近、可以攻下的小鎮」。小鎮都是自己的（或廢墟）時，照舊指最近的小鎮（ceo）。開局時城鎮都是中立的，所以就是最近的小鎮。

## 離民兵太近（D-044）

- 放建築時，預覽落在還有民兵的中立城鎮附近，提示列多一行「這裡離城鎮的民兵太近，去蓋的村民會被攻擊」。只警告，✓ 照樣能按（`src/game/militia.ts`）。
- 附近：建築占地的中心到城鎮那一格的中心不超過 12 格，剛好 12 格也算；和 core 的電腦蓋建築時保持的距離一樣（`sim/src/ai/ai.ts` 的 `TOWN_CLEARANCE`）。core 把它搬到 `rules.ts` 之後，改成直接讀。
- 城鎮的狀態和民兵數照快照（在霧裡就是最後看到的樣子）：民兵都倒了、被自己或對手拿下、變成廢墟，都不警告。還沒探索過的城鎮照開局的樣子算（中立、有民兵），照樣警告。

## 操作改善輪（D-050）與第六輪（D-054）

- 軍團畫面：點一下編隊按鈕，選取這個軍團，選取資訊換成軍團畫面（D-054）。點兩下照舊跳過去；長按拿掉了。
  - 三種兵各一列：現有、目標、−／+。標題列寫「現有/目標」，沒有兵時寫「還沒有兵」。
  - 「改成剛才選的 N 名」：點編隊之前選的兵變成這個編隊（原本的長按存編隊）；「清空」；「自動補兵：開／關」。進攻、撤退、堅守用右邊指令區的。
  - 換選別的東西就回到一般的選取資訊。
  - 拉兵：每個快照把沒編隊、沒留守、站著沒有指令而且不是堅守的兵，拉進缺人的編隊（缺最多的優先，一樣多給編號小的；自動補兵關掉的不拉）。正在照玩家指令走、打、撤退的兵，停下來才拉；堅守的不拉。
  - 新兵和拉來的兵都不等湊滿，直接走去編隊所在的地方（D-054）。編隊沒人時，先到集結點：兵營、射場、法術營裡建築編號最小、有設集結點的那一個；都沒設就到主城前面那一格。
  - 新兵補不進任何編隊（都不缺這種兵）時，加入現有兵最多的編隊，那種兵的目標加 1（一樣多給編號小的、自動補兵關掉的不算）；沒有編隊有兵時，留在集結點（D-054）。
  - 目標調低時，後加入的先離開編隊。
  - 新兵加入編隊的訊息，遊戲時間一分鐘最多一則（自動訓練每棟 12–35 秒就出一名）；編隊按鈕的數字照常更新。
  - 編隊按鈕存了兵之後寫兩行：編號，下面小一號的「現有/目標」。
- 選了兵時，指令區第一列是「進攻、撤退、堅守、停止」；選取資訊寫「目前：進攻中 3、堅守 2、待命 1」和三顆各一句說明；全部同一種時那顆亮。
  - 進攻中＝有前進、攻擊、晶砲的指令；撤退中＝有撤退指令；待命＝站著沒有指令、不是堅守。
  - 進攻：提示列請玩家點地面或小地圖，之後前進（點到敵人就攻擊）。玩家的前進和攻擊都算進攻：堅守的兵改回積極。
  - 撤退（D-059，取代 D-032 的「按撤退直接退回主城」）：和進攻一樣先選位置，點地面或小地圖就撤到那裡；點自己的主城，或提示列的「退回主城」，回到主城前面那一格。長按輪盤的撤退也一樣。左上的「全軍撤退」照舊一按就全部退回主城。
  - 撤退中點地面（D-061）：選的兵全都在撤退中時（按鈕是「取消撤退」），點地面或長按小地圖＝改撤到那裡，不是進攻；訊息列寫「改撤到這裡，撤到後原地堅守」，選取資訊的撤退那行換成「撤退中：點地面或小地圖改撤退位置，到了原地堅守」。只有一部分在撤退時照舊是進攻，和按鈕一樣。
  - 撤到就堅守（D-061）：每次親手撤退（指令區、輪盤、全軍撤退、退回主城、改撤退位置）都一起送堅守。模擬裡撤退中的兵本來就不打；到了以後是堅守，只打射程內的、不追。按「進攻」或點地面前進，才變回積極（D-050）。不用改模擬：`test/retreat-hold.test.ts` 直接跑模擬驗證。
  - 取消即堅守（D-054）：進攻中、撤退中，或在選位置時，那顆寫「取消進攻」「取消撤退」，按了就停下、改成堅守；提示列的「取消」和輪盤的同一顆也一樣。
  - 長按輪盤：槍兵、遠程兵是進攻、撤退、堅守；法師是晶砲、自動施放、撤退、堅守；村民只有撤退。
- 選取資訊的標題列有「收起」：收起後只剩標題列，記在這一局，換選取時照舊收著（D-054）。
- 資源列的人口含訓練中的兵（自己建築的佇列加總），後面寫「（訓練中 N）」；放不下時先拿掉「時間」，再拿掉括號。
- 自動訓練（D-054，規則在模擬：玩家的兵營、射場、法術營開局就開著）：
  - 這三種建築的指令區有「自動訓練　目前：開／暫停」，按一下切換這一棟（送 `auto_train`）；選取資訊寫「自動訓練中」「自動訓練暫停」或「人口滿了，蓋民居」。
  - 主城的指令區有「預留」：自動訓練只用超過預留額的資源。對話框裡糧、木、金每次 ±10，晶 ±5；「預設」回到 `AUTO_TRAIN.reserve`（木 150、金 100、晶 15）；按「套用」才送出（`reserve`）。
  - 人口滿了讓自動訓練停下來時（建築旗標 AutoPopulationFull），訊息列提示一次「人口滿了，自動訓練停下來：蓋民居」；有空位之後再滿才會再提示。
- 「分出 N 名」「改選其餘」拿掉了（D-054）。

## 派村民（D-061）

- 什麼都沒選時點樹、金礦、野果或晶脈，選取資訊寫它剩多少，下面一排「¼／½／全部（N 名）」：把正在別處採同一種資源的村民派過來，離這個點近的先派，人數四捨五入、至少 1 名（`src/game/dispatch.ts`）。
- 別處沒人在採這種資源時（晶脈只能手動派，一開始一定是這樣），改派閒置的村民。
- 送的是玩家自己的 `gather`，算親手派的，經濟分配改比例時不會動他們（D-050）。
- 農田不在裡面：一塊農田只給 1 名村民種，經濟分配本來就會派人去（ceo 2026-10-07）。
- 介面上一律叫「村民」（原本叫農民）；程式裡的名稱（`Farmer`）沒改。

## 第七輪（D-061）：城鎮只能搶一次、箭樓、躲進建築、馬廄和騎兵

每一項都看 `rules.features`（沒送就當全關，`src/game/features.ts`）。開關關著時畫面和第六輪一樣：沒有箭樓、沒有「躲進去」、不寫收入、攻下城鎮照樣有搶。

- 城鎮只能搶一次（`plunderOnce`）：搶過的城鎮（旗標 `Plundered`）再攻下時，對話框標題是「攻下小鎮！只能治理」，只有治理和治理的留守，下面寫「這座城這局已經被搶過，只能治理」；點城鎮時選取資訊也一樣。開局提示多一句「每座城一局只能搶一次」。
- 治理收入：自己治理的城鎮，選取資訊寫「收入 N%，慢慢回升」（滿了寫「收入 100%」）；修繕中寫「修好後收入 N%，慢慢回升」（`incomePermille`）。
- 箭樓（`towers`）：建造選單多一項箭樓。只能蓋在主城或治理的城鎮附近（`PlaceBit.TowerLand`），提示列寫「拖曳箭樓到主城或治理的城鎮附近」，外面預覽變紅並多一行「箭樓要蓋在主城或治理的城鎮附近」（`src/ui/placement.ts` 的 `towerLandOk`）。畫成有城垛的窄塔。
- 躲進建築（`garrison`）：
  - 選到遠程兵或法師時，指令區有「躲進去」；按了點自己蓋好的主城或箭樓，送 `garrison`，只送遠程兵和法師（混選時提示列先說）。點錯地方說「要點自己蓋好的主城或箭樓」（`src/game/garrison.ts`）。
  - 自己的主城、箭樓的選取資訊寫「躲了 N 名士兵（最多 M 名）」，旁邊「全部出來」送 `leave`。
  - 躲著的兵（走去躲的和已經躲好的，`order` 是 `Garrison`）在編隊裡照算，點編隊會選到，自動補兵也不會因為他們躲起來再拉兵補進編隊；但對編隊下的進攻、撤退、移動只送給沒躲的兵，躲著的留在裡面。只選了躲著的兵時，訊息列寫「躲著的兵要從建築的「全部出來」叫出來」。選取資訊的「目前：」寫「躲在建築裡 N」；進攻、撤退、堅守哪顆亮不看躲著的兵。全軍、全軍撤退、留守、自動補兵都不含他們（ceo 2026-10-07）。
  - 建築裡有人（旗標 `Occupied`，自己的和看得到的敵方建築）：右上角一個小盾牌；敵方的選取資訊寫「裡面有人」。
  - 事件 `shot`：從建築中心畫一支飛向目標的箭（0.3 秒）。
- 馬廄和騎兵（`cavalry`）：
  - 建造選單多一項馬廄（字「馬」）。`requires` 裡的建築還沒有自己蓋好的時候，按鈕變灰，寫「要先蓋兵營」這類說明（`src/game/features.ts` 的 `missingFor`）。
  - 馬廄訓練騎兵，自動訓練的開關和兵營一樣。
  - 騎兵畫成前後兩個有缺口的箭頭（»），和槍兵的楔形加槍看得出是兩種兵。
  - 騎兵是士兵：全軍、編隊、留守、自動補兵、人口、長按輪盤（進攻、撤退、堅守）都算到。軍團畫面在開關開著時多一列騎兵（第四列）。
- 兵種相剋（選單，ceo 2026-10-07）：每種兵一行，寫「剋：槍兵 ×2.5」「怕：槍兵 ×3」。
  - 倍數從這一局的 `rules.multipliers` 算（`src/game/counters.ts`）。
  - 不是倍數的剋制照 GDD 第 6 節寫上：槍兵怕晶砲（擠在一起時），遠程兵怕騎兵（跑得快），法師剋擠在一起的部隊（晶砲範圍傷害），騎兵剋遠程兵（跑得快）。
  - 騎兵關著時，騎兵和跟騎兵有關的倍數、說明都不列。開關關著時也看得到，只有三種兵。
- 用真的模擬驗過（core 第七輪 T、D、K，開關全開；ceo 2026-10-07 定為上線條件）：
  - `test/round7-sim.test.ts`：模擬照 Worker 的方式產生快照、餵給畫面的 GameView，指令用畫面自己組的。驗了：搶過的城鎮再選搶被拒、畫面只給治理；箭樓只能蓋在 TowerLand，畫面的判斷和模擬一致；躲進去、全部出來的結果和畫面讀到的人數、記號；馬廄訓練出騎兵，兵種相剋讀到遠程打騎兵 ×1.8。

## 點存放建築派村民（D-066）

- 點自己蓋好的伐木場、礦場、糧倉：選取資訊寫「附近有 N 名村民在採木」，旁邊一顆＋。主城收糧、木、金三種，三格並排寫「糧 N 名」，各有＋（主城有訓練佇列時，一種一列會蓋到左上的全軍撤退）。程式在 `src/game/depot.ts`。
- 人數：村民正在採的資源點或田，離哪一棟收這種資源的自己建築最近，就算在那一棟，也就是他會把東西送回的那一棟。所以每名村民只算一次，各棟加起來就是全部在採的人。
- ＋，一次一名：
  - 先派閒置的，離這棟近的先；沒有閒置的，就派採別種資源、離這棟最近的。採晶脈、正在蓋或修建築的不派。
  - 伐木場、礦場、主城的木和金：用 `gather` 派去離這棟最近的樹、金礦（占地 10 格內），算親手派的（`HandPicked`），經濟分配不會把他移走（D-050）。
  - 糧：先去 10 格內沒人種的田（`repair`），沒有就去野果，都沒有就提示「附近沒有空田，先蓋農田」。
- 還沒做（等 core 的協定，ceo 2026-10-07）：－（讓村民變閒置、交給經濟分配的新指令）；派去田也算親手派的。
- 現在的點資源派村民（D-061）照舊。

## 對局紀錄（D-056）

- 每局結束（勝、負、投降、時間到），以及按「重來」時已經打了一分鐘以上的局，把模擬的指令紀錄（`export_log`）、這局最後一個狀態雜湊、版本、難度、勝負、遊戲時間存在手機上（IndexedDB，最多 50 局），接著上傳到 `services/game-logs/` 的 Worker。量測和假世界不存。
- 上傳不擋畫面、失敗不顯示；沒傳成功的在下次打開遊戲、或下一局結束時再傳。`text/plain`，跨網域不用預檢；64 KB 以下加 `keepalive`，頁面關掉也會送完。
- 收紀錄的網址是 `src/logs/collect.ts` 的 `GAME_LOGS_URL`（使用者 2026-10-07 部署的 Worker 的 `/logs`）。測試頁（`?test=1`）不上傳，除非給了 `?logs=`，所以 CI 不會打到真的 Worker。部署步驟在 `services/game-logs/README.md`。
- 開局畫面的版本號旁邊寫「紀錄代號 xxxxxxxx」：手機第一次打開時隨機產生、存在手機上的 8 個字，不是帳號、認不出是誰，用來分開不同手機的紀錄。瀏覽器儲存不能用時只在這一頁有效。
- 紀錄裡沒有帳號、裝置名稱或任何認得出人的東西（欄位見 `services/game-logs/README.md`）。

## 加到主畫面（D-042）

- iPhone 的 Safari 用「加入主畫面」、或筆電的 Chrome 安裝之後，從圖示打開沒有網址列。名稱 `war-game` 和晶體圖示是暫時的（GDD 第 16 節）。
- 不用 service worker，什麼都不快取：常常部署，快取會讓人一直開到舊版。
- 建置時多一個 `version.json`（只有 commit）。頁面打開、從背景回來時繞過快取讀它，和自己的 commit 不同就在開局畫面顯示「有新版本」和「更新」。「更新」換到加上 `v=<新的 commit>` 的網址（其他參數保留），新網址不會拿到快取裡的舊 `index.html`；對局中只提示一次，不重新載入（`src/version.ts`）。

## e2e 怎麼模擬觸控

Playwright 沒有兩個瀏覽器都能用的多指、長按拖曳 API。`e2e/touch.ts` 在頁面裡用頁面自己的計時器送出手指會產生的
PointerEvent（`pointerType: "touch"`），進的是同一個手勢狀態機；單點另外用 `page.touchscreen.tap` 走瀏覽器真正的觸控路徑。
Chromium 在 CI 上用裝置倍率 1（沒有 GPU，倍率 3 會拖慢到手勢計時失準），WebKit 維持 iPhone 的 3。

## 檔案

- `index.html`、`src/`：原型頁。
- `site/`：Pages 首頁與第三方授權頁（整個網站的，不只原型）。
- `e2e/`、`playwright.config.ts`：Playwright 測試。
- `docs/`：client 的規格文件，例如兵種精靈圖集規格 `docs/sprite-atlas.md`。只改這裡不會觸發 CI 和 Pages 部署。
- `scripts/live-check.ts`：部署後檢查公開的網站（含 `version.json` 和 manifest）。
- `public/`：原樣複製到建置結果：`manifest.webmanifest` 和 `icons/`（加到主畫面用，D-042）。
- `scripts/icons.py`：畫暫時的主畫面圖示（`public/icons/` 的 SVG 和 180、192、512 的 PNG；要 Pillow，產出的檔案有進 repo，CI 不跑它）。
- `scripts/expected-hashes.sh`：產生確定性檢查的對照檔。
- `test/`：單元測試。
